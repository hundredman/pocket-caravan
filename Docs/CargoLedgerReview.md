# 화물 판매처·장부 이용 검토

검토/반영: 2026-10-21. [수량 거래 패치](MarketPlanningPatch.md) 다음 단계다. 첫 교역 후 플레이어가 자신의 화물을 어디에 팔지 판단하는 흐름과 안내의 실제 동작을 검토했다. 이번에도 거점 추가나 이동 시간을 늘리기보다 기존 거래 정보와 경유 관계를 읽기 쉽게 만든다.

## 확인한 문제와 반영

| 확인한 문제 | 반영 |
|---|---|
| 장터 상세가 L 전체 비교를 안내하지만 장터의 입력 차단 때문에 장부를 열 수 없음 | L로 장터를 닫고 장부로 전환. 같은 L 입력에 장부가 즉시 닫히거나 다시 열리지 않게 처리 |
| 전체 상품/도시 표에서 현재 짐과 평균 원가를 함께 비교하기 어려움 | 장부 기본 탭에 ‘내 짐 판매처’ 추가. 실제 소지 일반 교역품의 수량·평균 원가, 직접 기록한 판매가와 원가 대비 단위 차이 표시. 전체 시세 표도 별도 탭으로 유지 |
| 가격만 비교하면 가까운 거점과 먼 거점의 차이를 알기 어려움 | 등록된 맵 연결로 구간 수와 다음 경유 맵 표시. 같은 구역/연결 미확인을 구분 |
| 초기 고려에 도적을 제거했는데 지도가 모든 곳에 밤길 도적을 경고함 | 지역 전체에 통용되는 귀환 화물·거래처 계획 안내로 교체. 중간권 도적/통행료/전투 규칙은 그대로 |
| 개발용 흔들림 설명에 주행 낙하가 남아 있음 | 실제 감속 연출 용도와 맞게 정리. 동작 변경 없음 |
| 시설 화면 Q/L 안내가 즉시 전환되는 것처럼 보임 | 해당 창을 닫은 뒤 사용할 키라고 명시. 시설의 이용/보관/접근 규칙은 유지 |

## 정보와 권한의 경계

- 판매처 목록은 플레이어 장부의 과거 첫1개 가격이다. 원격 시장의 현재 재고/가격을 조회하지 않는다. 값 높은 순이며 동일 가격은 연결 구간 수·안정 ID 순으로 정렬한다. 모르는 시세를 채우거나 정답 경로를 선정하지 않는다.
- 연결 구간 수는 등록 그래프의 최단 간선 수다. 실제 보행 거리·노면·적재량·달리기·위험·로딩·시간당 이익과 다르다. 전체 수량의 매각 이익이나 도착 시 가격도 보장하지 않는다.
- 지금 소지한 교역 화물만 목록으로 보여 준다. 의뢰 짐과 창고 물건은 별도이며 빈 화물 안내에서 구분한다. 원가0 물품도 원가0으로 비교한다.
- 다른 지역 콘텐츠·가격·보수·이동 속도·신용 문턱·기존 저장 형식은 변경하지 않는다. 저장 장부는 예전 형식 그대로다. 공용 화면이라 통합된 지역에 적용되지만 북유럽/베네치아의 미통합 자산을 수정하지 않았다.
- 온라인 권한/시장 동시성·서버 경로/거리 검증을 완료한 패치가 아니다.

## 확인 범위

[검증 기록](Validation/CargoLedger-2026-10-21.json)에 상세 항목·소스·빌드/패키지 근거를 남긴다. 데이터13개와 실제 입력 경로 Play6개, 기존 수량 거래 Play16개 통과. 입력 시험은 임시 가상 키보드로 실제 InputReader/Update를 호출한 것이며 장치를 제거하고 기존 장치를 복원했다. 비시작 씬/저장 비활성 상태에서 검사하고 장부·시장 스냅샷을 복원했다.

1920×1080 화물 비교, 1024×768 화물/전체 시세를 캡처해 가독성과 잘림을 확인했다. 화면은 검사 화물/관측 기록을 넣은 테스트 상태다. 실제 사람의 길 찾기/자발적 선택·Windows 실행·플레이타임 실측은 아니다. 임시 GameView 크기를 제거하고 원래 선택값과 정지 Route01로 복원했다.

## 다음에 검토할 항목

1. 정보가 있어도 반복 루트가 고정되는지: 첫 왕복과 세 번째 왕복에서 품목·귀환품·경유 선택 이유를 사람 플레이로 확인한다. 최저 보행 시간과 가장 높은 관측가를 최적 루트로 단정하지 않는다.
2. 창고는 신용3 해금 후 분할 운송에 실제 가치가 있는지: 현지 보관/회수·원가 보존의 코드와 위치/신용 검사 경계를 읽었으며 이번에 수치나 기능을 바꾸지 않았다. 사용 가치는 사람 플레이 대기다.
3. 지역 맵의 대표 장면과 노면 선택 가독성, 좁은 창에서 긴 품목/마을 이름, 동시 개발 지역을 합친 뒤의 정보량을 검토한다. 현재 두 화면 비율 통과를 모든 창 크기 검증으로 확대하지 않는다.
4. EC-02 공유 거래·퀘스트 지역/장 필터·최신 출신 강점 구현은 별도 공통 과제로 유지한다. 이번 편의 UI가 멀티 검증을 대신하지 않는다.

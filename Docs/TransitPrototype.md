# 문명 사이 중간 여정 프로토타입

2026-10-17. 고려 외 마을/길의 **이동·경유·교역 비교용** 구현이다. 팀원이 개발 중인 베네치아·아라비아·북유럽 지역은 편집하지 않는다. 지명은 창작이며 실제 고려 국경, 실측 거리, 특정 시대의 도로망을 재현하지 않는다.

## 연결과 역할

장단 들마을 동쪽 → **솔바람 고개 → 솔재 길목 마을 → 버들 물가 길 → 버들나루 마을**. 장단에서 종점까지 맵 전환4번을 거친다. 고개 동단에서 북쪽으로 굽고, 솔재·물가 길·버들나루를 남북 방향으로 잇는다. 물가 길 안에서는 기존 두 다리의 선택을 유지한다. 모든 연결은 왕복 가능하며 다른 문명으로 바로 넘어가지 않는다. 현재 고려는 새 길3곳 포함9맵으로 늘었지만 수도1+마을4 기준은 그대로이며, 중간 마을2곳을 고려 마을 수에 더하지 않는다.

| 구역 | 환경/선택 | 경유 이유 |
|---|---|---|
| 솔바람 고개 | 산림·구릉 / 곧은 오솔길과 남쪽 큰길 | 등짐은 짧은 길, 수레는 좋은 노면 비교 |
| 솔재 길목 마을 | 숲 장터 / 쉼터·길 안내·손수레 판매 | 송진 공급, 귀환 생선 판매, 땔감 등 생활재 |
| 버들 물가 길 | 하천·연못 / 좁은 샛다리와 북쪽 큰다리 | 짧은 길과 적재 수레 우회 비교 |
| 버들나루 마을 | 강변 장터·선착장 / 이번 시험 종점 | 말린 생선 공급, 송진 판매, 쉼터·길 안내 |

화물 낙하 없음. 노면/적재 감속과 시각 흔들림을 유지한다. 선착장은 도보 관찰용이며 승선 기능이 없다. 날씨, 도적의 새 조건, 통행료, 보급품 소모, 다리 붕괴는 이 묶음에 추가하지 않았다. 물가라는 이름만으로 별도 습지 물리/기상 시스템이 구현됐다고 보지 않는다.

## 비교값과 남은 조정

- 도로 등급1(오솔길)과3(큰길), 기존 이동 수단의 실제 배율 사용. 새 전역 속도 값은 바꾸지 않았다.
- 직교 노면 최단 경로 계산: 고개에서 등짐은 샛길 비용38.918/큰길46.364, 수레는47.206/42.500. 물가에서 등짐38.918/44.545, 수레47.206/40.833. 이는 기본 이동속도 적용 전 비용이며, 자유로운 잔디 이동/대각선/가속/달리기/NPC를 포함한 플레이 시간 실측은 아니다.
- 두 상품 무게2, 송진 공급가8·생선9, 맵당 가격 할증0.35. 공급 적정재고64, 반대 마을48. 아이콘은 기존 생활재 그림을 임시 재사용한다.
- 출신 능력/시장일/시간 회복을 제외한 실제 MarketState 초기값: 송진5개 원가41→판매54(이익13), 생선5개46→57(11). 각각10개는86→102(16),96→112(16). 반복 판매에 따른 한계 이익 감소를 유지한다. 등짐 한도10에는5개, 손수레30에는15개를 실을 수 있다. 수레 구입비150의 회수 기간과 장시간 플레이 밸런스는 미확정이다.
- 시장은 현재 로컬 상태다. 온라인 공유 시세, 동시 매매/길목 혼잡/수용 인원 검증을 완료한 것은 아니다.

## 변경 방법과 협업

- `Tools/MapGen/frontier.py`: 네 구역 배치·길·표지판. 임의 시드 고정.
- `World/Regions/transit.json`: 지역 등록/연결용 맵 ID·파일 경로. `transit_` 이름공간 사용.
- `Data/Transit/`: 별도 RegionData·TownData·ItemData. `TransitRegionUpgrade.ApplyData()`는 이 데이터와 공용 DB 참조만 갱신한다. 다른 지역 데이터는 초기화하지 않는다. 기본 데이터 전체 재생성은 팀 작업 중 사용하지 않는다.
- 논리 좌표는 임시 `(5,0)`~`(8,0)`. 기존 고려 담당 작업 대역0~9 안에서만 사용해 다른 팀의10~39 대역을 점유하지 않았다. 게임 소속은 별도 가상 중간권이다. 최종 세계 좌표/경제 거리 모델 합의 때 재배치하되 저장 ID는 유지한다. 현재 가격은 Manhattan 좌표 거리이므로 좌표만 크게 옮기면 시세가 변한다.
- `World/settings.json`의 `atlasRegions`로 지도에 포함할 생성 구역을 선택한다. 타 팀 생성기를 임의로 전부 실행하지 않는다. 연결된 맵은 한 지도에 함께 포함해야 한다.
- 내보내기: 번들 Python으로 `Tools/MapGen/export.py .`. 장단 연결과 중간권 JSON/지형 지도를 갱신한다.
- Unity에서 데이터 갱신 후 `MapJsonBuilder.BuildSelected("goryeo_jangdan", "transit_pass", "transit_woodtown", "transit_wetroad", "transit_ferry")`. 수정 중인 씬이 있으면 중단하며, 선택하지 않은 팀원 씬은 재생성하지 않는다. 공통 색인/빌드 목록은 등록부에서 갱신한다.
- 검사: `validate_world.py`, 통합 unittest, `MapGen/validate.py`, `validate_route_choice.py`, `validate_transit.py`, Unity `TransitRegionChecks.Run()`.

## 확인 순서

1. 본편에서 닥목→장단→동쪽 출구로 이동한다. 빠른 지역 확인은 `Scenes/Transit/transit_woodtown.unity`를 열어 Play한다(비시작 씬이라 자동 저장 비활성).
2. 솔재에서 송진을 싣고 물가 길의 두 다리를 비교한다. 등짐/손수레, 가벼운 짐/무거운 짐을 바꿔 본다.
3. 버들나루에서 판매하고 말린 생선을 사서 솔재로 돌아온다. 매입원가와 전량 손익을 확인한다.
4. 마을 시설의 쉼터/길 안내를 이용한다. 고개를 지나 장단으로 돌아갈 수 있는지 확인한다.

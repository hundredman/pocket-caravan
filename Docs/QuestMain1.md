# 메인 퀘스트 ① 시작 지역 탐방 — 고려 (Q1 설계)

2026-10-24, Claude 설계 → Codex 구현. 원칙은 [방향 기준](Direction.md) 5절, 작업 정의는 [작업 계획](Plan.md) Q1, 저장 위험은 [퀘스트 저장 호환 검증](Validation/QuestSaveCompatibility-2026-10-24.md).

## 1. 목표

- 시작 마을 나루에서 출발해 **나루 → 장단 → 송악 → 닥목 → 개경** 순서로 돌고, 마지막에 수도 개경에 자연스럽게 들어간다.
- 마을마다 **한 가지씩** 익힌다: 짐 나르기 → 시세 거래 → 의뢰 게시판 → 특산품 → 수도와 장거리 교역.
- 메인 퀘스트는 튜토리얼이다. 의뢰 게시판·장터·교역은 처음부터 자유이고, 메인 퀘스트로 막지 않는다.
- 시작 돈 100냥으로 모든 단계를 할 수 있다.

## 2. 핵심 결정: 새 ID로 만들고, 옛 퀘스트는 은퇴시킨다

옛 튜토리얼(`tutorial_1`, `tutorial_2` 등)의 목표를 고쳐 쓰면, 저장된 단계 번호가 다른 목표를 가리키는 문제가 생긴다(호환 검증 문서의 재현 사례). 그래서 **새 메인 퀘스트는 새 ID로 만들고, 옛 퀘스트의 목표는 한 글자도 바꾸지 않는다.**

- 옛 퀘스트는 `retired`(은퇴)로 표시해 **새로 제안하지 않는다.** 옛 저장에서 이미 진행 중이면 옛 정의 그대로 끝까지 할 수 있다(마을·NPC ID는 그대로이므로).
- 옛 저장에서 이미 끝낸 옛 퀘스트는 대응표(5절)로 새 단계를 **보상 없이** 완료 처리한다. 튜토리얼을 다시 하게 만들지 않는다.
- 이렇게 하면 단계 번호를 옮기는 이주가 필요 없다. 이주는 "완료 기록 추가"뿐이다.

## 3. 새 메인 퀘스트 (체인 이름: `고려 한 바퀴`)

대사는 짧게 쓰고 페이지로 나뉜다(방향 기준 7절). **방위(동쪽·서쪽) 표현은 쓰지 않는다.** 맵 배치(B3)가 바뀌어도 대사를 고치지 않기 위해서다. 길 안내는 "길 안내소"와 지도(M)에 맡긴다.

### ① `q1_naru` — 첫 짐 (나루)

| 항목 | 값 |
|---|---|
| 주는 사람 | `naru_chief` (나루 촌장) |
| 선행 | 없음 (게임 시작 시 바로 제안) |
| 받는 짐 | `salt_parcel` ×1 |
| 목표 | 1. Deliver `goryeo_jangdan_farmer`에게 `salt_parcel` ×1 — "장단 농부에게 소금 꾸러미 전하기" |
| 보상 | 30냥, 신용 +1 (맡은 짐을 전한 약속 이행) |
| 익히는 것 | 퀘스트 짐 받기, 다른 마을로 걸어가기, NPC에게 건네기 |

- 제안: "자네가 행상이 되겠다는 젊은이로군. 배로 들어온 소금 꾸러미를 장단 농부에게 전해 주게. 들판 마을이라 소금이 늘 모자라지."
- 완료(농부): "나루 소금이로군, 고맙네! 장단은 곡식이 남아도는 곳이라 여기선 곡식이 싸다네."
- 마무리: "장터 옆 게시판에는 언제든 배달 의뢰가 붙어 있습니다. 메인 이야기와 상관없이 자유롭게 맡아 보세요."

- 제안: "이 한지 꾸러미를 개경 객주에게 전해 주게. 가는 김에 아까 산 종이도 수도 장터에 팔아 보고. 수도는 고려의 물건이 다 모이는 곳이라네."
- 완료(객주): "닥목 한지로군, 빛깔이 좋아. 개경은 처음인가? 시전에서는 손수레를 팔고, 객주에서는 짐을 맡아 두기도 한다네."
- 마무리: "고려 한 바퀴를 마쳤습니다. 이제부터는 자유입니다. 게시판 의뢰, 마을 사이 교역, 송악 너머 중앙 대륙 — 어디로 가도 됩니다."

### 진행 중 규칙

- **개경에 먼저 가도 된다.** 직행길로 개경에 먼저 들어가도 아무것도 막히지 않는다. ⑤의 VisitMap은 ⑤를 받은 뒤 개경에 있으면 바로 완료된다(현재 `CheckPassive` 동작).
- ②의 Buy, ④의 Buy는 **퀘스트를 받은 뒤의 구매만** 센다(현재 동작 유지). 미리 사 둔 물건은 Deliver/Sell 목표에는 쓸 수 있다.
- 메인 퀘스트를 받지 않아도 게시판·장터·교역·사이드 퀘스트(아래 4절)를 쓸 수 있다.

## 4. 옛 퀘스트 처리

| 옛 퀘스트 | 처리 | 새 선행(requires) | 이유 |

| `tutorial_2` 종이 사 오기 | **은퇴** | — | ④·⑤로 대체 |
| `naru_board` 의뢰 게시판 | **은퇴** | — | ③으로 대체 |
| `dakmok_hanji` 개경으로 가는 한지 | **은퇴** | — | ⑤로 대체 |

| `tutorial_5` 손수레 | 사이드 유지 | `q1_dakmok` | 수레 입문. 손수레는 개경 시전에서 산다 |

| `dakmok_firewood`, `goryeo_cart_supply` | 그대로 | 그대로 (`tutorial_5` / `goryeo_jangdan_trade`) | 선택 그룹 유지 |
| `goryeo_return_trade` | 그대로 | 그대로 | |

- **사이드 퀘스트는 목표·보상을 바꾸지 않는다.** `requires`만 바꾼다. `requires`는 제안 조건에만 쓰이므로, 이미 진행 중인 저장에는 영향이 없다.
- 사이드 퀘스트 보상의 신용을 평판으로 옮기는 것은 R6에서 한다. 이 작업에서는 바꾸지 않는다.

## 5. 옛 저장 → 새 단계 대응표

불러오기 때 한 번 적용한다. 새 단계는 **보상 없이 완료 기록만** 추가한다. 앞 단계부터 순서대로 보고, 조건이 안 맞는 첫 단계에서 멈춘다(그 단계가 다음 제안이 된다).

| 새 단계 | 이 옛 퀘스트 중 하나라도 완료했으면 완료 처리 |
|---|---|
| ① `q1_naru` | `tutorial_1` |
| ② `q1_jangdan` | `goryeo_jangdan_trade`, `tutorial_3` |
| ③ `q1_songak` | `naru_board` |
| ④ `q1_dakmok` | `tutorial_2`, `goryeo_return_trade` |
| ⑤ `q1_gaegyeong` | `tutorial_2`와 `dakmok_hanji` 둘 다, 또는 `tutorial_5` |

- **예외:** 옛 튜토리얼 체인을 끝까지 한 저장(`tutorial_2`와 `tutorial_5` 완료)은 ①~⑤ 전부 완료 처리한다. 순서 중간이 비어 있어도 다시 시키지 않는다.
- 진행 중인 옛 퀘스트(은퇴 포함)는 손대지 않는다. 옛 정의대로 끝낼 수 있다. 끝나면 위 대응표를 다시 적용한다(새로 조건이 맞게 된 단계만 추가).
- 대응표 적용은 여러 번 해도 결과가 같아야 한다. 보상은 절대 다시 주지 않는다.

## 6. 구현 (Codex)

1. `QuestData`에 `bool retired` 추가. 기본값 false라 기존 에셋은 그대로.
2. `QuestManager`: `retired` 퀘스트는 새로 제안하지 않는다. 진행 중·완료 기록은 그대로 다룬다.
3. 새 에셋 5개(`Data/Goryeo/Quests/Q1_*.asset`)를 3절대로 만들고 `GameDatabase.quests`에 등록. 체인 이름 `고려 한 바퀴`.
4. 옛 퀘스트 4개에 `retired = true`, 사이드 퀘스트 5개의 `requires`를 4절대로 바꾼다. 목표·보상·ID는 그대로.
5. 불러오기 이주: 5절 대응표를 데이터(코드 상수 또는 작은 표 에셋)로 두고 `QuestManager.Import` 뒤에 한 번 적용. 진행 중 옛 퀘스트가 끝날 때도 다시 적용.
6. ② 판매처 이익 확인(3절 ② 확인 항목). 결과를 작업 기록에 적는다.
7. `CurrentState.md`에 새 메인 퀘스트와 은퇴 퀘스트를 적는다.

**고치는 파일:** `Scripts/Quests/QuestData.cs`, `Scripts/Quests/QuestManager.cs`, `Data/Goryeo/Quests/*.asset`, `GameDatabase` 에셋, `Tools/Integration/QuestSaveProbe`(테스트), `Docs/CurrentState.md`.

## 7. 완료 확인 (검사)

`Tools/Integration/QuestSaveProbe`에 아래 시나리오를 넣고 통과시킨다. 실행 명령과 결과를 작업 기록에 남긴다.

1. 새 게임: ①~⑤가 순서대로 제안되고 끝까지 진행된다. 시작 돈 100냥으로 막히지 않는다.
2. 새 게임에서 은퇴 퀘스트 4개는 한 번도 제안되지 않는다.
3. 메인 퀘스트를 받지 않은 상태에서 게시판 의뢰 수락·완료, 장터 사고팔기가 된다.
4. ⑤를 받기 전에 개경에 먼저 가도 오류·막힘이 없고, ⑤를 받은 뒤 개경에 있으면 VisitMap이 완료된다.
5. 옛 저장(옛 튜토리얼 전부 완료): 불러오면 ①~⑤가 완료로 표시되고 돈·신용이 늘지 않는다.
6. 옛 저장(`tutorial_1`만 완료, `tutorial_2` 진행 중): ①만 완료, `tutorial_2`는 옛 정의대로 끝낼 수 있고, 끝나면 ④가 완료 처리된다(②·③이 비어 있으면 ④는 표시만 하고 다음 제안은 ②).
7. 대응표를 두 번 적용해도 결과가 같고, 저장·불러오기를 반복해도 보상이 중복되지 않는다.
8. 사이드 퀘스트는 새 선행 단계를 마친 뒤에만 제안된다.

> 6번 처리 방침: 순서가 비면 "멈춘다"가 원칙이지만, 옛 퀘스트를 끝내서 생긴 뒤 단계 완료 기록은 지우지 않는다. 다음 제안은 비어 있는 가장 앞 단계다. 이미 완료된 뒤 단계는 다시 제안하지 않는다.

## 8. 이 설계가 정하지 않은 것

- 평판 보상(R6·R2 이후 단계별로 고려 평판 소량 추가)
- 메인 퀘스트 ②~⑤ 큰 흐름(중앙 대륙 이후, D8)
- 맵 재구성(B3) 뒤 이동 거리에 맞춘 보상 재조정(B6)

# Claude 판단 기록 (2026-10-25)

Codex 검토 요청 세 건(B1, A3a→A3b, R2→D10)에 대한 답. 은샘의 최신 결정(환경 아트는 지금 그림 유지, 큰 호수는 기존 유지)을 따른다.

## 1. B1 — 맵별 면적의 기준

- **기준은 저장소의 원본 계산 결과다**(`Tools/WorldLayout/layout_proposal_d_coast_v2.py`, seed 7). 은샘이 승인한 것은 그 결과의 모양(Figma v2 프레임)이다.
- [세계 배치](WorldLayout.md)의 맵별 숫자 5개는 Claude가 원본을 저장소에 옮기기 전, 작업 폴더에서 돌린 계산에서 적은 값이라 몇 칸 차이가 났다. 경계와 모양은 그대로 두고 **문서 숫자를 원본 계산 결과로 고친다**: 개경 5,001 · 나루 3,997 · 장단 4,298 · 북동 길 3,050 · 남동 길 3,051. 합계(20,000 / 25,000)와 육지 칸 수는 같다.
- Codex는 이 숫자로 B1 이관과 테스트를 이어 간다.

## 2. A3b — 지금 에셋을 어떻게 할지

은샘 결정: 지금 환경 그림이 좋다. 바꿀 것은 사용자가 짚은 것만.

| 항목 | 판정 |
|---|---|
| 건물·나무·소품 그림 (궁궐·초가·기와·버드나무·숲 등) | **유지.** 그림을 바꾸지 않는다 |
| 시트에서 잘라 쓰기(`goryeo_art.sprite`, `STAMPS`), 즉석 색 바꾸기(`recolor`, `tone`) | **지금 모습 그대로 '굽기'.** 생성 중에 자르거나 색을 바꾸는 대신, 지금 화면에 나오는 결과를 온전한 개체 PNG로 한 번 만들어 A2 목록에 등록하고 그것을 쓴다. 화면 변화 0이 완료 기준 |
| 언덕 조각을 밭으로 쓰기(`FIELD`) | 화면은 유지. 위와 같이 밭 전용 에셋으로 굽고 등록 |
| 작은 연못 | A4 새 조립 세트로 교체. **은샘 승인 완료(2026-10-25: “작은 연못 좋은 것 같아. 승인할게.”)**, 범위는 작은 연못 경계이며 큰 호수/새 물결 애니메이션 제외 |
| 큰 호수 | 지금 그대로 유지(은샘 결정) |
| 나무·건물 겹침 | C3a에서 정상 이동으로 확인 후 필요한 곳만 수정 |

**C6 다시 정의:** 옛 출처 그림을 없애는 작업이 아니다. ① 위 '굽기'로 생성 중 자르기·색 바꾸기 코드를 쓰지 않게 하고 ② 게임에서 쓰지 않는 옛 맵·옛 생성 코드의 동물 NPC 참조 등 남은 찌꺼기를 정리한다. 지금 그림(Ninja 팩 타일 포함)은 유지한다.

## 3. D10 — 평판 가격·흥정 수치 (Claude 임시안, 구현 후 은샘 플레이로 조정)

Codex 계산(R2)에서 어떤 후보든 보정이 겹치면 같은 장터에서 사서 바로 되파는 이익이 생겼다. 그래서 수치보다 먼저 **안전 규칙 하나**를 둔다.

**안전 규칙:** 모든 보정(평판, 흥정, 출신, 장날)을 적용한 뒤, 한 마을에서 어떤 물건을 사는 값은 같은 마을에서 그 물건을 파는 값보다 항상 1냥 이상 높다. 이 규칙이 있으면 같은 장터 되팔기 이익은 0이 되고, 수치는 체감 위주로 정할 수 있다.

| 단계 | 사는 값 보정 | 파는 값 보정 | 흥정 최대 폭(사고팔 때) |
|---|---:|---:|---:|
| 적대 | +15% | 0% | 흥정 불가 |
| 경계 | +7% | 0% | 흥정 불가 |
| 중립 | 0% | 0% | 3% |
| 우호 | −3% | 0% | 5% |
| 신뢰 | −6% | 0% | 8% |
| 존경 | −10% | 0% | 10% |

- 판매 가산은 쓰지 않는다(되팔기 위험이 가장 컸다).
- 계산 순서와 반올림은 지금 본편처럼 개당 계산.
- **점수 구간(임시):** 적대 −6,000~−3,001 · 경계 −3,000~−1 · 중립 0~2,999 · 우호 3,000~8,999 · 신뢰 9,000~20,999 · 존경 21,000~42,000. 출신 문명은 3,000(우호 시작)에서 시작.
- **크기 이름 → 점수(임시):** 작음 25 · 중간 75 · 큼 250. 하락도 같은 표.
- Codex 확인: 안전 규칙을 넣은 뒤 같은 계산을 다시 돌려 같은 장터 되팔기 이익이 0인지 보고한다. 품목·시설 잠금 단계는 R2 구현 때 '신뢰'(일부 희귀품·수도권 고급 시설)·'존경'(최상위)으로 연결한다.

## 4. E1 — 거리 단위 (Codex 요청 [E1-B2-Handoff](Validation/B1-Migration-2026-10-25/E1-B2-Handoff.md) 1번)

- **기준은 '예상 이동 시간'이다.** 길 연결망에서 두 마을 사이 가장 짧은 길을 걸을 때 걸리는 시간(걷는 속도 기준). 맵 전환 횟수는 쓰지 않는다(맵마다 크기가 달라 한 구간이 같은 시간이 아니다).
- **경제 수치는 지금 균형을 지킨다.** 이동 시간을 '거리 단위'로 바꿀 때, 지금 고려 안 마을 쌍들의 거리 값이 지금과 최대한 같아지도록 환산 비율 하나를 정한다(기존 맨해튼 거리와 최소제곱으로 맞춤). 상품 가격·배달 보수·기한 공식은 그대로 두고 입력 거리만 바꾼다.
- 기한은 지금처럼 이동 시간에 여유 배수를 곱한다. 중앙 대륙 구간의 길 위 사건 지연은 기한 계산에 넣지 않는다(사건이 길을 늦추는 것이 여행의 재미).
- **지금은 B1 도식 길(직선)로 계산하고, B2가 실제 길을 만들면 실제 길 길이로 다시 계산한다.** 두 번째 계산은 B2 완료 조건에 넣는다.
- `ItemData.MapsFrom`, `ContractManager.Distance`, `DeliveryReward.RouteSteps`는 모두 이 거리 하나를 쓰게 한다.
- 완료 확인: 고려 마을 쌍 10개의 상품 가격·배달 보수·기한이 지금과 비교해 표로 나옴(차이 ±10% 안), 옛 저장의 진행 중 의뢰는 수락 당시 기한·보수 유지, 테스트 통과.

## 6. D5 — 맵 경계 이동 방식 (3번)

**지금 방식을 유지한다:** 맵 하나가 씬 하나, 맵 경계는 전체가 이어지고, 넘어갈 때 페이드(10/23 회의). 이어 불러오기·스트리밍은 하지 않는다. 맵이 3,000~5,000칸 크기라 지금 방식으로 충분하다. 온라인 단계에서 다시 검토한다.

## 7. D4/D7 — 다른 팀 구역 연결 (4번)

**고려와 중앙 동쪽 안쪽만 먼저 연결한다.** 다른 팀 구역 쪽 연결 지점(원안의 세 방향)은 계약 파일에 '비활성 연결 자리'로만 남기고 런타임 출구는 만들지 않는다. 팀원과 좌표·ID가 정해지면 그때 켠다.

## 8. E1 다시 정함 — 4절의 '쌍마다 ±10%' 기준 철회 (Codex 요청 [E1 Review](Validation/E1-2026-10-25/Review.md))

Codex 계산이 맞다. 4절의 기준이 잘못됐다. **새 배치(D)는 마을 위치 자체가 바뀌었다**(예: 나루–송악은 지금 맵에서 붙어 있지만 새 배치에서는 멀다). 그래서 쌍마다 지금 값을 유지하라는 조건은 처음부터 성립할 수 없다. 거리가 바뀌는 것은 새 지리의 정상적인 결과다.

**결정**

1. **거리 전환 시점을 맵 전환과 맞춘다.** 지금 게임은 아직 옛 맵이다. 새 배치 거리를 지금 넣으면 플레이어가 실제로 걷는 길과 맞지 않는다. 그래서 E1은 지금 다음만 한다.
   - 길 연결망 데이터(B1 원본에서)와 **거리 함수 하나**를 만들고, `ItemData.MapsFrom`·`ContractManager.Distance`·`DeliveryReward.RouteSteps`가 모두 그 함수를 부르게 한다.
   - 거리 함수의 입력은 설정 하나로 고른다: `current`(지금 맵의 기존 계산과 같은 값) / `layoutD`(새 배치의 예상 이동 시간 환산). **본편은 `current`.** 그래서 지금 가격·보수·기한은 그대로다(회귀 검사로 확인).
   - `layoutD`로 바꾸는 것은 새 맵을 본편에 넣는 B5에서 함께 한다.
2. **`layoutD` 환산 규칙:** 비율 하나(최소제곱 k), 거리는 반올림한 정수, 최소 1. 함수 형태가 지금과 같다.
3. **`layoutD`로 바꿀 때(B5)의 확인 기준** — 쌍별이 아니라 전체 규모와 플레이 가능성:
   - 고려 10쌍의 평균 기한·평균 배달 보수가 지금 평균의 ±15% 안.
   - 모든 의뢰의 기한이 실제 걷는 시간(게임 시간)보다 충분히 길다(달리기 없이 걸어서 기한의 70% 안에 도착 가능).
   - Q1 ② 장단 곡식 → 송악 판매가 여전히 이익인지. 아니면 [QuestMain1](QuestMain1.md) 3절 규칙대로 판매처를 바꾼다.
   - 진행 중인 옛 의뢰는 수락 당시 기한·보수를 유지.
4. B2에서 실제 길이 생기면 도식 길 대신 실제 길 길이로 `layoutD`를 다시 계산한다(4절 유지).

**E1 완료 기준(지금):** 거리 함수 하나로 통일, 본편 설정 `current`에서 가격·보수·기한이 기존과 완전히 같음(회귀 검사), `layoutD` 계산 결과 표가 나옴, 테스트 통과. 그다음 B2로 넘어간다.

## 9. R2 보완 (Codex 요청 [R2-Safety](Validation/R2-Safety-2026-10-25/README.md))

Codex 반례가 맞다. 같은 시점 호가 비교로는 산 직후 재고가 바뀌어 생기는 되팔기 이익(144→145 등)을 막지 못한다. 시세 공식을 건드리는 대신 **거래 기록으로 막는다.**

### 9-1. 되팔기 제한 (안전 규칙 보완)
- 마을마다, 물건마다 **최근 매입 기록**(수량, 평균 매입가)을 둔다. 매입하면 기록에 더하고, **12 게임 시간**이 지나면 사라진다(맵을 나갔다 들어와도 유지).
- 같은 마을에 그 물건을 팔 때 기록에 남은 수량만큼은 **판매가가 평균 매입가 −1냥을 넘지 않는다.** 기록을 다 쓰면 그 다음 수량은 원래 판매가.
- 이 제한은 평판·흥정·출신·장날·거래 성장과 상관없이 마지막에 적용한다. 3절의 '같은 시점 매입가 ≥ 판매가+1'도 유지한다.
- 완료 기준: Codex 안전 검산을 다시 돌려 **같은 마을 12시간 안 왕복 이익 0건**(수량 1/5/20/100, 성장 켬/끔, 흥정 포함). 다른 마을로 운반해 파는 정상 교역은 영향 없음(기존 고려 교역 이익 표와 비교).
- 기록은 저장에 들어간다(옛 저장은 빈 기록으로 시작).

### 9-2. 평판 잠금 대상 (지금 있는 것만)
| 대상 | 잠금 | 이유 |
|---|---|---|
| 나전칠기(`najeon`) **사기** | 그 마을 평판 '신뢰' 이상 | 고려 최고급 특산품. 시작(우호)만으로는 못 사게 하는 방향(방향 기준 5-1절). 파는 것은 막지 않는다. 퀘스트에 쓰이지 않음 |
| 그 밖의 상품 7종 | 잠금 없음 | 인삼·종이·소금 등은 Q1·사이드 퀘스트와 기본 교역에 쓰인다 |
| 시설 13개 | 평판 잠금 없음. 개경 보관소의 신용 3 조건 유지 | 지금 시설은 모두 기본 시설 |

- '존경' 잠금 대상은 지금 없다. 수도권 고급 시설·희귀 장신구·보물은 새로 만들 때 '신뢰'/'존경'으로 붙인다(새 콘텐츠 작업).
- 잠긴 물건은 장터 목록에 보이되 "평판 신뢰 필요"와 현재 진행을 표시한다.

### 9-3. 점수 누락분
- `VerySmall`(부분 납품 등 '아주 작음') = **10점**.
- **일상 거래 기여:** 사는 것은 0점. 파는 것은 마을마다 **게임 하루 1번만**: 그날 그 마을 판매 합계가 50냥 이상이 되는 순간 '작음'(25). 그 판매에 다른 지역 특산품(장거리 교역)이 들어 있으면 대신 '중간'(75). 9-1의 되팔기 제한에 걸린 판매액은 합계에 넣지 않는다.
- 의뢰·퀘스트 점수는 R6 표의 크기 이름 그대로.

### 9-4. 테스트 하나 고치기
`test_layout_d_terrain`의 경로 파일 비교가 환경에 따라 소수 끝자리(…950922 / …95092)가 달라 실패한다(Claude 쪽 numpy 2.2.6 / Python 3.10에서 재현). 내보낼 때 소수를 정해진 자리(예: 6자리)로 반올림해 환경과 상관없이 같게 만든다.

## 10. C6 — 반투명 픽셀 예외 (2026-10-26, Codex 요청: C6 사전 굽기 기록)

지금 그림 중 바위·건조대 그림자 5타일, 캐릭터 발밑 그림자, 물결 4프레임은 원래 반투명이다. A2 검사의 "알파는 0 또는 255" 규칙과 부딪힌다. **은샘 결정이 '지금 그림 유지'이므로 그림을 고치지 않는다.**

- **이미 있는 그림:** 반투명이 들어 있는 기존 그림은 파일 해시로 고정한 예외 목록에 올리고, 그 해시와 정확히 같을 때만 통과시킨다(Codex 권장안 채택). 한 픽셀이라도 바뀌면 예외가 아니다.
- **앞으로 만드는 그림:** 일반 개체·타일은 계속 알파 0/255. 단 `effect` 종류(그림자, 물결, 빛 같은 효과)만 반투명을 허용한다. A2 목록에 `kind: effect`를 추가하고, 그 경우에만 반투명 검사를 끈다.
- 이 결정으로 A2 검사가 통과하면 C6를 이어서 끝낸다: 굽기 결과를 본편에 연결(화면 변화 0을 Unity 전후 캡처로 확인), 생성 중 자르기·색 바꾸기 호출 0, 쓰지 않는 옛 맵·옛 생성 코드 정리(동물 NPC 참조 포함, 지우기 전 목록 보고).

# 최종 점검 2차 — 거래·Q1, 남은 문제

## 이번 결과

현재 codex/goryeo-atmosphere에서 일반 거래/Q1 다섯 퀘스트를 실제 등록 씬으로 진행해 자동Play **149확인**을 통과했다. 전체 게임의 최종 완료는 아니다.

- 100냥·신용0에서 Q1 첫 짐→곡식3개 거래→송악 일반 배달→닥목 종이2개 매입→개경 납품/판매까지 진행했다. 각 거래는 순차 견적의 금액과 새로 완료된 퀘스트의 수락 당시 보상을 합친 정확한 잔고/신용인지 검사했다.
- 첫 짐 수락 상태와 최종 완료 상태를 실제 임시 JSON에 저장하고, 시작 메뉴 Space 이어하기로 짐·진행·완료 기록/돈 복원을 확인했다. 완료된 첫 의뢰를 다시 보고해도 추가 보상을 받지 않는다.
- 일반 배달 의뢰 수락/목적지 게시판 납품·같은 의뢰 중복 지급 거절, 완료 후 신용3·잔고 비음수, 같은 마을 재계산 되팔기 이익0이하를 확인했다.
- NPC 대화/수락/보고·장터 열기·장부 L/Esc는 가상 Keyboard→일반 InputReader 경로다. 여러 의뢰 중 선택은 실제 목록의 OfferAt 도우미, 거래 버튼은 실제 TradeBatch 함수, 게시판 수락/납품은 실제 ContractManager 함수를 호출했다. 이 부분을 마우스로 클릭했다고 주장하지 않는다.
- 위치 이동은 QA 텔레포트·등록 씬 로드이고 실제 도보/이동 시간 검사가 아니다. 게시판 목록은 생산 DB/WorldIndex에 seed21을 쓴 재현 가능한 시험 값이다.
- 개경 여관 권유는 IMGUI Event.current로 Esc를 읽는다. 가상 Keyboard만으로는 이 GUI 이벤트가 생기지 않아 별도 CloseAsk 취소 함수로 닫았다. 실제 키/클릭 문제로 판정하지 않았다. 최초 실패/후속 캡처를 보존했다.

## 1. 공용 의뢰 게시판 잘림 — 승인 후 본편 수정 완료

ContractBoard.OnGUI는 높이310·목록202를 고정해, 고려 기본 화면480×270에서 창의 위쪽20px/아래쪽20px이 화면 밖으로 나간다. 실제 송악 게시판에서 제목과 닫기 버튼이 잘렸다.

처음에는 Editor 전용 GoryeoBoardLayoutTrial로 검토안을 만들었다. 2026-11-06 사용자 “게시판 수정안 승인” 후 본편 ContractBoard.cs에 아래 레이아웃4줄만 반영했다. 계약 수락/납품·보상/저장 코드는 바꾸지 않았다.

- 창 높이: 기존 UIStyle.WindowHeight(310) 사용.
- 목록 높이: 창 높이에 맞춰 계산. 제목·상태·닫기 버튼은 창 안에 둔다.
- 목록 글 너비를 줄여 불필요한 가로 스크롤을 없애고 세로 스크롤로 읽는다.

[전후 비교](../../ArtReview/Goryeo-Trade-Quest-20261106/board-comparison.png). **승인 후 본편 적용 완료.** 전체 파일을 시험 복사본으로 교체하지 않고 필요한 레이아웃 부분만 반영했다. 본편54확인/네이티브9캡처로 고려480×270/960×540, 수락·납품 목록·완료 메시지와 다른 세 문명640×360을 확인했다. 승인 검토본과 본편의 불투명 패널456×246 RGBA 픽셀차이는0이다(전체 화면 비교가 아님). 상세는 Docs/Validation/Goryeo-Board-Binding-2026-11-06. R4 통합 때 새로 늘어나는 영역은 보존해 다시 확인해야 한다.

## 2. R3·R4 연결 부재 — 로컬 보완·검증 완료, 화면 승인 대기

149확인 당시에는 별도 `claude/r3-r4`에만 코드가 있었고 원격 integration에도 없었다. 사용자 인계 지시 후 Codex가 현재 코드에 결합하고 실행 가능 수량·저장 실패 복원·기존 단일 거래 호출 호환을 보완했다. UI B안/승인 게시판 치수·ATM 우물3냥과 기존 ID/저장은 유지한다.

현재 로컬 `codex/r3-r4-integration`에서 Play99·C#62·Python403 두환경·Editor8종을 통과했다. 저장 실패 주입과 실제 시작 씬 Space 이어하기·속죄 수락/납품/실패/중복 거절을 포함한다. **사용자 새 화면 승인과 원격 integration 반영은 아직이다.** 옛 검토 근거는 [병합 전 기록](R3-R4-Merge-Review-2026-11-06.md), 현재 결과와 남은 한계는 [통합 기록](R3-R4-Integration-2026-11-06.md)에서 확인한다.

# ATM-B2 나룻배 빠른 이동 검토

사용자 “네가 할 작업들은 계속 진행해줘”에 따라 준비했다. 현재는 검토 전용이며 요금/시간/직항 구성·선택창·도착 위치 승인 대기다. 본편 자동 설치나 Resources/Ferry 설정은 없다.

## 제안

- 예성 나루(Naru), 버들나루(transit_ferry), 남동 포구(transit_southport) 세 곳을 서로 직접 연결한다. 각 사공 메뉴에서 나머지 두 곳을 고른다.
- 1회8냥·게임 시간1시간. 기존 짐/수레·출신/의뢰는 그대로 운송하며 새 무게 제한·미니게임·해금 조건을 추가하지 않는다. 최종 수치가 아니라 사용자 검토안이다.
- 기존 뱃사공·배 그림과 자리/ID는 그대로다. 목적지 이름 버튼과 요금·시간 본문만 추가하고, “이야기”로 원래 대사를 듣고 “다음에”로 닫는다. 초기 긴 버튼이480화면 밖으로 잘려 요금·시간을 본문으로 옮기고 버튼을 짧게 정리했다.

현재 TownRoutes.walkingDistances 기준 마을 사이 보행 시간은 예성↔버들57.09초, 버들↔남동59.74초, 예성↔남동39.99초다. 이 값은 등록된 기준표이며 실제 플레이어 출신/짐/날씨별 실측이 아니다. 현재 하루360초 설정에서는 약3.81/3.98/2.67게임 시간에 해당한다. 빠른 이동은 실제 걷는 시간을 줄이고8냥을 쓰는 선택이다. 시세/시장 거리/재고 회복·R2 가격 공식은 바꾸지 않는다. 이동 시간 대비 교역 수익성에는 영향이 있으므로 수치 최종 확정 시 함께 검토한다.

## 위치

좌표는 맵 JSON의 좌상단 기준이다. 도착은 사공 바로 왼쪽 한 칸이며 Unity의 실제 통행 가능/출구 아님을 검사한다.

## 검토 구현과 보존

Tools/WorldLayout/goryeo_ferry_trial.py는 기존 맵을 읽어 사공/차원/도착점·장터까지의 정적 연결과 보행 기준표를 추출하고 ArtReview/Goryeo-Ferry-20261105/source.json만 만든다. Maps/씬/공용 목록을 다시 만들지 않는다.

GoryeoFerry는 기본 비활성이고, UNITY_EDITOR에서만 안전한 previewOnly/자동저장OFF 세션에 EnableReview를 호출할 수 있다. 그 뒤 해당 세 맵만 메모리에서 previewOnly로 바꾼다. 실제 본편에는 메뉴가 나타나지 않는다. 다른 문명이나 다른 NPC에는 아무것도 하지 않는다.

Map/TalkNpc.Interact 앞에 지역용 선택 훅1줄을 넣었다. 원래 TalkNpc를 끄거나 대체하지 않아 기존 ID/대사순환·G선물/이름표/캐릭터·충돌을 보존한다. “이야기”에서는 이 훅만 잠시 우회해 원래 Interact를 호출한다. 공용 Core/Economy/Quests/UI·GameDatabase/WorldIndex/Connections·EditorBuildSettings는 수정하지 않는다.

실제 GameManager.TravelTo/기존 창호지·지역명 전환을 사용한다. SubsystemRegistration의 sceneLoaded 훅을 GameManager.Awake 등록보다 먼저 두어 새 도착 SpawnPoint를 등록한다. 도착 맵·통행 가능 지점·요금을 다시 검증한 뒤에만 돈을 차감/시계를1시간 진행하고, 그 뒤 공용 도착/MapEntered/저장 처리가 따른다. 출항 전에는 돈/시간을 바꾸지 않는다. 초기 돈부족/원격/미등록 목적지·중복 요청은 거절한다. 도착 검증 실패 시도 요금·시간을 적용하지 않는다. 추가 저장 필드는 없다.

본편 연결 전 필요한 결정은 위 직항3쌍/8냥·1시간/무게제한 없음/도착점과 화면 승인이다. 본편용 승인 설정/설치 가드 전환과 실제 저장 순서/도착 실패 복구 검사는 승인 후 단계이며, 검토 결과를 본편 완료라고 쓰지 않는다.

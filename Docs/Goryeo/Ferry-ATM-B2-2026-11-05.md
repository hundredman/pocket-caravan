# ATM-B2 승인된 나룻배 빠른 이동

사용자 “일단 좋은 것 같아.”로 화면/직항/8냥·1시간/짐·수레 유지와 사공 옆 도착을 승인했다. 게임1시간은 평소실제15초지만 승선은15초를 기다리지 않고 전환·로딩 후 시계에 운항1시간을 더한다. 전환 중 시계의 자연진행은 기존대로다.

## 규칙과 위치

예성 나루(Naru)·버들나루(transit_ferry)·남동 포구(transit_southport)는 서로 직항이다. 목적지에 관계없이1회8냥/게임1시간, 기존 짐·수레·출신/의뢰는 그대로다. 새 무게/날씨/평판·해금 제한이나 미니게임은 추가하지 않는다. 시세/시장 거리/재고·R2 가격 공식도 그대로다. 빠른 이동으로 시간당 교역 수익은 달라질 수 있다.

좌표는 맵 JSON 좌상단 기준이다. 정상 도착 칸은 사공 바로 왼쪽이며, 일시 막혔다면 주변1칸의 통행 가능/비출구 칸을 고른다.

|항구|사공|정상 도착|기존 정박배 좌상단(5×2)|
|---|---|---|---|
|예성 나루|47,28|46,28|53,27|
|버들나루|39,14|38,14|44,20|
|남동 포구|41,51|40,51|45,45|

세 곳 모두 승인된 기존 배가 있다. 구역도 원본·실제 게임 캡처로 확인했다(moored-boats.json). 버들나루 배는 선택창 뒤 사공 오른쪽 아래여서 초기 메뉴 그림에서는 가려졌다. 기존 배를 추가/변형/중복 배치하지 않는다. 승선은 기존 사공과 대화해 고른다. 원래 대사는 “이야기”, 비용 없는 취소는 “다음에”다.

## 구현과 보존

원본 goryeo_ferry_trial.py는 기존 맵/사공/도착 칸·장터까지 정적 연결·TownRoutes 보행표만 읽어 ArtReview/source.json을 만든다. 승인 원문과sourceSHA256은 approval.json, PromoteApproved가 검증해 Resources/Goryeo/Ferry/Config로 복사한다. source는 당시 review원본으로 보존한다.

GoryeoFerry는 해당3맵의 승인 설정으로 자동 동작한다. 기존 Map/TalkNpc.Interact 훅1줄은 NPC를 비활성화/교체하지 않고 원래 대사 순환·G선물/이름/캐릭터/충돌을 유지한다. 다른 NPC/다른 맵은 그대로다. 초기 Editor EnableReview는 저장OFF/previewOnly 전용으로 남겼으며 본편 맵을previewOnly로 바꾸지 않는다.

출항 전 목적지 등록/높이·범위·돈·거리·중복/이동중 여부를 확인하고 공개 GameManager.SaveNow로 현재 진행을 저장한다. 저장 실패 시 출항하지 않는다. 출항 전 돈/시계는 바꾸지 않는다. 실제 공유 GameManager.TravelTo/기존 창호지·지역명 전환을 사용한다. SubsystemRegistration에서 먼저 등록한 sceneLoaded 훅이 공유 도착 콜백 전에 안전 SpawnPoint를 만든다. 도착 검증과 요청 소유 GameManager/저장슬롯 일치 후 요금/운항시간을1회 반영하고, 이어서 공유 도착/MapEntered/저장이 진행된다. 무효/오래된 요청은 요금/운항시간을 적용하지 않는다. 새 저장 필드/경제거리·맵/씬/공용Core·Economy·Quests·UI/DB·WorldIndex/Connections·BuildSettings는 미변경이다.

## 확인과 한계

임시 전용 슬롯에서 실제 저장ON/본편138확인·6방향 적재손수레 운송·원래 NPC/대화·취소/돈부족/원격/미등록/중복·출항전 파일/도착후 실제 저장 JSON의 위치/요금/시각/수레·짐/출신을 검사했다. 저장실패와 목적지규격불일치 거절, 요청 소유자/슬롯 변조 주입 무차감, 정상도착 칸을 막은 안전인접 보정도 검사했다. 실제 프로세스 강제종료나 Unity 엔진의 로드실패를 재현했다고 쓰지 않는다.

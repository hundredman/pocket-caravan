# UI1 잘림 2건 수정 — 2026-11-06

## 상태

사용자는 앞선 글자 대비·조건 정리 시안을 “이대로 승인”했다. 승인 기록은 해당 submission.json에 반영했다. 이번에는 전반 UI 점검의 우선순위1·2인 문명 선택/다중 대화 선택지 잘림을 공용 표시 코드2파일에서 수정했다. **코드·아래 검사 완료, 사용자 “이대로 승인”으로 배치 승인.** GitHub integration/push/PR/게임 빌드는 하지 않았다.

## 문명 선택

StartScreen의 기존190×107 카드·출발 마을 그림·동물 그림/크기·문명/도착지 데이터는 그대로다. 화면 높이에 맞춘 목록 영역을 두고 작은 창에서는 스크롤한다. 방향키로 고르면 그 카드 전체가 보이는 위치로 자동 이동한다. 창 폭이 좁을 때는1열, 보통은 기존2열이다. 카드와 분리된 고정 소개 영역에서 강점·키 안내는 필요한 만큼 줄바꿈한다. 방향키·Space 선택·저장 메뉴로 Esc 뒤로 돌아가기 경로는 유지한다.

모든 카드를 한꺼번에 축소해 넣은 것이 아니다. 480×270에서는 위쪽/아래쪽 두 문명씩 원래 크기로 볼 수 있다. 사용자 검토판의 위 두 화면은 같은 목록에서 고른 문명이 다른 모습이다.

## 대화 선택지

DialogueUI의 한 줄 선택지가 들어가면 기존 한 줄 배치를 유지한다. 합계 폭이 넘거나 명시적 줄바꿈이 있으면 기존 공용 종이 버튼을 세로로 배치하고 긴 문구의 높이를 계산한다. 본문 페이지 영역은 유지하며 선택지 때문에 필요한 만큼 창을 위로 늘린다. 목록이 길면 선택지 부분만 스크롤하고 창/본문/페이지 번호는 화면 안에 둔다.

떠돌이 상인의 실제4개 선택지는 가격·수량·취소까지 모두 보인다. 선택지 순서/구매 콜백·Space 첫 항목·Esc 마지막 항목·마지막 페이지 전에는 페이지를 넘기는 기존 규칙은 유지했다. 새 게임·구매 규칙/수치/ID나 저장 형식은 수정하지 않았다.

## 실행 검증

- Unity 컴파일·Console error0. Editor 조건부 자동 Play **162확인**, 원본 캡처12장.
- 실제480×270·960×540·360×270 창에서 선택 카드/소개/선택지 창 범위와 겹침을 검사했다. 일반 크기2열·좁은 창1열의 네 카드에 실제 방향키로 접근한다.
- 현재 StartChoices 네 선택 각각을 실제 Space로 확정해 기존 startScene과 origin에 도착하는지 확인했다. 기존 저장 메뉴의 새 게임 진입→Esc 뒤로도 확인했다. 이는 한 테스트 세션에서 목적지/출신 연결을 확인한 것이지, 네 문명의 완전한 신규 게임/튜토리얼 전체 검사나 앱 재시작 검사가 아니다.
- 실제 떠돌이 상인4선택지를 표시만 했다. 실제 거래/구매는 하지 않았다. 별도 검토용0/1/2/4/8선택지에서 첫/마지막 콜백·페이지 진행을 가상 Keyboard로 확인하고, 긴 문구·명시적 줄바꿈·8개 목록의 마지막 항목을 GUI 스크롤로 드러낼 수 있는지 검사했다.
- 전체 Python403개(23skip), 실패0. 월드/씬 재생성 없음. 이전 Editor8종/별도Pillow환경/FPS 검사를 이번에 다시 통과했다고 쓰지 않는다.
- 사용자 기존 저장9파일 SHA256 불변·일회용 저장0. 검토는 저장OFF·전용 파일명으로 실행했다. 첫/새 게임 실제 선택은 기존 BeginNewGame을 통해 이동했지만 저장은 켜지지 않았고 사용자 슬롯도 지우지 않았다.

네이티브 마우스/휠 드래그·한글 IME·사람 직접 플레이·실제 로그인·온라인·모든 미니게임/언어/극단적 화면 크기·게임 빌드/FPS는 미검사다. 검토용 스크롤의 끝 위치 설정은 도구가 했고 GUI가 실제로 클램프한 뒤 마지막 행의 범위를 확인했다. 클릭을 직접 했다고 주장하지 않는다.

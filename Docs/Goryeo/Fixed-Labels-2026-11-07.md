# 고정 이름표·Space·작은 퀘스트 아이콘 — 2026-11-07

사용자 후속 지시: 이름은 대상 위, Space는 아래. 플레이어 이동 때문에 위치가 바뀌지 않도록 한다. 퀘스트 표시는 이름 오른쪽의 작은 네모 아이콘으로 둔다. 문자만 남긴 안을 검토한 뒤 기존 네모가 더 낫다는 사용자 최종 선택을 반영한다. 중간 승인을 기다리지 말고 최종 확인 자료를 준비하는 기존 지시를 따른다.

## 적용

- 이름은 NPC/물건 자신의 그림 위, Space는 자신의 그림 아래에 고정했다. 같은 대상의 좌표를 플레이어·다른 인물·가림 상태·접근 대상 우선순위에 따라 다시 찾지 않는다. 화면 끝으로 밀지도 않는다.
- 인물은 걷기/방향 프레임 대신 고정 정면 그림 범위를 기준으로 삼는다. 대상이 움직이면 그 대상을 따라가지만, 플레이어가 움직였다는 이유로 자리가 바뀌지는 않는다. 게시판은 가까운 실제 게시판 그림 범위를 고정 기준으로 쓴다.
- 작은 글씨/밝은 외곽선과 Space 단독 표시는 유지한다. 가까워질 때의 표시 범위는 유지하며 표시 여부와 위치를 구분한다. 다른 이름과 겹치는 보조 장소 이름은 다른 자리로 옮기지 않고 생략한다.
- 퀘스트 기호는 이름 문자열에서 분리했다. 실제 QuestManager 상태를 읽어 수락 가능 !, 완료 가능 ?를 금색으로 표시한다. 진행 중 ?는 기존 회색 구분을 유지한다. 어두운 바탕과 금색 테두리의 기존12×14px 네모 안에 !/?를 표시한다.
- 기호는 이름 오른쪽3px 간격에 별도로 붙인다. 기호가 생기거나 !에서 ?로 바뀌어도 이름 중심/좌표를 바꾸지 않는다. 기존 작은 월드 퀘스트 스프라이트는 이 범위에서 중복 표시하지 않고, 컴포넌트 비활성화/지역 이탈 때 원래 상태로 복원한다.

가림 회피를 위해 이리저리 재배치하던 탐색과 플레이어 몸 보호에 따른 좌표 이동은 제거했다. **모든 다른 에셋/이름과의 겹침0을 주장하지 않는다.** 이번 우선 기준은 대상 바로 위/아래의 고정 위치와 작은 점유 면적이다. 맵·NPC 배치·카메라 이동·상호작용·퀘스트 진행/보상·ID·저장 형식은 변경하지 않았다.

## 확인

- 최종 Unity 자동 **2699확인**, 480×270 원본 **30캡처**. 고려·중앙 동쪽13맵에서 플레이어를 대상 주변16위치로 옮겨 이름/같은 대상의 Space/퀘스트 문자 좌표가 바뀌지 않는지 확인했다. 이름은 자신 위, Space는 자신 아래, 기호는 이름 오른쪽인지 검사했다.
- 같은 대상 Space 반복 비교25회, 접근 대상 변경9회를 실행했다. 카메라12단계 이동에서는 대상 기준 픽셀 오프셋과 Space 반올림 안정성을 확인했다. 위치 이동은 도구가 실제 PlayerMotor.Teleport로 준비한 것이며 사람 키보드로 연속 걸어 본 시험은 아니다.
- 실제 NPC의 기존 퀘스트 스프라이트 중복 숨김/범위 해제 때 복원, 이름 끝의 !/? 제거, 실제 MarkerFor 상태와 표시 상태 일치를 확인했다.
- 별도 저장OFF 슬롯에서 기존 `q1_naru`를 실제 수락하고 장단 수령 NPC(`goryeo_jangdan_farmer`, 현재 표시명 장단 곡물 상인)의 완료 가능 상태를 만들어 **실제 완료 가능 물음표 아이콘**도 촬영했다. 새 퀘스트를 만든 것이 아니며 개인 진행에 반영하지 않았다.
- Python403개/23skip 통과(최종 네모 복원 직전 실행). 네모 복원 뒤 표시 범위 정적2개와 Unity 전체 고정 배치 검사를 다시 실행했다. 세계1437출구/오류0. Unity 컴파일/최종 콘솔은 별도 JSON 참조. 맵·씬/저장 변경이 없어서 Editor 지형·전체 경제·전체 저장 회귀를 다시 실행하지 않았다.
- 사용자 진행을 SaveNow 성공 후 종료하고9개 파일을 백업했다. 이후 해시 보존 확인은 `Docs/Validation/Goryeo-Fixed-Labels-2026-11-07/save-preservation.json`을 따른다. 개인 저장ON 상태에서 QA를 실행하지 않았다.

아래쪽 이름/문자만 표시한 아이콘안은 중간 기록이다. 최종 기준은 이름 위·Space 아래와 이름 오른쪽 작은 네모 아이콘이다. `previous-below-name-layout.json`은 중간 기록이고 `play.json`이 최종 결과다. 이전916/57검사를 이번 새 결과에 합산하지 않는다.

# 실제 플레이 제보: 초상화·수레·게시판·이름표

사용자 제보: 이동 중 일정 구역을 벗어나지 못함, 초상화 절반 잘림, 사람이 끌지 않는 수레 단독 이동, 수레에 사람이 가림, 글씨에 의뢰 게시판 가림, 이동 중 NPC/게시판/장소 이름표 흔들림. 화면 수정안은 확인 대기이며 원격 integration에는 아직 넣지 않았다.

## 수정

- CuteUI.Portrait: 이동/걷기 프레임 대신 정면 첫 그림을 사용한다. 기존 위쪽60%는16×24 너구리의 머리 위 여백5px을 포함해 얼굴 아래를 자르므로 위쪽18px(75%, 정수 픽셀)까지 표시한다. 기존 원형 테마 안에 비율을 유지해 가운데 배치한다. 새 아트/에셋 변경은 없다. 다른 방향/프레임에서도 같은 초상화다.
- GoryeoVillageLife: 혼자 왕복하던 생활 수레의 PingPong 이동을 제거해 기존 시작 자리에 세운다. 닭·배·사람 등의 기존 생활 연출은 유지한다. 생활 수레는 사람보다 뒤에 그린다.
- CarryVisual: 플레이어 자신의 수레/적재 상자를 몸보다 낮은 그리기 순서와 같은 레이어로 맞춘다. 수레 충돌·적재/거래·차량ID/속도는 바꾸지 않는다.
- GoryeoPlaceLabels: 실제 게시판 SpriteRenderer 영역을 보호해 이름표가 겹치지 않게 하고 게시판 이름은 그림 위, Space 안내는 그림 아래에 둔다. 말 걸기 동작/문구와 퀘스트 안내는 유지한다.
- 이름표 배치와 겹침 계산을 카메라와 독립된 좌표에서 하고, 카메라의 공통 이동을 픽셀 단위로 더한다. 화면 끝으로 이름표를 강제로 몰아 쌓던 처리를 제거해 영역 밖의 이름표는 표시하지 않는다. 마우스 hover 등 스타일 상태도 동일 색으로 고정한다. 실제 NPC 자체가 이동하거나 다른 이름표가 새로 가까워지는 상황까지 모든 재배치를 없애는 기능은 아니다.

게임 코드4파일만 변경했다. 시장/상품/퀘스트/NPC/시설ID·저장 형식·맵·씬·카메라·출구·이동 충돌은 변경하지 않았다. 표시 변경이 포함되므로 통합은 사용자 그림 확인 뒤 별도 진행한다.

## 이동이 막힌 제보

사용자가 “다시 시작하니 괜찮아졌어”라고 알려왔다. 점검 시에는 장단/솔재/초원 진입로로 이동이 가능했고 TimeScale1·UI잠금false·전환중false 상태를 읽었다. 원래 막혔을 때의 위치/상태를 캡처한 것이 아니므로 원인 규명이나 해결 완료로 처리하지 않는다. 지형/충돌을 추측해 뚫지 않았다. 재발 시 현재 씬·발 위치·입력·UI잠금·출구/주변충돌을 같은 시점에 기록해야 한다.

## 실행한 확인

- 사용자 실제 저장ON 플레이를 발견해 읽기/스크린샷만 먼저 진행했다. 원본9저장을 백업한 뒤 SaveNow 성공을 확인하고 Play를 종료했다. 이후 별도 저장OFF·일회용 슬롯으로 검토했다.
- 최종 Unity 자동407확인·480×270 원본48캡처. 정면 원본이 연결된4출신·4방향에서 같은 정면 Sprite 선택과 초상화36×36 RGBA 픽셀 동일, 자기 수레4방향의 몸/짐 그리기 순서와 정지, 실제 생활 수레 시간 변화 후 위치 불변/사람보다 뒤 순서를 확인했다.
- 나루·솔재의 실제 게시판 그림 보호/이름 유지, 카메라24단계 이동 중 이름표의 카메라 독립 배치와 겹침0을 확인했다. 최종 화면에서는 실제 플레이어의 상호작용 대상 갱신을 켜 Space 안내도 촬영했다. 첫 통과407은 북쪽 수레 캡처가 옆 방향이어서 최종 촬영을 보완한 뒤 다시407확인했다. 합산하지 않는다.
- 검토판의 초상화 “기존”은 이전 표시 코드를 Editor 검토 오버레이에서 재현한 것이다. 수정 HUD는 현재 게임 코드다. 초상화 비교 부분만2배 nearest 확대했고 게임 캡처 원본은480×270 그대로 보존했다. 이동 GIF는 실제 연속 캡처24장을 왕복 순서로 재생한 것이다. 반복 끝의 순간 이동을 피하기 위한 편집이며 원본 PNG24장은 그대로다.
- Python403개/23skip 통과, 월드0오류·1437출구, 최종 Console 컴파일error0. 초기 검사 도구의 잘못된 API/목록 참조2건을 고쳤다. Python 첫 실행1실패는 게시판 Space 안내의 공용 코드 완전 일치 전제였으며, 게시판 표시 앵커1줄만 허용하고 나머지 안내/퀘스트 로직의 엄격 비교는 유지해 재실행했다.
- 사용자 체크포인트 이후9저장 SHA256 불변·검토 임시파일0. 진행 저장 전후의 정당한 파일 변경을 QA 불변 검사와 혼동하지 않는다.

사람이 실제로 움직이며 느끼는 이름표 안정감/가독성은 확인 대기다. 실제 온라인·다른 지역 전용 화면/모든 카메라/모든 수레 배치·장시간/FPS·게임 빌드·원래 이동 막힘 재현은 미검사다.

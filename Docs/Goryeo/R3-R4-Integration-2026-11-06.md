# R3·R4 현재 코드 연결 — 2026-11-06

## 상태

Codex가 사용자 지시로 Claude 작업을 인계했다. `codex/r3-r4-integration`에서 `claude/r3-r4` 원본9c0fe9d06의 게임 코드9개와 규칙 검사를 현재 region/goryeo의 UI B안·거래/게시판에 결합했다. 옛 파일 전체를 덮거나 다른 문명 전용 파일·맵을 재생성하지 않았다. **구현·아래 검사 완료, 사용자 화면 승인 대기. GitHub integration 반영·push/PR/게임 빌드는 하지 않았다.**

## 바뀐 동작

- 흥정 확률에는 요청 최대치가 아닌 할인 전 실제 실행 가능한 견적 수량을 쓴다. 품목·방향·날짜·실수량이 일치하는 한 번의 거래에만 할인하며, 돈/재고/적재 변화로 수량이 달라지면 적용되지 않는다. 할인으로 더 살 수 있어도 합의 수량으로 제한한다. 실행 경계에서도 합의 수량과 실제 견적을 대조한다. D10 확률·20개 기준·5%p 보너스는 그대로다.
- 기존 단일 거래 Buy/Sell 진입점을 보존하고 할인 거래를 별도 내부 함수로 처리한다. Q1·R2 검사 호출과 현 일괄 견적/장부 L·지역 UI 동작을 유지한다.
- R4 마을 일·기부·속죄는 기존 결정대로 중립까지만 회복한다. ATM 우물 사례비3냥과 별개다. 속죄 제안은 해당 게시판 확인 때에도 준비해 한 시간 기다리지 않아도 된다. 기존 한 평판 단위당 하나/24시간 재개방 정책은 유지한다.
- 흥정 시도·게시판 수락/납품·마을 일 수락/보고·기부는 저장 사전 확인→작업→저장 순서다. 실패하면 돈·신용·평판·거래 기록·의뢰/게시판/계약 필드·시각·시장/NPC 상인·퀘스트 진행을 함께 되돌린다. 마을 일의 한 시간 진행이 일으킨 경제 변화도 포함한다. 원래 계약 객체 참조를 유지한다.
- 속죄 저장 필드의 잘못된 보증금/대상은 거부하며, 보증금 반환으로 잔고가 넘칠 때는 의뢰를 소모하지 않는다. 기존 일반 계약과 누락된 R3/R4 선택 필드는 계속 읽는다. 저장 버전·기존 ID는 변경하지 않았다.
- 작은 화면에서 흥정 버튼은 두 줄로, 회복은 세 경로가 보이도록 문구/여백을 조정했다. 승인된 게시판 바깥 높이/목록 글 너비/세로 스크롤은 유지한다. 수락·납품 메시지 높이를 계산해 목록 공간을 줄이므로 긴 상태 문구와 닫기 버튼도 화면 안에 남는다. 480×270 실제 화면10장이 제출 폴더에 있다. 이후 사용자 지시로 회복·게시판도 장터의 기존 공용 UI B안으로 통일했다. 그 종이 테마는 사용자 승인됐고 현재 가독성 보완 검토판은 `ArtReview/Goryeo-R3-R4-Readable-20261106`이며, 어두운 이전 검토판은 이력으로 남긴다. 테마 변경 후 Play99확인/10캡처를 재실행했다([검증](../Validation/R3-R4-Paper-2026-11-06/README.md)).

## 남은 확인과 한계

사용자 화면 승인, 사람이 실제 클릭/도보로 하는 흥정·속죄 기한 체감, 앱 종료/재시작 전체 경로, 온라인·장시간/FPS·빌드는 미검사다. UI는 실제 Interact/함수를 호출해 열고, 버튼 동작은 실제 콜백/매니저를 호출했다. Esc/Space 이어하기는 가상 Keyboard→InputReader로 실행했으며 네이티브 마우스 클릭이라고 쓰지 않는다. Read 데이터의 saveToLoad 준비는 시험 도구 주입이다. 실제 사용자 슬롯을 불러와 시험하지 않았고 실제 디스크 고장도 만들지 않았다. 반올림 때문에 저가품 흥정이0냥일 때 최소1냥 보장 여부 등 기존 수치 결정 대기는 그대로다.

시험 도구의 초기 슬롯/시작 씬 준비 오류와 수정 이력은 검증 폴더 fixture-history에 남겼다. 도착지에서 직접 Continue를 호출하면 비시작 씬 정책으로 저장이 꺼지는 것은 게임 버그로 판정하지 않았다. 최종 시험은 시작 씬을 거치고 메모리 변조 후 복원도 확인한다.

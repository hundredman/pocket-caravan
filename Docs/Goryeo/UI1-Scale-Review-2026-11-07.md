# UI1 배율 원인·후속 범위

지도 짧은 이름/양옆 이름표는 사용자 “이대로 승인”으로 확정했다. 초기 조사 때에는 코드 읽기와 수식 계산만 하고 UI 코드는 바꾸지 않았다. 이후 사용자 재수정 지시로 공용 기준을 적용했으며 아래 적용 절과 UI4 결과를 따른다.

## 변경 전 원인

변경 전 UIStyle은 고려/중앙 동쪽13맵에서 높이270 기준 정수 배율을 썼고, 다른 지역은 가상 높이360 연속 배율이었다. 폰트와 본문/작은 글자 크기도 달랐다. 아래 표는 변경 전 수식이다.

| 실제 화면 | 고려 배율 | 다른 지역 배율 | 고려 본문 크기×배율 | 다른 지역 본문 크기×배율 |
|---|---:|---:|---:|---:|
|480×270|1|0.75|12|8.25|
|640×360|1|1|12|11|
|960×540|2|1.5|24|16.5|
|1280×720|2|2|24|22|
|1920×1080|4|3|48|33|

수식상 명목 글꼴 크기이며 실제 글자 잉크 영역이나 OS배율/DPI 실측값은 아니다. 앞선 실제480×270 캡처에서 타 지역 글자가 작았던 관찰과 일치한다. 정수 배율은 고려의 도트를 유지하지만540·810 등 경계에서 UI 크기가 단계적으로 변한다. 이것만으로 카메라/플레이 버그라고 단정하지 않는다.

## 사용자 결정과 적용

2026-11-07 후속 지시로 **팀 공용360 기준을 고려에도 적용**한다. UIStyle.Scale은 모든 문명에서 Screen.height/360, 본문11·작은9·공용Galmuri로 통일한다. 고려 전용270/정수/큰 글자 분기를 제거하며 다른 지역 전용 창을270으로 바꾸지 않는다. 따라서 기존360기준 팀 구현은 유지된다. [재수정·실제 비교 결과](Common-Scale-2026-11-07.md)를 따른다.

별도로 만들었던 오른쪽 아래 튜토리얼 카드와 하단 다음목표 알림도 중복을 없앤다. 보상 알림과 공용 HUD 조작 안내는 유지하며 영역을 확보한다.

480×270은 이번 검토 해상도이며 팀 전체 최소 지원 규격을 새로 확정했다는 뜻은 아니다. 실제 온라인/모든 지역 전용 미니게임/네이티브 입력/빌드/FPS 확인과 구분한다. PR28까지는 이미 integration에 병합됐고, 이번 공용 배율 재수정은 별도 로컬 검토본이다.

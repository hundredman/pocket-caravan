# UI1 배율 원인·후속 범위

지도 짧은 이름/양옆 이름표는 사용자 “이대로 승인”으로 확정했다. 이번에는 코드 읽기와 수식 계산만 했다. 새 Unity 실행/캡처/Python 검사나 UI 코드는 변경하지 않았다.

## 확인한 원인

UIState.cs의 UIStyle은 GoryeoTravelTransition.RegionOf에 해당하는 고려/중앙 동쪽13맵에서 높이270 기준 정수 배율을 쓰며, 다른 지역은 가상 높이360을 유지하는 연속 배율이다. 폰트 프로필/본문·작은 글자 크기도 다르다.

| 실제 화면 | 고려 배율 | 다른 지역 배율 | 고려 본문 크기×배율 | 다른 지역 본문 크기×배율 |
|---|---:|---:|---:|---:|
|480×270|1|0.75|12|8.25|
|640×360|1|1|12|11|
|960×540|2|1.5|24|16.5|
|1280×720|2|2|24|22|
|1920×1080|4|3|48|33|

수식상 명목 글꼴 크기이며 실제 글자 잉크 영역이나 OS배율/DPI 실측값은 아니다. 앞선 실제480×270 캡처에서 타 지역 글자가 작았던 관찰과 일치한다. 정수 배율은 고려의 도트를 유지하지만540·810 등 경계에서 UI 크기가 단계적으로 변한다. 이것만으로 카메라/플레이 버그라고 단정하지 않는다.

## 변경 영향과 다음 범위

같은 화면에 같은 배율을 쓰는 방향은 비교할 수 있으나, 먼저 각 지역의 고정 높이 창을 확인해야 한다. 가상 높이를270으로 통일하면360기준으로 만든 지역 전용 창/미니게임이 잘릴 수 있다. 공용 창만 키우면 기존 지역 UI와 크기가 다시 달라질 수도 있다.

UIStyle.Scale/VirtualHeight는 HUD/공용 지도뿐 아니라 NetChat/RemotePlayers 머리 위 표시, NorthCaravan/NorthSnowball의 화면 좌표 변환과 Venice/Arabia/North 전용 창에서도 사용한다. 따라서 이번 승인 기록에서 자동으로 전체 기준을 바꾸지 않았다. 다른 문명 전용 코드는 수정하지 않는다.

다음 배율 작업은①공용 최소 지원 창 크기와 지역별 높이 기준을 검토 범위로 정하기 ②4문명 HUD·지도·장터/공용 창과 담당자가 확인할 지역 전용 창을 같은 크기로 비교 ③표시와 마우스 좌표/스크롤을 같이 검사하는 순서가 적절하다.480×270은 현재 검토 크기이지, 이번 조사로 팀 전체 최소 지원 규격이 확정된 것은 아니다. 실제 온라인/전용 미니게임/네이티브 입력/게임 빌드/FPS도 완료했다고 쓰지 않는다.

앞선 공용 UI/지도 수정은 로컬 브랜치에만 있다. 원격 통합은 별도 지시와 팀 공지 절차를 따른다.

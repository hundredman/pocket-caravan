# E3 범람 — Claude 본편 연결 전달

Codex 런타임/생성기 연결 준비 완료. 실제 맵 배치·본편 연결은 AgentGuide/Plan 및 `Codex-Requests-2026-11-03.md`의 분담대로 Claude가 한다. 이번 작업은 본편 Maps/Scenes/DB/저장/공용 Core·Economy·Quests·UI를 고치지 않았다.

## 승인 기준

`ArtReview/E3-FloodTerrain-20261103/approval.json` (사용자 2026-11-03). 강62칸 확장, 길22칸 침수. 기존 강 조립 타일만 쓰고 수면 내부에 테두리를 남기지 않는다. 별도 범람 PNG v1/v2는 폐기 상태다.

## 연결 순서

1. `codex/e3-art` 작업을 검토·병합한다. `MapJsonBuilder.cs`의 새 `terrainFloods`는 선택 항목이다. 메타데이터 없는 기존 맵은 기존대로 만든다.
2. 최신 `Tools/WorldLayout/m4_export.py`의 맵 데이터 작성 단계에서 **JSON을 쓰기 전에**, `Tools/MapGen/river_flood_binding.py`의 `attach(data, placement_id)`를 호출한다. 이 원본 연결은 Claude 담당 파일이라 Codex가 대신 고치지 않았다. 생성 JSON만 손으로 바꾸지 않는다. 고려/다른 중앙 맵은 attach가 그대로 보존한다.
3. 북동 길의 새 제안 배치 ID는 `e3_wetroad_flood`, 정의 ID는 기존 `river_flood`. 이미 정한 실제 배치 ID가 있다면 `e3_` 접두사를 유지해 명시적으로 넘기고 이후 유지한다. 기존 별도 그림 범람 배치가 있으면 중복으로 두지 말고 정리 후 생성한다(attach/빌더가 중복을 거부한다). 통나무·산적 등 다른 배치는 유지한다.
4. 최신 배치 원본에서 북동 길 맵을 다시 생성한 뒤 `MapJsonBuilder`로 해당 본편 씬을 만든다. 본편 BuildSettings/WorldIndex나 다른 문명 씬을 새로 만들 이유는 없다. 미승인 통나무/아이콘/포구 수정과 범람 승인을 섞지 않는다.
5. 본편 씬에서 컴파일·실제 이동·재진입·기존 저장 불러오기를 다시 확인한다. 새 공유/온라인 규칙을 임의 추가하지 않는다. 원격 통합은 사용자 지시·카톡 전후 공지 후에만 진행한다.

한 맵 입력/출력 형태로 확인하는 보조 명령은 `python Tools/MapGen/river_flood_binding.py INPUT.json OUTPUT.json --id e3_wetroad_flood`다. 본편 반영 시에는 이 명령으로 생성물만 덧씌우지 말고 2번의 원본 내보내기 단계에 연결한다. 현재 검증한 데이터 예시는 `ArtReview/E3-FloodRuntime-20261103/terrain-binding.json`이며, 최신 원본에서 다시 만들어야 한다.

## 동작·안전

- `RiverFloodTerrain.cs`: 기존 일별40% 선택(`RoadHazardSchedule.Enabled`)과 정의의 활성9초/개방6초를 재사용한다. 순환 시계는 기존 ObstacleField와 같은 **방문별 플레이 시간**이며 UI 일시정지 동안 멈춘다. 재진입 시 순환이 다시 시작되는 기존 방식도 유지한다. 일별 선택은 같은 맵·ID·게임 날짜에 대해 동일하다.
- Ground/Deco/Blocked/RoadGrid를 한 번에 전환하고 원상 복원한다. 별도 Sprite/사각 장애물 영역은 만들지 않는다. 맵을 떠나거나 컴포넌트를 끄면 임시 변경을 복원한다.
- 캐릭터 발 충돌 상자가 새로 잠길 칸과 겹치면 범람 적용을 보류한다. 다른 칸으로 벗어나고 아직 범람 시간이라면 다시 적용한다. 강제 이동·재산 차감은 없다.
- 맵 기준 타일/충돌/등급이 다르거나 필요한 그림이 없으면 적용하지 않고 오류를 낸다. 크기/원점·침수 규모가 승인본과 달라지거나 기존 범람 배치와 충돌하면 생성 단계에서 거부한다. 임의로 다른 위치에 옮기지 않는다.
- 새로운 저장 필드를 추가하지 않았다. 재입장/불러오기는 기존 날짜와 방문별 순환으로 다시 계산한다. 온라인 서버 동기화는 별도 작업이며 이번에 구현하지 않았다.

# ATM-B5 장맛비·통나무 연결

사용자 “추천안으로 진행” 승인 범위: 장맛비가 오는 날에만 승인된 초원 진입로 숲길 한 곳의 기존8시간구간50% 진입 판정을 적용한다. 무료3초 치우기·위치·충돌·ID·방문 중 해결 상태 유지. 번개·천둥은 별도 시안 확인 뒤 연결한다.

## 본편 연결

- 대상은 transit_central_approach / e3_central_approach_log 한 쌍뿐이다. GoryeoStormLogs가 승인된 Resources/Goryeo/Atmosphere 설정의 날짜별 날씨를 읽는다. Clock.TotalHours에서 day=1+floor(hours/24)로 같은 날짜를 구한다.
- RoadHazardSchedule.Enabled의 기존 fallen_log 판정 앞에 장맛비 조건을 하나 추가했다. native log Start(-150)에서도 ObstacleField.Start 전에 최종 도착 시각으로 이 한 곳만 판정해, 초기 콜백 상태와 충돌/그림이 어긋나지 않게 한다. 기존 FNV 결정값/8시간구간/.5 확률을 그대로 쓴다. 봄비·맑음·안개에는 그 위치의 통나무를 켜지 않는다. 다른 통나무·범람 일정은 원래 값과 같다. 승인 날씨 설정을 찾지 못하면 대상 통나무를 켜지 않는다.
- 기존대로 맵 진입 때 판정한다. 방문 중 날짜·8시간구간이 바뀌었다고 통나무가 갑자기 나타나거나 사라지지 않는다. 치운 뒤 같은 방문 동안 다시 켜지지 않는다. 다시 방문하면 원래 일정으로 판정하므로 같은 조건에서 재등장할 수 있다. 해결 상태를 영구 저장하는 기능은 추가하지 않았다.
- 새 피해·보상/가격/지도·씬/원본 그림·통행 마스크·날씨 확률·저장 형식 변경 없음. 산적 연계 없음.

## 승인된 번개·천둥 본편 연결

사용자 “이 표현과 빈도로 승인” 후 연결했다. ArtReview/Goryeo-StormLogs-20261105/thunder-approval.json에 승인 원문과 Native/source/당시 효과 코드 지문을 보존했다. EditorTools.GoryeoStormLogReview.PromoteApproved가 지문 검증 후 Resources/Goryeo/Thunder로 온전한 PCM을 복사한다. GoryeoThunder는 검토 당시와 같은7%빛0.4초/0.7초뒤 천둥·실제 효과음음량×.35/음소거를 사용한다. 원작합성5.5초 음원은 바꾸지 않았다. 옛 Trial 클래스는 본편용 이름으로 바꾸고 GUID를 보존했다.

GoryeoLogVisuals.Start에서 기존 날씨 조건을 확정한 다음, 승인 대상 배치가 켜진 본편맵에만 Director.Apply로 효과·Trigger·AudioSource를 각각 하나만 만든다. 충돌 상태가 완성되고 실제 장맛비이며 대화/화면전환이 끝난 때 한 번 재생한다. 재생 전 통나무가 해결되었거나 해당 진입8시간구간을 이미 벗어나면 시작하지 않는다. 누락 음원·실패한 트리거는 구간을 소비하지 않는다.

재생 이력은 static HashSet<int>이며 앱 실행/Editor Play 세션 시작의 SubsystemRegistration에서 비운다. 씬 재진입·비활성/재활성/저장 불러오기만으로 같은 세션의 이력을 비우지 않는다. 같은 구간 재진입은 무음, 다른 발생 구간은 다시1회다. 새 저장 필드는 없다. 다른 맵은 설치/재생하지 않는다. 맵 이탈·비활성·날씨 불일치 시 소리/빛을 멈추고, 씬 이탈 때 소유 소스를 정리한다. 음소거 상태에서도 빛은1회 보이며 그 구간은 재생한 것으로 센다.

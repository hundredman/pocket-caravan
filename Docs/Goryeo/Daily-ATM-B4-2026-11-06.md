# ATM-B4 일상 활동 — 우물 물 긷기 검토

## 현재 상태

사용자 계속 진행 지시로 착수했다. **화면 승인 대기, 본편 미연결**이다. B4 전체 완료가 아니다. 우선 기존 나루 우물에서 물을 긷는 활동 한 가지를 검토한다. 소 여물 주기 등 다른 활동은 이번에 만들지 않았다.

- 예성 나루의 기존 우물(원본 구역도 x245,y61/1×2칸, 맵 Naru x43,y35 밑칸)을 사용한다. 그림·크기·충돌·아낙 배치는 바꾸지 않는다.
- 가까이에서 Space → 물 긷기 선택 → 실제3초 진행 → 완료 안내. Esc/그만두기로 중단할 수 있다. 중단·컨트롤러/활동 비활성·씬 이탈·저장 슬롯/날짜 변경은 완료 횟수에 들어가지 않는다.
- 게임 날짜 기준 하루1회. 다음 날 다시 가능하고, 기록된 날짜보다 과거로 바뀐 경우에도 재이용하지 못한다. 이 횟수는 물 긷기 한 종류에 대한 기록이며, 우물마다 보상을 반복해서 얻는 기능은 없다.
- 돈·신용·평판·아이템/체력 보너스·시간 비용은 추가하지 않는다. UI를 연 동안의 이동·시계 정지는 기존 UIState 방식이다. 별도 두레박/손동작 애니메이션과 신규 소리는 이번 검토에 포함하지 않았다.

## 구현과 저장

GoryeoDailyActivity를 새로 추가했다. **자동 설치 코드와 본편 설정은 없다.** Editor에서 명시적으로 previewOnly 맵/저장OFF를 확인한 InstallReview만 설치할 수 있다. 잘못된 맵·규격·활동ID·저장키를 거절한다. 같은 설치 요청은 중복 개체를 만들지 않는다.

기존 공개 GameManager.GetMemo/SetMemo에 `goryeo:daily:water_day` 날짜만 기록한다. 공용 저장 형식의 cooldownKeys/cooldownUntil로 그대로 직렬화되고, 예전 저장에 이 키가 없으면 이용 가능하다. 북유럽의 비공개 필드 reflection 저장 방식은 가져오지 않았다. R4 마을 일/평판 회복 기록을 재사용하지 않는다.

공용 Core/Economy/Quests/UI·DB/WorldIndex/Connections/BuildSettings, 맵·씬·다른 문명 코드/그림·기존 ID는 미변경이다. 저장ON 사용은 QA가 일회용 슬롯에 수동 체크포인트를 쓴 경우뿐이다. **본편 완료 직후 자동 저장 정책은 아직 구현/검사하지 않았다.** 승인 후 본편 연결 단계에서 재접속/저장 실패 처리와 함께 정한다.

- Unity 자동 Play **42확인**, 실제 **480×270 4캡처**. 첫 촬영에서 우물이 대화창에 가려져 QA 카메라만 아래로5칸 옮기고 같은42확인을 재실행했다. 본편 카메라는 미변경이다.
- 접근/선택지1페이지·실제 진행·취소/재시도·같은날 거절·다음날 가능·과거날짜 거절, 활성/거리/UI/슬롯/날짜/씬 중단을 확인했다. QA 함수와 직접 날짜 주입 방식이며 사람이 키보드로 플레이한 검사가 아니다.

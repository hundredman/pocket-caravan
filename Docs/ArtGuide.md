# 아트 기준

정리: 2026-10-24. 원칙은 [방향 기준](Direction.md) 1~2절이다. 이 문서는 그 원칙을 실제 제작 기준으로 풀어 쓴다.
**아직 확정되지 않은 값**(타일 크기 등)은 [작업 계획](Plan.md)의 결정 대기 항목으로 관리한다. 결정 전에는 임의로 정하지 않는다.

## 1. 목표 스타일

기준 시안은 [Figma `아트 시안` 페이지](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=0-1)다.

- **분위기:** 밝고 따뜻하고 귀엽다. 사실적인 질감이나 세밀한 그림자를 쓰지 않는다.
- **캐릭터:** 2~3등신 동물 캐릭터. 큰 머리와 단순한 표정, 한복 모티브 옷. 플레이어와 NPC가 같은 그림체를 쓴다.
- **형태:** 굵고 단순한 실루엣. 작은 화면에서도 무엇인지 바로 알아볼 수 있어야 한다.
- **선과 명암:** 진한 색 테두리, 빛은 왼쪽 위에서. 명암은 2~3단계로 제한한다.
- **시점:** 정면을 약간 위에서 내려다보는 2D 탑다운. 아이소메트릭이 아니다.
- **색:** 공용 팔레트 하나를 모든 에셋이 함께 쓴다. 지역마다 강조색만 다르게 한다. 고려는 기와 남색, 청자 녹색, 볏짚 금색이다.

### Figma 시안에서 확인한 점 (2026-10-24)

- **디자인 레퍼런스:** 채도가 높은 귀여운 탑다운 마을. 길·풀·물 경계가 조립용 타일로 자연스럽게 이어진다.
- **고려 캐릭터 시안:** 너구리·토끼·고양이·수달 동물 캐릭터와 사람 캐릭터. 시안 문구는 48×48px, PPU 32를 **임시 기준**으로 적었다.
- **고려 물체·풍경 시안:** 짐, 나무, 꽃, 초가와 기와집, 성문과 성벽 모듈. 성벽은 "연결 가능한 모듈로" 만들라고 적혀 있다. 이 문서의 조립용 에셋 규칙과 같은 방향이다.
- **팀 간 차이:** 베네치아·아라비아 에셋은 단순하고 덩어리가 큰 도트다. 고려 물체 시안은 더 세밀하게 칠해져 있다. 팀 공통 기준을 정해야 한다(결정 대기 D3).

## 2. 기술 기준

| 항목 | 현재 엔진 | Figma 시안의 임시 기준 | 상태 |
|---|---|---|---|
| 타일 크기 / PPU | 16px / 16 | 48×48 캐릭터, PPU 32 | **결정 대기 D2** |
| 캐릭터 크기 | 16×24 (코드로 그림) | 48×48 | D2에 따름 |
| 필터 / 압축 | Point / 없음 | 같음 | 유지 |
| 카메라 기준 해상도 | 480×270 | — | D2에 따라 다시 정함 |

D2를 정하기 전에는 새 에셋을 대량으로 만들지 않는다. 타일 크기가 바뀌면 칸 수(면적) 기준은 그대로 두고, 화면에 보이는 크기와 카메라만 바뀐다.

## 3. 에셋 등록과 사용

1. **원본:** Aseprite 원본(`.aseprite`)과 내보낸 PNG를 함께 둔다. 위치는 `Assets/PocketCaravan/Art/<지역>/<종류>/`.
2. **목록(manifest):** 에셋마다 아이디, 용도, 크기(칸), 종류(단일 개체 / 조립용 세트), 허용 배치(예: 물가만, 길 위 금지)를 적는다. 형식은 작업 A2에서 정한다.
3. **맵 생성기:** 목록에 있는 에셋만, 적힌 용도로만 놓는다. 좌표로 시트를 잘라 쓰는 코드는 쓰지 않는다.
4. **검사:** 검사기가 목록에 없는 에셋, 일부만 놓인 개체, 용도와 다른 배치, 조립 조각 누락을 찾아 실패시킨다.
5. **출처:** AI로 만든 초안, 외부 팩, 직접 그린 것을 목록에 구분해서 적는다.

### 조립용 에셋 세트

| 세트 | 필요한 조각 |
|---|---|
| 물(호수·바다) | 가운데, 가장자리 4, 바깥 모서리 4, 안쪽 모서리 4, 물결 애니메이션 |
| 강 | 위 세트 + 폭 2~3칸 직선·굽이·하구 |
| 해안 | 모래/풀 ↔ 물 경계 전체. 해안선은 최소 5칸 폭의 큰 굴곡만 쓰므로(세계 배치 해안선 v2) 1~2칸짜리 돌기용 조각은 만들지 않는다 |
| 길 | 흙길·큰길·돌길 각각 가운데·가장자리·모서리·교차 |
| 풀/흙/밭 경계 | 경계 전체 세트 |
| 성벽 | 직선, 모서리, 끝, 문(열림/닫힘) |
| 다리·나루 | 시작, 가운데, 끝 |
| 산맥·절벽 | 가장자리, 모서리, 끝. 지나갈 수 없는 땅을 자연스럽게 막는 용도 |

## 4. 제작 방법

- **Aseprite:** 최종 도트는 실제 해상도로 여기서 다듬는다.
- **AI 이미지:** 시안과 초안에만 쓴다. 그대로 축소해 넣지 않는다. Aseprite에서 실제 해상도로 다시 찍는다. 팀 시안의 "단순 축소하지 말 것" 문구와 같은 원칙이다.
- **Claude / Codex:** 배치 코드, 목록, 검사기, 맵 생성을 맡는다. 도트를 코드로 생성하는 방식(현재 `chars.py`)은 새 스타일 기준을 통과할 때만 계속 쓴다.

## 5. 현재 에셋 진단 (2026-10-24, 코드 확인)

지금 게임 화면에는 그림 출처 세 가지가 섞여 있어 스타일이 통일되지 않는다.

| 출처 | 쓰이는 곳 | 코드 |
|---|---|---|
| Ninja Adventure 무료 팩(CC0) | 땅·물·길 타일, 일부 나무·집·소품 | `Tools/MapGen/tiles.py` (`STAMPS`, `K()`) |
| AI로 만든 고해상도 시트를 줄이고 색 수를 줄인 것 | 고려 건물, 마을 소품, 마당 돌바닥, 숲 | `Tools/MapGen/goryeo_art.py` (Architecture, VillageDetails, CourtyardStone, Woodland, PineAncient) |
| 코드로 그린 도트 | 플레이어·NPC 16×24 | `Tools/ArtGen/chars.py`, `items.py` |

새 규칙에 어긋나거나 의심되는 곳. 작업 A3에서 하나씩 확인한다.

- `goryeo_art.py`: 고해상도 AI 이미지를 부드럽게 축소(LANCZOS)하고 28색으로 줄인다. 도트를 새로 찍은 것이 아니라서 캐릭터와 그림체가 다르다.
- `goryeo_art.py`의 `RECTS`, `DETAIL_RECTS`, `WOODLAND_COLUMNS/ROWS`: 시트를 좌표 사각형으로 잘라 쓴다.
- `tiles.py`의 `STAMPS`: Ninja 시트에서 좌표로 사각형을 잘라 쓴다(`pinebig`, `roundbig`, `hall`, `bigtree`, `plot` 등). 원래 개체 경계와 맞는지 확인하지 않았다. `FIELD`는 언덕 조각을 밭처럼 쓴다.
- `STAMPS`의 `"slate"` 색 바꾸기와 `goryeo_art.tone()`: 맵을 만드는 중에 색을 즉석으로 바꾼다.
- `CourtyardStone.png`: 큰 텍스처를 64px 반복 타일로 줄여 쓴다.
- 잔물결: Ninja 프레임을 가공해 쓴다.
- `tiles.py`의 `forest_border()` / `stamp_clipped()`: 나무를 한 그루 단위로만 놓도록 고쳐져 있다. 유지한다.

# 아트 기준

정리: 2026-10-24. 원칙은 [방향 기준](Direction.md) 1~2절이다. 이 문서는 그 원칙을 실제 제작 기준으로 풀어 쓴다.
**아직 확정되지 않은 값**(타일 크기 등)은 [작업 계획](Plan.md)의 결정 대기 항목으로 관리한다. 결정 전에는 임의로 정하지 않는다.

## 1. 목표 스타일

기준 시안은 [Figma `아트 시안` 페이지](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=0-1)다.

- **분위기:** 밝고 따뜻하고 귀엽다. 사실적인 질감이나 세밀한 그림자를 쓰지 않는다.
- **플레이어:** 2.5등신 동물 캐릭터. 큰 머리와 단순한 표정, 지역별 복식(고려는 한복 모티브 옷)을 쓴다.
- **NPC:** 귀여운 픽셀 아트의 사람 캐릭터. 플레이어와 같은 그림체·도트 밀도·팔레트·시점·빛 방향을 쓴다. 사람 NPC의 등신 비율은 아직 확정하지 않았다. 같은 그림체가 같은 종족이나 같은 등신을 뜻하지 않는다.
- **형태:** 굵고 단순한 실루엣. 작은 화면에서도 무엇인지 바로 알아볼 수 있어야 한다.
- **선과 명암:** 진한 색 테두리, 빛은 왼쪽 위에서. 명암은 2~3단계로 제한한다.
- **시점:** 정면을 약간 위에서 내려다보는 2D 탑다운. 아이소메트릭이 아니다.
- **색:** 공용 팔레트 하나를 모든 에셋이 함께 쓴다. 지역마다 강조색만 다르게 한다. 고려는 기와 남색, 청자 녹색, 볏짚 금색이다.

### Figma 시안에서 확인한 점 (2026-10-24)

- **디자인 레퍼런스:** 채도가 높은 귀여운 탑다운 마을. 길·풀·물 경계가 조립용 타일로 자연스럽게 이어진다.
- **고려 캐릭터 시안:** 너구리·토끼·고양이·수달 동물 캐릭터와 사람 캐릭터. 시안 문구는 48×48px, PPU 32를 **임시 기준**으로 적었다.
- **고려 물체·풍경 시안:** 짐, 나무, 꽃, 초가와 기와집, 성문과 성벽 모듈. 성벽은 "연결 가능한 모듈로" 만들라고 적혀 있다. 이 문서의 조립용 에셋 규칙과 같은 방향이다.
- **팀 간 차이:** 베네치아·아라비아 에셋은 단순하고 덩어리가 큰 도트다. 고려 물체 시안은 더 세밀하게 칠해져 있다. 팀 공통 기준을 정해야 한다(결정 대기 D3).

## 2. 기술 기준 (D2 확정 2026-10-24)

**원칙: 큼직한 도트 느낌을 살리고, 모든 에셋이 같은 도트 크기를 쓴다.** 화면에서 픽셀 한 개의 크기가 캐릭터·건물·나무·타일·아이콘 모두 같아야 한다. 고해상도 그림을 섞거나 일부만 더 잘게 그리지 않는다. 이것이 통일성의 기준이다.

| 항목 | 기준 |
|---|---|
| 타일 크기 / PPU | **16px / 16** (지금과 같음) |
| 플레이어 캐릭터 (2.5등신 동물) | **16×32** 기본. 넓은 귀·꼬리 때문에 필요하면 **24×32**까지 |
| 사람 NPC | 같은 도트 크기(PPU 16). 키는 플레이어와 같은 화면에 놓고 은샘 검토로 정함 |
| 건물·나무·소품 | 16px 격자 단위 크기(예: 32×48, 48×64). 같은 도트 크기 |
| 필터 / 압축 | Point / 없음 |
| 카메라 기준 해상도 | 480×270 (가로 30칸 × 세로 17칸 정도) |
| 픽셀 확대 | 정수 배율만. 회전·늘이기·부드러운 축소 금지 |

- 세계 면적(칸 수), 맵, 이동 속도는 바뀌지 않는다.
- 기존 캐릭터(16×24)는 C1에서 16×32로 바꾼다. `CharacterAnimator`·`MapJsonBuilder.LoadFrames`의 프레임 크기·발밑 기준을 함께 맞춘다.
- Figma 시안의 48×48 캐릭터는 모양 참고용이다. 크기를 그대로 쓰지 않는다.
- A5 정리 도구와 A2 검사기 프로파일은 칸당 16px을 쓴다. 팔레트는 D3에서 정한다.

## 2-1. 팀 공통 기준 (D3 방향 확정 2026-10-24)

팀원은 각자 방식으로 작업한다. 회의나 긴 문서 대신 **같은 파일 몇 개를 같이 쓰면 저절로 맞춰지게** 한다.

1. **꼭 맞출 것은 네 가지만:** 타일 16px(2절), 공통 팔레트, 외곽선 규칙, 시점·빛 방향. 건물 모양·옷·문화 디자인은 지역 담당이 자유롭게 정한다.
2. **공통 팔레트 + 지역 강조색:** 모든 지역이 같은 기본 색(약 32색)을 쓰고, 지역마다 강조색을 몇 개(약 8색)만 더한다. 팔레트 파일(Aseprite에서 불러올 수 있는 형식)을 저장소에 둔다.
3. **크기 기준 그림 한 장:** 플레이어·사람 NPC·집·나무·바닥 타일을 실제 크기로 나란히 놓은 PNG. 팀원은 자기 그림을 옆에 놓아 크기와 도트 밀도를 확인한다.
4. **중앙 대륙 지형은 한 세트를 같이 쓴다:** 풀·흙·물·길·해안 같은 조립용 지형(A4)을 중앙 대륙 공통 세트로 공개해 네 구역 경계가 이어지게 한다. 지역 건물·소품만 각자 만든다.
5. **검사 명령 하나:** A2 검사기 프로파일에 16px·공통 팔레트를 넣어, 팀원도 명령 한 줄로 확인할 수 있게 한다.

진행: Claude가 아트 시험 샘플과 함께 공통 팔레트 + 고려 강조색, 크기 기준 그림을 만든다 → 은샘이 **화면으로 보고** 승인 → 은샘이 팀에 공유.

## 3. 에셋 등록과 사용

**사용자 검토는 필수다.** 새로 제작하거나 교체하는 아트는 은샘에게 비교 이미지 또는 시험 화면으로 보여 준다. 목록에 제작 중·사용자 검토 대기·승인·수정 요청을 구분하고, 승인 전 결과를 본편 적용 완료로 처리하지 않는다. 기준 샘플 승인만으로 이후 모든 아트가 자동 승인되는 것은 아니다.

1. **원본:** Aseprite 원본(`.aseprite`)과 내보낸 PNG를 함께 둔다. 위치는 `Assets/PocketCaravan/Art/<지역>/<종류>/`.
2. **목록(manifest):** 에셋마다 아이디, 용도, 크기(칸), 종류(단일 개체 / 조립용 세트), 허용 배치(예: 물가만, 길 위 금지)를 적는다. 형식은 작업 A2에서 정한다.
3. **맵 생성기:** 목록에 있는 에셋만, 적힌 용도로만 놓는다. 좌표로 시트를 잘라 쓰는 코드는 쓰지 않는다.
4. **검사:** 검사기가 목록에 없는 에셋, 일부만 놓인 개체, 용도와 다른 배치, 조립 조각 누락을 찾아 실패시킨다.
5. **출처:** AI로 만든 초안, 외부 팩, 직접 그린 것을 목록에 구분해서 적는다.

### 조립용 에셋 세트

| 세트 | 필요한 조각 |
|---|---|
| 물(호수·바다) | 가운데, 가장자리 4, 바깥 모서리 4, 안쪽 모서리 4, 물결 애니메이션 |
| 강 | 위 세트 + 폭 2~3칸 직선·굽이·하구 |
| 해안 | 모래/풀 ↔ 물 경계 전체. 해안선은 최소 5칸 폭의 큰 굴곡만 쓰므로(세계 배치 해안선 v2) 1~2칸짜리 돌기용 조각은 만들지 않는다 |
| 길 | 흙길·큰길·돌길 각각 가운데·가장자리·모서리·교차 |
| 풀/흙/밭 경계 | 경계 전체 세트 |
| 성벽 | 직선, 모서리, 끝, 문(열림/닫힘) |
| 다리·나루 | 시작, 가운데, 끝 |
| 산맥·절벽 | 가장자리, 모서리, 끝. 지나갈 수 없는 땅을 자연스럽게 막는 용도 |

## 4. 제작 방법

- **Aseprite:** 최종 도트는 실제 해상도로 여기서 다듬는다. 은샘 맥에 정식 구매판(dmg 설치)이 있다. 스팀판은 필요 없다.
  - **원본은 `.aseprite`로 남긴다**(레이어·팔레트·애니메이션 포함). 게임용 PNG는 원본에서 명령으로 내보낸다. 은샘이 원본을 열어 바로 손볼 수 있어야 한다. A2 목록의 `source.path`는 이 원본을 가리킨다.
  - **에이전트 사용:** Aseprite 명령줄 실행 + Lua 스크립트(`aseprite -b --script …`)로 그리기·팔레트 적용·내보내기를 한다. Codex는 맥에서 직접 실행한다. Claude는 Claude 데스크톱 앱에 등록한 Aseprite MCP를 거쳐 쓴다(A6).
  - 공통 팔레트는 Aseprite에서 불러올 수 있는 팔레트 파일로 저장소에 둔다(2-1절).
- **AI 이미지:** 써도 된다(2026-10-24 사용자 결정). 기준은 "스타일에 맞고 녹아드는가" 하나다. 다만 생성 이미지를 부드럽게 축소해 넣는 방식(옛 `goryeo_art.py`)은 흐릿하고 색이 섞여 녹아들지 않으므로 쓰지 않는다. 아래 정리 과정을 거친다.
  1. **생성:** 흰/단색 배경, 한 개체, 정해진 시점·빛 방향, 기준 이미지(A1 승인본)를 참고로 넣어 생성한다.
  2. **격자 맞추기:** 생성 이미지의 도트 격자를 찾아 실제 해상도(타일 16px, 플레이어 16×32 등, 2절 기준)로 **최근접 방식**으로 줄인다. 부드러운 축소 금지.
  3. **팔레트 고정:** 공통 팔레트 색으로만 다시 칠한다. 중간색·반투명 픽셀을 없앤다(알파는 0 또는 255).
  4. **손질:** 외곽선 두께·색, 빛 방향, 눈·얼굴 같은 작은 부분을 실제 해상도에서 직접 고친다(Claude가 코드로, 또는 은샘이 Aseprite에서).
  5. **비교 검사:** 이미 승인된 에셋 옆에 나란히 놓아 크기·도트 밀도·색이 튀지 않는지 본다. 에셋 검사기(A2)로 팔레트·알파·크기를 자동 확인한다.
  6. **등록:** 목록에 출처를 `AI 생성 + 정리`로 적는다.
  - 애니메이션(걷기 등)은 정리한 기본 자세에서 프레임을 직접 만든다. 프레임마다 따로 생성하면 모양이 흔들린다.
- **Claude:** 에셋 제작(AI 생성 + 위 정리 과정, 또는 코드로 도트 생성)과 스타일 검사를 맡는다. **Codex:** 목록, 검사기, 맵 생성을 맡는다. 도트를 코드로 생성하는 방식(현재 `chars.py`)은 새 스타일 기준을 통과할 때만 계속 쓴다.

## 5. 현재 에셋 진단 (2026-10-24, 코드 확인)

지금 게임 화면에는 그림 출처 세 가지가 섞여 있어 스타일이 통일되지 않는다.

| 출처 | 쓰이는 곳 | 코드 |
|---|---|---|
| Ninja Adventure 무료 팩(CC0) | 땅·물·길 타일, 일부 나무·집·소품 | `Tools/MapGen/tiles.py` (`STAMPS`, `K()`) |
| AI로 만든 고해상도 시트를 줄이고 색 수를 줄인 것 | 고려 건물, 마을 소품, 마당 돌바닥, 숲 | `Tools/MapGen/goryeo_art.py` (Architecture, VillageDetails, CourtyardStone, Woodland, PineAncient) |
| 코드로 그린 도트 | 플레이어·NPC 16×24 | `Tools/ArtGen/chars.py`, `items.py` |

새 규칙에 어긋나거나 의심되는 곳. 작업 A3에서 하나씩 확인한다.

- 현재 동물 NPC(곰·개·여우·토끼·너구리 등)는 "플레이어는 2.5등신 동물, NPC는 사람" 기준과 다르다. C1에서 사람 NPC로 교체한다. 이번 문서 정리는 실제 에셋 교체 완료를 뜻하지 않는다.

- `goryeo_art.py`: 건축·소품 분기는 LANCZOS 축소 후 28색(돌바닥은 12색)으로 줄인다. `woodland` 계열은 최근접 축소와 18색 양자화를 쓴다. 어느 방식도 공통 팔레트나 미술 승인을 자동 보장하지 않으므로 에셋별로 판정한다.
- `goryeo_art.py`의 `RECTS`, `DETAIL_RECTS`, `WOODLAND_COLUMNS/ROWS`: 시트를 좌표 사각형으로 잘라 쓴다.
- `tiles.py`의 `STAMPS`: Ninja 시트에서 좌표로 사각형을 잘라 쓴다(`pinebig`, `roundbig`, `hall`, `bigtree`, `plot` 등). 원래 개체 경계와 맞는지 확인하지 않았다. `FIELD`는 언덕 조각을 밭처럼 쓴다.
- `STAMPS`의 `"slate"` 색 바꾸기와 `goryeo_art.tone()`: 맵을 만드는 중에 색을 즉석으로 바꾼다.
- `CourtyardStone.png`: 큰 텍스처를 64px 반복 타일로 줄여 쓴다.
- 잔물결: Ninja 프레임을 가공해 쓴다.
- `tiles.py`의 `forest_border()` / `stamp_clipped()`: 나무를 한 그루 단위로만 놓도록 고쳐져 있다. 유지한다.

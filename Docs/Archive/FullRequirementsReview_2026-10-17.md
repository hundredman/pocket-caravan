# 10월17일 전체 기획 재대조와 누락 교정

> **날짜 기준 검토 기록:** 본문의 구현 판정·검사·미완료는 당시 시점이다. 이후 구현 상태는 [진행표](DevelopmentStatus.md)에서 확인한다. 고증/요구/검사 근거는 기록으로 보존한다.

> 현재 구현/검사는 [진행표](DevelopmentStatus.md), 문서 우선순위는 [문서 안내](../README.md)를 따른다.

기준: 2026-10-17. 이번 검토는 원본 PDF 15쪽, 공통 시나리오 DOCX 본문/회의 메모, 아트 참고 PDF, 이 대화의 후속 결정, 저장소 문서·본편 코드·데이터·발표 파일을 대조했다. 아래 구현 판정은 **정적 코드/데이터 확인**이며 새 Unity Play·멀티·부하·사용자 재미 검증 결과가 아니다. 타 지역은 아래 북유럽 브랜치의 제한적 정적 확인 외에 전체 플레이/통합 검사를 하지 않았다.

## 1. 먼저 바로잡은 내용

이전 문서 동기화는 전체 요구를 충분히 반영하지 못했다. 특히 다음은 사용자 지시가 없는데도 미정/장기 범위로 축소되거나 실행 항목에서 빠졌다.

1. **스타팅 지역은 수도 1개 + 수도 외 최소 마을 4개.** 고려는 기존 네 씬의 품질 개선만으로 완료할 수 없다. 길/다리는 마을 수에 넣지 않는다.
2. **이미 발전한 지역에서 시작하고 마을별 등급이 있다.** 촌락 개경을 거래로 수도로 키우는 이전 서사는 최신 기준이 아니다.
3. **마을 이동은 자유, 시설·고급 거래는 마을 등급과 개인 신용으로 차등.** 기존 고급 배달 의뢰의 신용 제한과 수레의 최소 등급만으로 충족되지 않는다.
4. 지역당 동물 종·색상 변형, 실제 지명, 돈·신용·명성, 텍스트 채팅 우선도 회의에 있으나 작업 카드로 충분히 연결하지 않았다. 확정된 방향과 남은 세부 규칙을 분리했다.
5. Q1~Q7는 회의 초안이다. 기존 T1~T4/S1~S3가 같은 내용인 것처럼 취급하면 안 된다. Q3 낙하·Q7 마을 승급/관문은 후속 결정에 맞춰 고쳐야 한다.
6. `검토 우선/바로 시행하지 않음`과 `마을 하나 걷기만`은 과거 검토/3D 시안의 범위였다. 사용자가 재개한 본편 2D 고려 개발을 막는 현재 지시로 사용하면 안 된다.
7. 발표 8쪽·12쪽·18쪽과 대본의 ‘마을 네 개는 장기 계획/이번 개수 미정’ 표현을 최신 제작 범위로 교정한다. 현재 네 맵과 목표 다섯 거점을 구분한다.

## 4. 고려에서 먼저 해야 할 묶음

1. **GY-04/05:** 수도+네 마을 구성표, 실제 지명 후보·고증/각색·기본 등급·시설·생산/소비·연결·ID를 작성하고 기존 세 TownData와 대응한다.
2. **FAC-01:** 등급과 신용을 모두 사용하는 시설/고급 거래 정책을 데이터로 정의하고 잠김/해금/재접속 시나리오를 설계한다. 첫 거래와 무자본 재기는 열어 둔다.
3. **MV-01/02:** 낙하 제거와 저장 이주. GY-06의 거리/노면/적재 경로 비교와 연결한다.
4. **GY-04/06:** 부족한 마을 최소2곳과 연결 구역을 만든다. 다섯 거점의 최소 시장/게시판·시설 접근·생산/소비·왕복을 먼저 이어 본다. 한 거점만 장식 완료하고 끝내지 않는다.
5. **SCN-01/ORG-01:** 최신 지역/시설을 반영해 짧은 공통 시나리오와 고려 정보 특화를 연결한다. 기본 교역과 독립 시험장은 퀘스트 없이 확인 가능하게 유지한다.
6. **GY-01/02, QA-REG/FAC:** 저신용/해금 직전/직후, 등짐/손수레, 다섯 거점, 왕복 손익·반복 피로·통행/지도/대사를 검사한 뒤 팀에 보여 준다. 온라인 담당은 같은 시설 판정을 서버로 연결한다.

상세 작업 계약은 [고려 지역 제작 명세](../Reference/GoryeoRegionSpec.md), 실행 ID는 [작업 목록](../Reference/ImplementationBacklog.md), 달력은 [일정](../Reference/DeliveryPlan.md)을 따른다. 마감이 어렵다는 이유로 마을 수를 조용히 줄이지 않는다. 지명/등급 수치/시설별 세부 포함 범위가 비어 있으면 빈 항목과 제안 상태를 공개하고, 전체 지역 요구 자체를 미정으로 되돌리지 않는다.

## 5. 검토의 한계와 근거 보존

원본 첨부는 변경하지 않았다. 추출 텍스트·해시·코드/에셋 정적 재고·슬라이드 QA는 로컬 `output/full-requirements-audit-2026-10-17/`에 남긴다. 아트 참고 이미지/원본 시설표는 시각 확인과 텍스트를 함께 사용한다. 기존 자동 검사 수는 과거 기능의 검사 범위이며 이번 새 목표 충족의 증거로 재사용하지 않는다. 모든 버그나 다른 팀 브랜치의 누락이 없음을 보증하지 않는다.

## 6. 새로 확인한 북유럽 브랜치 — 통합 참고

`origin/feature/north`의 확인 시점 HEAD는 `c51b6e6`이다. 공통 파일을 덮어쓰지 않고 북유럽 전용 파일을 추가한 작업을 정적으로 확인했다. 이 브랜치는 이번 문서 교정에서 병합/수정하지 않았다.

- 등록4맵·TownData3개(비르카/사냥꾼/나루), 순록 외형·Q1~Q7 전용 콘텐츠가 있다. ‘타지역 미개발’로 기록하면 안 된다. 이 브랜치도 수도/마을 최소4·시설 기준 충족 여부는 추가 작업/검증이 필요하다.
- Q3은 주행 낙하에 의존하지 않는 정직 시험으로 수정돼 있다. 이를 공용 PlayerController의 낙하 제거 완료로 소개하면 안 된다. 공통 본편 낙하는 아직 남아 있다.
- NorthQuestDirector의 Q4/Q6가 로컬 시장을 직접 변경하고 트리거 시간이 메모리에 있으므로, SCN-01/SIM-01/SAVE-02에서 서버 단일 실행·1회성/저장/재접속을 맞춰야 한다. 현재 코드가 온라인 중복 안전하다는 뜻이 아니다.
- NorthDevStart의 출신/외형 교체는 에디터 시험 전용이다. ORG-01의 정식 출신 선택·저장·지역 이동에도 유지되는 외형을 대신하지 않는다.

이 사실은 고려 제작 범위를 줄이는 근거가 아니다. 공통 퀘스트/시설 규칙을 정할 때 이미 제작된 북유럽 콘텐츠를 재사용하고, 지역 담당의 작업을 통째로 덮어쓰지 않기 위한 참고다.

- 거점 기본 등급 `settlementTier`와 기존 시장의 거래량 성장 `MarketState.Level`을 구분했다. 다른 지역은 새 필드를 쓰지 않으면 기존 startLevel로 호환한다.
- 장터 → **마을 시설**에서 쉼터·길 안내소·객주 보관소 이용/잠김 이유를 확인한다. 신용 판정은 개인별이다. 기본 장터 매매/방문을 막지 않는다.
- 보관소는 일반 상품을 마을별/캐릭터별로 맡기고 찾으며 수량/매입 원가를 보존한다. 의뢰 물품·창고 한도/출고 적재 초과를 거절한다. 다른 마을에서 원격 출고할 수 없다.
- 주행 낙하 생성과 누적 흔들림/안정화 정차는 제거했다. **사용자 후속 확인에 따라 흔들림 연출은 유지**한다. 노면·적재량·속도에 반응해 짐/수레가 흔들리며, 카메라·충돌/이동 위치·화물 수량을 흔들지 않는다. 멈추면 연출도 멈춘다. 속도는 기존 노면·적재 감속 계산이 담당한다.
- 기존 낙하물은 불러올 때 수량/원가/활성 의뢰를 복원한다. 적재 초과도 재산을 보존하며, 알 수 없는 ID/종료 의뢰 기록은 지우지 않고 보류한다. 새 저장에는 남은 미해결 기록만 남긴다.
- 저장은 버전2의 추가 보관 필드를 쓰고 버전1을 읽는다. 임시 파일 완성→원자 교체·이전 .bak 보존, 읽기 실패/미지원 미래 버전은 원본 자동 덮어쓰기를 차단한다. 모든 손상 파일·사라진 씬/ID의 완전 복구까지 완료한 것은 아니다.

## 4. 확인 근거

- 맵 회귀106개, 경로 선택4개, 등록 출구10개, 통합 도구 단위검사12개 통과.
- Unity `고려 거점·시설·저장 이주 검사`25개, 기존 `로컬 의뢰·회수·저장 검사`30개 통과. 기존 회수 검사는 구 레코드 호환 방어이며 신규 주행 낙하의 복원이 아니다.
- Play: 신용0 시설 잠금, 신용3 개경 보관 입고, 새 두 마을 로딩/걷기, 장단↔닥목 실제 출구 왕복 화물2개/원가9 보존.
- 60초 분량 운반 Tick과 이전 DropRandomCargo API 호출에서 물량 보존. 적재 감속, 거친 노면/이동 시 큰 시각 흔들림·정지 시0을 확인했다. 실제 손맛/재미의 사용자 승인은 별도다.
- UI 캡처·순수 검사·저장 시험 파일: 로컬 `output/goryeo-development-2026-10-17/`. 본편 사용자 저장에 시험 재화/신용을 넣지 않도록 비시작 씬에서 검사했다.

### 요구 추적의 자동 검사

`Tools/Integration/test_goryeo_contract.py`는 실제 등록된 장터의 독립 townId를 세어 수도 외 네 마을과 공용 DB 참조를 확인하고, 시설 등급/개인 신용/ID 데이터를 검사한다. 기존 GitHub Actions의 unittest discover에 포함된다. 이 검사는 시설의 서버 권한/아트/재미를 보증하지 않으며 Unity25개·실제 Play 검증과 함께 사용한다.

### 이번 빌드 결과

Mac 오류0/경고4, Windows 오류0/경고18으로 빌드 성공. Windows는 비지원 레이 트레이싱 셰이더 경고가 있으며 2D 빌드는 완료됐다. Mac은 미서명/미공증이고 실제 다른 Windows 장비 실행은 미검증이다. [커밋에 보존한 검증 요약](Validation/Goryeo-2026-10-17.json)을 함께 확인한다. 빌드 보고서와 실제 플레이 검증을 구분한다.

# 수원·농경 마을·지도/UI 수정 재개 메모

**2026-10-30 사용자 사용량 제한으로 중단. 이번에는 조사만 했고 구현/에셋 제작/본편 변경/Unity 검사하지 않았다.** 직전 구현 커밋은 `5ed274854`(건물·배 본편 교체, 자연 배치 검토). 이 메모와 지시만 로컬 커밋한다.

## 새 사용자 지시

1. 처음 강이 시작하는 수원지 모두를 산악 지형으로 표현. 필요하면 에셋 추가 가능.
2. 고려 남서쪽 마을 근처에 논을 더해 풍요로운 마을 느낌. 현재 좌표상 장단이 해당하는 것으로 보이며 마을/길 위치와 함께 확인한다.
3. 지도 수정의 구체 뜻은 **지역·마을 이름이 일부만 표시되는 것처럼 보인다**는 후속 답변이다. 전체 지형을 다시 설계하라는 뜻으로 확대하지 않는다.
4. 번지고 깔끔하지 않은 UI를 편안하고 읽기 쉽게 개선. 다른 게임 UI·방법론 참고를 허용/요청했다.
5. 그림 변경은 묶음 전후/게임 화면 검토. 기존 ID·저장 보존, 원본 생성, 최신 main 합침, 로컬 커밋만이라는 규칙 유지. 사용자가 다시 진행을 요청하기 전 작업 재개하지 않는다.

## 확인한 사실

- 수원 검출: `m1_tiles_preview.py`의 source 부분(525행 부근)이 강별 높은 지점을 고르고 숲을 덮는다. 현재 생성 보고 좌표는 세계 타일 기준 `(66,-48)`, `(226,-62)`, `(191,-48)`, `(117,-9)` 네 곳이다. 마지막은 검토본 큰 폭포/호수 유입 수원과 대응한다. 이를 바탕으로 각 강의 실제 상류/흐름을 먼저 검증한다.
- `nature_layout.json`에는 송악 짧은 능선, 큰 폭포/하류, 논2구획만 있다. 나머지 수원은 암산으로 바뀌지 않았다. live 스냅샷은 없으며 자연 배치는 아직 previewOnly다.
- 기존 큰 폭포는 유지하고 출입구·도착 위치를 조정하는 선택을 이미 받았다. 그 결정을 다른 폭포로 축소하는 승인으로 바꾸지 않는다.
- 서쪽 수원 `(66,-48)` 바로 북쪽은 담당 경계에 가깝다. 12×12칸 산을 수원 중심에 놓으면 담당 범위 밖을 침범한다. 8~10×10칸을 `(66,-58)`에 놓는 사각형은 담당 범위 안이지만 수원 출구가 맨 왼쪽이 된다. 큰 모듈을 억지로 자르거나 회전하지 말고, 실제 방향에 맞는 별도 소형 원본/조립 모듈이 필요한지 판단한다. 아직 에셋을 만들거나 이 방식을 확정하지 않았다.
- 원래 논 위치는 `(211,16)`, `(217,29)`의192×128px 전체 구획. 장단 광장 중심은 대략 세계 `(202,43.5)`라 기존 논이 마을 북동쪽에 치우쳤다. 마을 서/남쪽의 길·강·기능물/출입구를 피한 추가 구획을 검토한다. 초원 위 논·길이 밭 사이를 지나가는 기존 사용자 선호를 유지한다.
- **지도 이름 누락 원인 확인:** `WorldMapUI.cs` 약149행의 `if(!regional && ...) continue`가 전체 지도에서 일부 맵 이름만 의도적으로 표시한다. 두 atlas JSON의 annotations도 비어 있어 쉼터를 별도 마을 이름으로 표시하지 않는다. 등록13구역과 실제 마을/쉼터 목록을 대조해 빠짐·겹침·잘림을 확인할 필요가 있다.
- **번짐 원인 후보 확인:** 공용 `Core/UIState.cs`의 UIStyle은 가상 높이360, Scale=화면 높이/360이다. 480×270에서는0.75배, 11px/9px 글자가 각각8.25/6.75px가 된다. 갈무리 폰트 importer renderingMode는0. 소수 배율/작은 글씨/그림자와 이름표 겹침을 실제 캡처로 분리 확인해야 한다. 원인 전체가 확정된 것은 아니다.
- UIStyle은 다른 문명도 사용한다. 가상 높이를 무작정270으로 바꾸면 높이330짜리 기존 창과 다른 문명 UI가 잘릴 수 있다. 다른 지역 화면/입력 호환을 포함한 검사 계획이 필요하다.
- 직전 실제 Play에는 마을/방향 이름표 여러 개가 지붕 위에 겹쳤다. 이름표 구현 위치를 추가 추적해야 한다. `WorldLabels`는 NPC/상호작용 이름·퀘스트 안내를 그린다.

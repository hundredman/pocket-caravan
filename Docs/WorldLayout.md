# 세계 배치

정리: 2026-10-24. 원칙은 [방향 기준](Direction.md) 3~4절이다.
**배치는 검토안 단계다. 사용자가 승인하기 전에는 맵·씬·생성기에 반영하지 않는다.**

## 1. 면적과 담당

| 구역 | 면적(칸) | 담당 |
|---|---:|---|
| 중앙 대륙 전체 | 100,000 | 4명이 1/4씩 |
| └ 중앙 대륙 동쪽 | 25,000 | 은샘 |
| 고려 (동) | 20,000 | 은샘 |
| 북유럽 (북) | 20,000 | 기우 |
| 베네치아 (서) | 20,000 | 윤채 |
| 아라비아 (남) | 20,000 | 은인 |

1칸 = Unity Grid 1칸. 은샘 담당 합계는 45,000칸이다. 바다를 면적에 넣을지는 검토 질문 5번이다.

## 2. 좌표 약속 (검토안 기준)

- 중앙 대륙 중심을 (0, 0)으로 둔다. x는 동쪽, y는 남쪽이 +다.
- 검토안은 중앙 대륙을 넓이 100,000칸의 원(반지름 약 178칸)으로 단순화했다. 실제 해안선 모양은 팀이 정한다.
- 방향은 시계로 부른다. 12시가 북, 3시가 동이다.
- 중앙 대륙 동쪽 담당은 **1시 30분~4시 30분**(90°)으로 잡았다. 원이면 정확히 25,000칸이다. 사용자 지시는 "대략 1~2시부터 4~5시"이므로, 경계 각도는 이웃 담당자와 합의해 정한다(결정 대기 D4).
- 이 좌표는 땅의 위치(지리)다. 시세 계산에 쓰는 경제 좌표(`TownData.worldCoord`)와 따로 관리한다.

## 3. 배치안 B (현재 검토안)

그림: [Figma `고려 배치 검토안` 페이지](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=131-2)의 `고려 배치 검토안 B` 프레임
계산 원본: `Tools/WorldLayout/layout_proposal_b.py`. 실행하면 맵별 칸 수와 윤곽 좌표가 나온다.

### 맵 나누기 원칙

- 맵(타일맵) 하나 = 마을이나 도시 하나와 그 주변 땅. 맵마다 크기가 다르다.
- 구역 경계선이 곧 맵 경계다. 이웃 맵과는 길 하나가 아니라 걸을 수 있는 경계 전체로 이어진다.
- 고려 안에는 이동 전용 맵이 없다. 마을 맵끼리 바로 맞닿는다.
- 중앙 대륙에는 마을 맵 사이에 이동 구역 맵을 둔다. 여기서 길 위 사건이 일어난다.
- 모든 땅을 실제로 만든다. 지나가지 못하는 곳은 산맥·절벽으로 막는다.

### 고려 (20,000칸)

| 맵 | 위치 | 면적(칸) | 성격 |
|---|---|---:|---|
| 개경 | 중서부 강변 평야 | 5,500 | 수도. 궁성·시전·객주. 뒤(북)에 송악 산. 서문이 중앙 대륙 쪽으로 열림 |
| 송악 | 북 | 3,500 | 산록 마을, 소나무. 북쪽은 산맥으로 막힘 |
| 나루 | 남 | 3,000 | 강 하구 포구. **튜토리얼 시작 마을.** 개경과 바로 맞닿음 |
| 장단 | 동남 | 4,000 | 넓은 들판 |
| 닥목 | 동북 | 4,000 | 숲 계곡, 한지 작업장. 동해안은 산으로 막힘. 강이 시작되는 곳 |

- 강은 닥목 계곡에서 시작해 장단과 개경 사이를 지나 남쪽 나루 하구로 빠진다.
- 개경은 수도답게 가장 크다. 시작 마을 나루에서 바로 걸어 들어갈 수 있다.
- 바다는 고려의 북·동·남 바깥에 있다. 서쪽 면 약 123칸이 중앙 대륙과 맞붙는다.
- 진행: 나루(시작) → 개경(수도) → 서문 → 동문 마을(중앙 대륙).

### 중앙 대륙 동쪽 (25,000칸)

| 맵 | 종류 | 면적(칸) | 성격 |
|---|---|---:|---|
| 동문 마을 | 마을 | 3,000 | 고려와 가장 가까운 중앙 마을. 개경 서문과 길로 이어짐 |
| 북동 마을 | 마을 | 3,000 | 교역. 장터 후보. 북쪽(북유럽 구역)과 중앙으로 길이 이어짐 |
| 남동 마을 | 마을 | 3,000 | 교역. 장터 후보. 남쪽(아라비아 구역)과 중앙으로 길이 이어짐 |
| 북동 길 | 이동 구역 | 5,300 | 동문↔북동 사이. 길 위 사건 |
| 남동 길 | 이동 구역 | 5,300 | 동문↔남동 사이. 길 위 사건 |
| 내륙 길 | 이동 구역 | 5,400 | 대륙 중심 쪽. 다른 구역과 이어짐 |

- 마을 간격: 동문↔북동 약 90칸, 동문↔남동 약 89칸, 북동↔남동 약 126칸.
- 다른 구역의 마을 위치와 간격은 각 담당자가 정한다. 공통 간격 규칙은 팀이 합의한다(결정 대기 D7).

### 사용자에게 검토받을 것

1. 개경 위치: 중서부 강변. 서문이 대륙 쪽 동문 마을과 바로 이어져도 되는지
2. 마을 방위: 북 송악 / 남 나루(하구, 시작) / 동남 장단 / 동북 닥목
3. 맵 크기: 개경 5,500 · 장단 4,000 · 닥목 4,000 · 송악 3,500 · 나루 3,000
4. 중앙 동쪽: 마을 3곳(각 3,000) + 이동 구역 3곳, 마을 간격 약 90칸
5. 고려 20,000칸은 땅(산·강 포함)만 세고 바깥 바다는 빼기

검토 결과는 이 절과 [방향 기준](Direction.md)에 반영하고, [작업 계획](Plan.md)의 D1 상태를 바꾼다.

### 이전 검토안 A (대체됨)

개경을 고려 한가운데에 두고 네 마을이 사방을 감싸는 안이었다. 사용자 피드백(개경을 한쪽으로, 마을 단위 맵)으로 B로 대체했다. 그림은 같은 Figma 페이지에, 계산은 `Tools/WorldLayout/layout_proposal_a.py`에 남겨 둔다.

## 4. 승인 후 구현할 때의 원칙

- **원본 하나:** 세계 배치 원본 파일(좌표·면적·맵 경계)을 하나 두고, 지형 생성기·지도(M)·씬 등록이 모두 그 파일을 읽는다. 지도에만 지형을 덧그리지 않는다.
- **맵 경계 이동:** 경계 전체가 이어진다. 마을 이동은 페이드로 연출한다(10/23 회의).
- **기존 시스템 보존:** 시장·상품·퀘스트·NPC·시설 아이디와 저장 데이터는 유지한다. 위치가 바뀐 저장은 이주표(`Resources/GoryeoLayout.json` 방식)로 옮긴다.
- **면적 검사:** 생성 결과의 칸 수가 3절 표와 맞는지 자동 검사한다.

## 5. 현재 구현과의 차이 (2026-10-24)

현재 맵(고려 5씬 + 중앙 6씬)은 새 방향과 다르다. 다시 만든다.

- 고려 다섯 권역이 길을 따라 늘어서 있다. 수도 위치에 지리적 근거가 없다.
- 고려가 중앙 대륙과 좁은 땅으로만 연결되어 따로 떨어진 직사각형 섬처럼 보인다.
- 중앙 동쪽 6맵은 직사각형을 이어 붙인 형태다. 대륙 전체에서의 위치(1~2시~4~5시)를 기준으로 만들지 않았고, 마을과 이동 구역의 구분이 없다.

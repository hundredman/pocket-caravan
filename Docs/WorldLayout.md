# 세계 배치

정리: 2026-10-24. 원칙은 [방향 기준](Direction.md) 3~4절이다.
**배치안 D를 확정했다(2026-10-24).** 다만 실제 해안선 모양은 아래 자연 해안선 초안의 검토가 끝난 뒤 구현한다(작업 계획 D9).

## 1. 면적과 담당

| 구역 | 면적(칸) | 담당 |
|---|---:|---|
| 중앙 대륙 전체 | 100,000 | 4명이 1/4씩 |
| └ 중앙 대륙 동쪽 | 25,000 | 은샘 |
| 고려 (동) | 20,000 | 은샘 |
| 북유럽 (북) | 20,000 | 기우 |
| 베네치아 (서) | 20,000 | 윤채 |
| 아라비아 (남) | 20,000 | 은인 |

- 1칸 = Unity Grid 1칸. 은샘 담당 합계는 45,000칸이다.
- **면적 = 육지 + 앞바다.** 검토안은 해안에서 10칸까지를 앞바다로 잡았다. 앞바다는 그 지역 맵에 실제로 만든다.
- 먼 바다는 면적에 넣지 않는다. 지도(M)에만 그린다.

## 2. 좌표 약속 (검토안 기준)

- 중앙 대륙 중심을 (0, 0)으로 둔다. x는 동쪽, y는 남쪽이 +다.
- 검토안은 중앙 대륙 육지를 원(반지름 약 170칸)으로 단순화했다. 육지 90,504칸 + 앞바다 9,506칸 = 100,010칸. 실제 해안선 모양은 팀이 정한다.
- 방향은 시계로 부른다. 12시가 북, 3시가 동이다.
- 중앙 대륙 동쪽 담당은 25,000칸이 되도록 **약 1시 25분~4시 35분**으로 잡았다. 사용자 지시는 "대략 1~2시부터 4~5시"이므로 경계 각도는 이웃 담당자와 합의해 정한다(결정 대기 D4).
- 이 좌표는 땅의 위치(지리)다. 시세 계산에 쓰는 경제 좌표(`TownData.worldCoord`)와 따로 관리한다.

## 3. 배치안 D (확정)

그림: [Figma `고려 배치 검토안` 페이지](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=131-2)의 `고려 배치 검토안 D` 프레임
계산 원본: `Tools/WorldLayout/layout_proposal_d.py`(면적)와 `layout_proposal_d_terrain.py`(강·산·길·메인 퀘스트, 강 흐름 검사).

### 맵 나누기 원칙

- 맵(타일맵) 하나 = 마을이나 도시 하나와 그 주변 땅·앞바다. 맵마다 크기가 다르다.
- 구역 경계선이 곧 맵 경계다. 이웃 맵과는 길 하나가 아니라 걸을 수 있는 경계 전체로 이어진다.
- 고려 안에는 이동 전용 맵이 없다. 마을 맵끼리 바로 맞닿는다.
- 중앙 대륙에는 마을 맵 사이에 이동 구역 맵을 둔다. 여기서 길 위 사건이 일어난다.
- 모든 땅을 실제로 만든다. 지나가지 못하는 곳은 산맥·절벽으로 막는다.

### 고려 (20,000칸 = 육지 16,352 + 앞바다 3,648)

| 맵 | 위치 | 면적(칸) | 성격 |
|---|---|---:|---|
| 개경 | 동해안 | 5,000 | 수도. 개경 강 하구의 항구 도시. 궁성·시전·객주. 중앙 대륙과 닿지 않음 |
| 장단 | 남 | 4,500 | **곡창지대.** 큰 강이 논 사이를 흐른다. 남해안 |
| 나루 | 남동 | 3,500 | 큰 강 하구의 나루터 포구. **튜토리얼 시작 마을** |
| 닥목 | 북 | 3,500 | 숲 계곡, 한지 작업장. 북쪽 해안 산맥. 두 강이 시작되는 곳 |
| 송악 | 서 | 3,500 | 산록 마을. **중앙 대륙으로 나가는 관문** |

**자연환경**
- 큰 강: 닥목·송악 사이 산지 → 송악 동쪽 → 장단 곡창 → 나루 하구(남해안).
- 개경 강: 닥목 계곡 → 개경 → 동해안 항구.
- 산: 북쪽 해안 산맥(닥목), 송악 산록. 강의 발원지다.
- 해안: 북쪽은 산이 바다에 닿는 해안, 동쪽은 개경 항구, 남쪽은 곡창 앞 해안과 나루 하구.
- 강 세 줄기(대륙 쪽 하나 포함)는 모두 발원지가 육지, 하구가 바다인지 계산으로 확인했다.

**길과 메인 퀘스트**
- 메인 퀘스트: ① 나루 → ② 장단 → ③ 송악 → ④ 닥목 → ⑤ 개경. 나루터에서 큰 강을 건너 곡창으로 가고, 송악·닥목을 돈 뒤 닥목 계곡을 따라 내려와 수도에 들어간다.
- 순환로(나루–장단–송악–닥목–개경) 외에 나루↔개경 직행길과 개경↔송악 큰길이 있다. 사이드 퀘스트와 이후 이동에 쓴다.
- 대륙으로 나가는 길은 송악 → 동문 마을이다.
- 다리: 나루터(큰 강 하구), 송악–닥목, 개경–송악(큰 강), 북동 길(대륙 동쪽 강).

### 중앙 대륙 동쪽 (25,000칸 = 육지 23,538 + 앞바다 1,462)

| 맵 | 종류 | 면적(칸) | 성격 |
|---|---|---:|---|
| 동문 마을 | 마을 | 3,200 | 고려와 가장 가까운 중앙 마을. 송악과 길로 이어짐 |
| 북동 포구 | 마을 | 3,200 (육지 2,699) | 해안 교역, 장터 후보. 북쪽(북유럽 구역)으로 길이 이어짐 |
| 남동 포구 | 마을 | 3,200 (육지 2,699) | 해안 교역, 장터 후보. 남쪽(아라비아 구역)으로 길이 이어짐 |
| 중앙 길목 마을 | 마을 | 3,200 | 대륙 중심 쪽. 교역, 장터 후보 |
| 북동 길 / 남동 길 | 이동 구역 | 각 3,053 | 북동 길: 강 범람. 남동 길: 산적·통나무 |
| 북쪽 내륙길 / 남쪽 내륙길 | 이동 구역 | 각 3,047 | 길 위 사건 |

- 마을 간격 약 87~115칸(걷기 약 23~30초).

**마을 크기 검토 (6곳 × 2,000칸 → 4곳 × 3,200칸)**

| 필요한 공간 | 대략 칸 수 |
|---|---:|
| 장터 광장(노점 8, 플레이어 10명 안팎이 움직일 공간) 약 24×15 | 360 |
| 이벤트 마당 약 20×16 | 320 |
| 상설 시설 6채 + 집 8채 | 340 |
| 길 | 300 |
| 맵 가장자리 자연·출입구 | 540 |
| 마을 성장 여유 | 200 |
| 합계 | 약 2,060 |

- 2,000칸 마을은 이 합계를 넘거나(해안 마을 육지 약 1,825) 여유가 없다. 3,200칸이면 해안 마을도 육지 2,699칸이라 꾸밈·생활 연출을 넣을 여유가 생긴다.
- 장터 광장은 한 화면(30×17칸)에 들어와, 모인 사람들이 한눈에 보인다.
- 수치는 계획용 추정이다. 실제 마을을 만든 뒤 사람이 모였을 때의 체감은 따로 확인한다(작업 D-1).

### 확정 내용 (2026-10-24 사용자 승인)

강 2개와 산 배치, 메인 퀘스트 순서, 길 구성, 중앙 동쪽 마을 4곳(각 3,200칸), 길 위 사건 배치. 위 표와 설명이 기준이다.

### 자연 해안선 초안 (검토 중)

그림: 같은 Figma 페이지의 `배치안 D — 자연 해안선 초안` 프레임
계산 원본: `Tools/WorldLayout/layout_proposal_d_coast.py`(해안선·면적), `layout_proposal_d_coast_terrain.py`(강·산·길, 강 흐름 검사)

- 배치안 D의 둥근 윤곽은 면적과 위치를 보여 주는 도식이다. 실제 지형으로 쓰지 않는다.
- 초안은 같은 구역·면적·강·길에 자연스러운 해안선을 입혔다.
  - 기본 윤곽: 대륙에 서쪽 면이 붙은 반도. 북동쪽으로 뻗은 땅, 남쪽 반도 두 개, 하구 만, 개경 항구 만.
  - 해안별 거칠기: 남해안은 리아스식으로 복잡하게, 북·서는 중간, 동해안은 매끈하게.
  - 남해안·동해안 앞 작은 섬 4개. 섬도 앞바다 범위 안에 두어 면적에 포함된다.
  - 대륙 동쪽 해안도 다듬고 두 포구 앞에 작은 만을 두었다. 다른 팀 구역 해안선은 건드리지 않았다.
- 면적: 고려 육지 14,856 + 앞바다 5,144 = 20,000칸. 중앙 동쪽 육지 23,223 + 앞바다 1,777 = 25,000칸. 맵별 크기는 개경 4,997 · 장단 4,299 · 나루 4,001 · 닥목 3,403 · 송악 3,300(해안이 복잡해져 시작 마을 나루의 육지를 확보하려고 배분을 조금 바꿨다).
- 강 세 줄기는 새 해안선에서도 발원지(육지) → 물길(육지) → 하구(바다) 검사를 통과했다. 마을 위치 다섯 곳은 모두 육지 위다.
- 실제 맵은 생성기(작업 B2)가 같은 규칙으로 만든다. 이 그림은 형태 예시다.

**검토 질문**
1. 해안선 형태가 실제 있을 법한 대륙으로 보이는지
2. 해안이 복잡해져 고려 면적의 약 1/4(5,144칸)이 앞바다가 됐는데 괜찮은지

### 이전 검토안 (대체됨)

- **A:** 개경을 한가운데, 네 마을이 사방을 감쌈. → 개경을 한쪽으로
- **B:** 개경 중서부, 서문이 대륙과 맞닿음, 중앙 마을 3곳. → 개경은 바다 쪽, 대륙과 떨어지게, 마을 더 많이
- **C:** 개경 동해안, 남쪽 곡창, 중앙 마을 6곳(각 2,000). → 곡창에 강이 없음, 마을이 작음

## 4. 승인 후 구현할 때의 원칙

- **원본 하나:** 세계 배치 원본 파일(좌표·면적·맵 경계)을 하나 두고, 지형 생성기·지도(M)·씬 등록이 모두 그 파일을 읽는다. 지도에만 지형을 덧그리지 않는다. 먼 바다는 지도에만 있다.
- **맵 경계 이동:** 경계 전체가 이어진다. 마을 이동은 페이드로 연출한다(10/23 회의).
- **기존 시스템 보존:** 시장·상품·퀘스트·NPC·시설 아이디와 저장 데이터는 유지한다. 위치가 바뀐 저장은 이주표(`Resources/GoryeoLayout.json` 방식)로 옮긴다.
- **면적 검사:** 생성 결과의 칸 수(육지·앞바다)가 3절 표와 맞는지 자동 검사한다.

## 5. 현재 구현과의 차이 (2026-10-24)

현재 맵(고려 5씬 + 중앙 6씬)은 새 방향과 다르다. 다시 만든다.

- 고려 다섯 권역이 길을 따라 늘어서 있다. 수도 위치에 지리적 근거가 없다.
- 고려가 중앙 대륙과 좁은 땅으로만 연결되어 따로 떨어진 직사각형 섬처럼 보인다.
- 중앙 동쪽 6맵은 직사각형을 이어 붙인 형태다. 대륙 전체에서의 위치를 기준으로 만들지 않았고, 마을과 이동 구역의 구분이 없다.

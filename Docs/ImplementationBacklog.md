# 개발 작업 목록

기준일: 2026-10-16. **먼저 무엇을 할지**, 일정은 [개발·검증 계획](DeliveryPlan.md)의 11월 초 마감 역산표에서 본다. 사용자가 마감을 ‘11월 초’로 확인했으며 정확한 날짜는 아직 미정이다. 기존 구현을 다시 만드는 목록이 아니라, 현재 프로토타입에서 남은 작업을 실행 단위로 나눈 것이다. 게임 코드·미술·서버 구현을 이번 문서 작업에서 변경하지 않았다.

초기 MVP: 네 스타팅 지역과 여러 중간 구역, 교역/운반/경로 선택, 2~4명 실제 공유 세계 검증. 최종 제품: MMORPG 규모의 다중 접속 교역 세계. 2~4명은 최종 정원이 아니다. 아래 담당 A~D는 배정안이며, **A의 고려 담당 외 실제 팀원 이름·역할은 미확정**이다. 다른 세 지역의 팀 산출물도 아직 이 저장소에서 통합 확인하지 못했다.

## 2. 우선순위와 상태

- **P0:** MVP 경험/진행/팀 통합/재산 일관성에 필수. 늦어지면 병목을 공개하고 일정·범위를 다시 합의한다.
- **P1:** 고려의 품질과 체험을 높일 작업. P0의 실제 결함과 비교해 양·세부 표현을 조절한다. 원본 요구의 영구 폐기는 아니다.
- **후속:** MVP 안정 뒤 MMORPG 확장/콘텐츠 확대. 필요한 데이터·권한 경계는 초기에 고려한다.
- 상태는 `진행 전·미구현 / 부분 구현·보완 / 검증 대기·미검증 / 완료 / 보류`로 기록한다. 아래 표의 상태는 이번 검토 시점의 기준이며 일정에 적힌 날짜가 지나도 자동 완료되지 않는다.

EC-02와 SAVE-02는 같은 재산 변경의 두 면이므로 병렬로 따로 완성한 뒤 붙이지 않는다. C가 한 명령의 저장/응답까지 세로로 연결하고 B가 세션·전송을 맞춘다. NET-03을 위해 MAP-05 전체 미술 완료를 기다릴 필요는 없으며, 임시로 연결된 두 구간으로 먼저 전환을 시험하고 최종 네 지역망을 검사한다.

SIM-01은 기존 모든 원본 확장 기능을 새로 구현하는 작업이 아니다. **MVP에서 실제 켜 두는 기존 기능의 권한 누락을 막는 작업**이다. 의뢰·도적·길 사건 중 시연 범위를 좁힐 필요가 생기면 PL-02에서 명시적으로 합의한다. 클라이언트마다 무작위로 재산을 변경하는 로컬 기능을 온라인에 그대로 남기지 않는다.

## 8. 매 작업의 완료 기록

각 ID에 `실명 담당 / 보조·리뷰어 / 예정 시작·끝 / 상태 / PR·커밋 / 검사·플레이 기록 / 남은 문제`를 붙인다. 한 작업이 너무 커서 한 번의 리뷰로 확인하기 어려우면 하위 작업으로 나누되, 이 표의 상위 ID를 유지한다. 현재 목록의 ‘완료 기준’은 승인된 기능이 아니라 작업 완료를 판단하기 위한 제안이며 팀과 실제 마감에 맞춰 조정한다.

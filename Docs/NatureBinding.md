## 바로 교체하면 안 되는 부분

### 산맥

현재 `m1_tiles_preview.py`의 MOUNT_BLOCK은 소나무 등을 겹쳐 산악을 표현한다. FMASK 전체를 blocked에 넣고, 개체의 아래 줄/중앙을 기준으로 충돌과 obj/high를 나눈다. 여기에 새 산맥을 나무처럼 등록하면 고개·계곡의 빈 공간까지 막거나, 절벽 전체를 줄기 한두 칸만 막는 오류가 생길 수 있다.

배치 자료에는 **그림 범위 / 암벽 막힘 / 고개 통행 / 물 / Above**를 별도로 둔다. 그림 알파를 그대로 충돌로 삼지 않는다. 고개 승인 폭48px와 길32px가 게임의 발밑 판정·16px 격자에서도 통과하는지 PlayerMotor로 검증한다. 실제 지형 높이·등산·새 고도 시스템은 이번 그림 연결에 포함하지 않는다.

22종은 넓이가 다른 능선·굽힘·갈림의 세트다. 현재 지형에 전부 억지로 맞추지 않는다. 보수적 공간 검사에서 `branch-w-e-s`는 기존 산악 범위 안 후보0, `branch-w-e-n`는3이었다. 이는 마을·현재 길/물/기능물을 피하고 보이는 칸을 산악 범위 안에만 넣는 단품 검사다. 산맥 전체가 연결된다는 뜻도, 조각을 쓸 수 없다는 최종 판정도 아니다. 필요한 구간에 더 작은 별도 조각을 제안하거나, 산자락 배치를 조정한 그림을 먼저 검토받는다. 승인본을 줄이거나 자르거나 회전해 맞추지 않는다.

수원·폭포는 기존 수원1곳→호수→바다의 방향을 유지한다. 물 접속 모듈은 기본적으로 남북 방향이다. 현재 강이 꺾이는 자리나 다른 폭에 맞지 않으면 현재 강가를 통째로 바꾸지 말고 전용 굽힘/전이 조각을 별도 만든다. 227접속 통과는 에셋끼리의 단면 호환일 뿐, 현재 강의 물 판정·폭·흐름까지 보장하지 않는다.

### 논

small-plot은192×128px(렌더12×8칸), 실제 작물 논리 영역은8×4칸이다. 좌우32px·위48px·아래16px의 그림 여유를 포함한다. A2를8×4칸/16px로 등록하거나 주변 길 바로 옆에 논리 영역만 보고 놓으면 크기 검사 실패 또는 이삭이 길을 덮는 문제가 생긴다. **전체12×8칸 등록 + 내부 논리 영역 별도 기록**이 필요하다.

장단 현재 JSON에서 물·길·충돌·obj/high·기능물 주변을 피한12×8칸 빈 사각 후보는51곳이었다. 서로 겹치는 후보 수이며51개 논을 놓을 수 있다는 뜻이 아니다. 농경지에 알맞은 자리나 길/강과의 풍경은 아직 선택하지 않았다.

계획의 “들판(논)은 넣지 않는다”는 M1 단계 결정은 새 논 그림 승인으로 자동 취소되지 않는다. 현재 사용자의 적용 검토 지시에 따라 **장단의 제한된 초원 구획을 previewOnly로 검토하는 후속 작업**을 제안한다. 위치·규모는 그 화면 승인 뒤 본편에 반영한다. 기본 지형 전체를 논으로 바꾸지 않는다. 원래 길을 살리고 논 구획 사이로 길이 지나는 요구도 반영한다.

농사·수확·판매 품목은 추가하지 않는다. 논 안으로 들어갈 수 있는지, 들어가면 캐릭터 앞/뒤로 어느 부분이 보이는지는 배치 시험에서 정할 항목이다. 그림 승인만으로 통행 금지나 감속을 추가하지 않는다. Native9모듈의 새 크기 조합/비정형/안쪽 모서리는 이번 완성 구획 승인 범위로 확대하지 않는다.

### 인증과 성능

현재 M4 합성 인증 경로는 새 에셋에도 재사용할 수 있다. 31원본(산맥22+논3+숲6)을 임시 A2 목록에 전체 개체로 등록하고4,668개의16px 렌더 칸을 원본에서 재합성해 오류0을 확인했다. **형식 호환 시험이며 본편 등록이나 새로운 배치 승인 완료가 아니다.**

A2의 cliff 모듈 규칙은 center/edge/outer_corner/inner_corner를 요구한다. 22종 catalogue는 다른 역할 이름과 포트 규격을 가진 능선 목록이므로 그대로 대입해 완료 처리하지 않는다. 후속에서는 전체 역할 개체 등록과 별도로 연결 목록을 검사하고, 완성 배치에 누락/불일치 포트가 없도록 한다. 범용 절벽 면 조립 세트를 구현한 것으로 표시하지 않는다.

현재 m4_certify의 승인 근거 파일 존재 확인만으로 배치 승인까지 추정하지 않는다. 신규 등록 때 approval의 상태·범위·크기·RGBA 지문과 실제 출처를 대조하는 검사를 연결한다. 이번 검토 도구는 동결 원본과의 일치부터 확인했다.

새 산맥·논 원본에서 현재 타일에 없는 고유16px 그림은 최대2,611종, 순수RGBA 약2.55MiB였다. 전체 라이브러리 원본 칸만 센 값이다. 실제 배치/겹침으로 새 합성 칸이 더 생길 수 있으며 Unity 총 메모리·FPS 추정치가 아니다. 적용 후 조밀한 숲+산맥+논 장면에서 다시 측정한다.

앞선 atlas 시험의 비정수 축소 차이가 남아 있으므로 **아트 연결과 atlas 최적화를 한 번에 묶지 않는다.** 우선 기존 Chunk Tilemap으로 그림과 기능을 검증하고, 최종 사용 타일이 정해진 뒤 atlas를 별도로 해결한다. atlas 최적화가 끝나야만 새 아트를 시험할 수 있는 것은 아니다.

## 조정한 후속 순서

1. **A7a 적용 검토 — 완료.** 승인 원본/지문, 현 숲 연결, 임시 A2/M4 합성, 산맥 접속, 배치 제약 조사.
2. **A7b previewOnly — 연결·검사 완료, 배치 승인 대기.** `nature_layout.json`에 세계 좌표, `nature_masks.json`에 암벽/물/Above 판정을 두었다. 송악의 짧은 능선(고개 모듈은 이번 배치에 미사용), 큰 폭포/하류, 장단 부근 논 두 구획을 연결했다. 원래 숲 합성을 유지하며 교체 영역만 온전한 나무 단위로 제거한다. 사용자 선택으로 큰 폭포를 유지하고 기존 ID를 보존한 출구·도착 위치 조정6건/새 경계15칸을 검증했다. 논은 통행을 유지하고 플레이어 발 위치에 따라 가림을 바꾼다. 위치·규모는 최종 그림 확인 전이다.
3. 배치 원본→M4 export→MapJsonBuilder로 검토용 JSON/씬을 만든다. 생성물을 손으로 고치지 않는다. 본편과 별도 출력 경로·previewOnly=true를 지켜 저장을 보호한다.
4. 전후480×270/전체 지도, 맵 경계 양쪽 접속, 전체 원본 RGBA·포트·통행/물/노면, PlayerMotor의 고개 통과·물/암벽 차단·논 가장자리·가림을 검사한다. 기존 시장/NPC/시설/퀘스트/출구ID,13맵 도달성과 기존 저장 유효 위치를 보존한다. 물/막힘 변경은 별도 diff로 검토한다.
5. **사용자 배치 그림 승인 뒤** 승인된 범위만 본편 생성 원본에 연결한다. 13맵 재생성→출구 도달/저장 회귀→성능 비교를 마친 뒤 완료로 표시한다. 다른 문명·공용 파일·월드 지형/통행에 영향을 주는 변경은 기존 규칙대로 별도 검토한다.
6. M5 생활·사건과 D-1 플레이 확인은 계속 별도다. 이번 적용 준비를 농사/고도/새 시장 기능 구현으로 확대하지 않는다.

# 고려 지역 프로토타입 — 수도 도착·물류 동선

> **현재 구현 추적:** [개발 진행표](DevelopmentStatus.md)를 먼저 확인한다. 아래 검토 당시의 ‘4맵·마을2·시설/낙하 제거 미구현’은 이전 기준선이다. 이번 구현은 6맵·수도1+마을4·로컬 시설3종이며, 사용자 후속 확인에 따라 감속을 나타내는 시각적 흔들림은 유지한다. 기획/검증/미완료는 진행표에서 구분한다.

> **10월17일 전체 재대조 교정:** 스타팅 지역은 수도1+수도 외 최소 마을4, 이미 발전한 지역·자유 이동·마을 등급/개인 신용별 시설 이용이 제작 범위다. 현재 고려 네 맵은 수도1+마을2+길1로 미달이다. [전체 누락 교정](FullRequirementsReview_2026-10-17.md)와 [고려 제작 명세](GoryeoRegionSpec.md)를 우선하며 이전 최소 거점/미정/검토 중단 표현을 현재 범위로 재사용하지 않는다.

> **2026-10-17 후속 결정:** [출신 역할](OriginDesign.md)과 [최신 변경 요약](DesignUpdate_2026-10-17.md)을 우선한다. 주행 낙하는 제외하고 감속 중심으로 변경하며 정보·적재·판매·이동 역할을 사용한다. 아래 기존 낙하/회수 검사·관찰은 이전 코드의 기록이며 유지할 신규 기능의 요구가 아니다. 실제 코드 제거/저장 이주는 아직 완료되지 않았다.

2026-10-15. 사용자 후속 요청에 따라 팀에게 보여 주고 수정할 수 있는 고려 프로토타입을 개선했다. **최종 미술·배치·재미 승인본이 아니다.** 전체 제작 구조 이관이나 경제 수치 변경을 시작한 것은 아니다. 초기 MVP의 2~4명 검증과 최종 MMORPG 목표는 유지한다.

## 이번에 적용한 것

- 개경 남문: 판타지 조각상 모양의 기존 망루 타일을 성벽 기둥과 기와 처마로 교체했다. 처마는 위쪽 그림 층이고 남문의 네 칸 통행 폭은 유지한다. 기존 자산 재조합이며 실존 남대문 복원이 아니다.
- 시전 동쪽: 생산 마을로 가는 큰길 옆에 짐 마당·보관 건물·수레·적치물을 묶고 시전/주거 골목과 연결했다. 짐을 나누어 싣는 장소가 읽히도록 하는 공간 비교안이다.
- 생활 동선: 짐 마당을 왕복하는 짐꾼과 시전을 오가는 행상을 추가했다. 기존 WorkingNpc를 재사용하며 통행을 막거나 실제 재고를 생산하지 않는다.
- 길 안내: 남문·시전 갈림길·동문 짐 마당·궁성 앞마당에 방향 안내를 보강했다. 기존의 연결되지 않은 서문 안내를 제거하고, 거래 수량·귀환 화물·직접 확인한 장부를 짧게 언급한다.
- 궁성 진입: 두 전각 앞 길을 중앙 접근로와 연결했다. 지형 지도에도 변경된 길과 건물 배치가 반영된다.

나루·예성 길·닥목의 기존 플레이 가능한 연결은 유지했다. 가격·재고·보수·화물 낙하·시간 정책은 그대로다. 출구·스폰·맵/거점 ID와 시장/객주/게시판 위치도 유지했다. 이번 작업을 고려 전체 완료나 이동 재미 검증으로 세지 않는다.

## 확인 방법

Unity에서 `Assets/PocketCaravan/Scenes/Goryeo/Gaegyeong.unity`를 열고 Play한다. 남문에서 북쪽 시전, 동문 짐 마당, 닥나무 마을 방향을 걸어 본다. WASD 이동, Shift 달리기, Space 상호작용, M 지도, L 장부다. 시작 맵이 아닌 개경을 직접 Play하면 기존 코드가 본편 저장을 불러오거나 자동 저장하지 않으므로 새 임시 상태로 확인할 수 있다. 기본 시작 자금·수단은 기존 설정을 따른다. 검증용 수레/화물을 씬에 저장하지 않았다.

통합 교역은 기존 나루 시작 플레이에서 확인한다. 이 경우 기존 저장을 이어 갈 수 있으므로 새 게임 선택과 기존 진행 보존을 구분한다. 개경 직접 Play는 자유 배치 확인에 편하지만, 실제 초보의 첫 왕복 테스트를 대체하지 않는다.

팀에서 볼 항목:

1. 표지판을 모두 읽지 않아도 남문→시전→동문 방향을 찾는가?
2. 나루와 다른 수도의 인상이 나는가? 가장 반복적이거나 비어 보이는 구간은 어디인가?
3. 물류 마당의 건물·짐·수레가 기능을 전달하는가? 단순히 소품만 늘어난 느낌인가?
4. 손수레를 실은 상태에서 처마의 가림과 길 너비가 불편하지 않은가?
5. 왕복 교역에서 화물·판매 수량·다음 경로를 바꿀 이유가 있는가? 이번 시각 개선만으로 해결되지 않은 문제를 따로 기록한다.

## 수정할 원본과 재생성

주 원본은 `Tools/MapGen/gaegyeong.py`다. 동쪽 물류 마당의 길·건물은 초반 블록, 남문 표현과 작업자·안내판은 후반 블록에 모았다. 새 마당의 난수 소비는 기존 가게/식생 난수열과 분리했다. 변경으로 배치 가능 영역이 달라진 만큼 주변 가게·식생 일부도 재배치됐다.

`python3 Tools/MapGen/export.py`는 JSON·타일·지형 지도를 내보낸다. `python3 Tools/MapGen/validate.py`, `python3 Tools/MapGen/validate_route_choice.py`로 검사한다(Pillow 필요). Unity 씬 생성은 개경 한 장에만 `MapJsonBuilder.BuildSingleMap`을 사용했다. 아직 씬 수작업 보존 기능이 없으므로 **생성 씬만 직접 고친 뒤 재생성하지 않는다.** 출구/거점 연결을 바꾸면 별도 WorldIndex 갱신도 필요하지만 이번에는 그 연결이 변하지 않았다.

## 검증과 실행 파일

- 전체 맵 회귀 **78개**, 기존 경로 선택 **4개** 통과. 새 검사에는 남문 통행 폭·물류 마당 길 연결·수레가 통행로 밖에 온전히 배치되는지가 포함된다.
- Unity Play **10개** 검사: 소금5개를 실은 손수레로 남문 네 통행 칸 각각 통과, 작업자2명 생성·양쪽 지점 왕복·통행 가능 타일·비차단 확인, 화물 보존. 조작은 정해진 입력으로 PlayerMotor를 수동 Tick한 기술 검사이며 사람의 길찾기·재미 평가가 아니다.
- 생성된 개경 씬의 **2,944칸**을 내보낸 JSON과 대조해 바닥 존재·충돌·길 등급 불일치0을 확인했다.
- 콘솔 오류0. 본편 저장·다른 세 본편 씬/맵·기존 시험장·WorldIndex·빌드 목록의 해시가 작업 전후 동일하다.
- Mac Player 빌드 성공: 오류0·경고1·약7초. 경고는 Unity Cloud 네이티브 심볼 업로드 토큰 부재다. 이전 빌드의 미컴파일 변경 경고는 이번 빌드에서 발생하지 않았다. 독립 실행 앱의 수동 플레이 검증은 아직 하지 않았다.

로컬 빌드: `Builds/validation-goryeo-prototype/PocketCaravan.app`. 네 고려 본편 맵을 포함하며 `CARAVAN_PREVIEW`로 본편과 다른 `pocket_caravan_preview_save.json`을 사용한다. 기존 프리뷰 진행이 있으면 이어질 수 있다. Windows/모바일 빌드가 아니다. 기존 GitHub 프리릴리스 실행 파일은 교체하지 않았다.

로컬 근거: `output/goryeo-prototype/`의 `runtime-validation.json`, `preservation-before.json`, `preservation-after.json`, `capital-gate.png`, `capital-loading-yard.png`, `capital-market.png`. 빌드 결과는 위 빌드 폴더의 `build-report.json`이다. 기존 자동 검사는 소스에 있으나 이번 일회성 Editor 실행 검사·화면은 로컬 기록이다.

다음 수정은 팀의 위 관찰을 바탕으로 정한다. 수도 대표 미술, 노면 소리, 주막의 실제 휴식/정보 기능, 반복 교역·실패 복구, 공유 시장과 온라인 인원 검증은 남아 있다. 이번에 새로운 서버·대규모 제작 도구·생산 체인을 추가하지 않았다.

## Windows 64비트 검토 빌드 — 2026-10-15

사용자 요청으로 동일 게임 소스 `3ad1d5c`의 Windows x64 Mono 빌드도 만들었다. Unity Hub로 6000.3.26f1의 Windows Build Support(Mono)를 추가했다. 첫 시도는 실행 중인 Editor가 새 후처리 모듈을 로드하지 못해 실행 파일이 없었으며, Editor 재시작 후 다시 빌드했다. 첫 시도를 성공 산출물로 배포하지 않는다.

최종 빌드 성공: 오류0·경고1·약23초. 경고는 TestRunBuilder의 자동 생성 PerformanceTestRunInfo.json 갱신이다. `PocketCaravan.exe`와 `UnityPlayer.dll`의 AMD64 PE 헤더, 네 씬 데이터, 프리뷰 전용 저장 파일명이 포함된 게임 어셈블리, 필요한 런타임 폴더를 확인했다. Windows PC에서 실제 실행·입력·소리·화면은 아직 검증하지 않았다.

로컬 배포 ZIP: `Builds/PocketCaravan-Windows-x64-2026-10-15.zip`(47,152,754바이트). 실행 파일·데이터·Mono 런타임·조작 안내·에셋/글꼴 라이선스를 포함한 195개 파일이며 압축 CRC 검사 통과. 디버그 배포 제외 폴더는 넣지 않았다. ZIP을 **전체 압축 해제한 뒤** `PocketCaravan.exe`를 실행한다. exe만 따로 옮기지 않는다. 본편과 분리된 프리뷰 저장 정책은 Mac 빌드와 같다.

결과: `Builds/Windows/build-report.json`, `output/windows-build/package-validation.json`, `preservation-after.json`. 빌드 전후 2,209개 추적 프로젝트 파일·본편 저장 해시가 동일하고, Editor 대상은 원래 StandaloneOSX로 복구했다. 게임 소스·밸런스·씬은 이번 Windows 작업에서 변경하지 않았다. ZIP은 로컬 산출물이며 GitHub 프리릴리스는 갱신하지 않았다.

## GitHub 팀 공유 — 후속 요청

Windows x64 ZIP과 Mac Universal ZIP을 [새 팀 검토용 릴리스](https://github.com/hundredman/pocket-caravan/releases/tag/goryeo-prototype-2026-10-15)로 공유한다. 위의 ‘로컬만 있음’은 당시 상태이며 이후 릴리스 전달 단계로 이어졌다. 두 ZIP의 압축 CRC, Mac ZIP을 다시 푼 앱의 ad-hoc 서명 무결성을 검사했다.

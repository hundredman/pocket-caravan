## 1. 판단과 범위

2026-10-17 후속: 팀에 먼저 맞출 좌표 구역·ID 접두어·출구/스폰 계약은 [지역 통합 규칙 합의안](TeamIntegrationContract.md)에 구체화했다. 기존 고려 x=0~3 사용을 확인했으며, x 구역 분할이 현 거리 기반 시세 계산에 미치는 영향을 함께 기록했다. 아직 팀 승인이나 런타임 이관을 뜻하지 않는다.

현재 2D를 유지하면서 지형·길·마을·지역 미술을 교체하고, 나중에 여러 경로가 있는 교역망으로 확장하는 것은 가능하다. 이미 Python 맵 원본→JSON→Unity 씬, 별도 시장 데이터, 맵 연결 인덱스가 있다. 다만 **안전한 시각 편집 도구가 완성된 상태는 아니다.** 생성 책임과 데이터 경계를 먼저 정리해야 한다.

권장안은 기존 생성기를 유지하면서 맵 등록부를 한 곳으로 모으고, 지역 설정·고증 근거·미술 묶음을 분리하는 것이다. 전용 월드 에디터, 무한 월드, 실시간 지형 변경, 전체 3D 전환은 이번 필수가 아니다. 미술 개선만으로 이동 재미나 온라인 수용 인원을 보장하지 않는다.

원본 시대는 대항해시대 이전, 대략 8~15세기 상인 문화가 공존하는 가상 교역 세계다. 단일 12세기 복원으로 변경하지 않는다. 동물 캐릭터·압축 지리·공통 화폐는 각색이다. 현재 Naru·Route01·Gaegyeong·Dakmok은 모두 고려 내부이며, 다른 문명은 여러 중간 구역을 지난 후 도달해야 한다.

## 3. 분리할 제작 단위

| 단위 | 담을 정보 | 따로 두는 이유 |
|---|---|---|
| 월드 등록부 | mapId, regionId, scenePath, authoringSource, entryPoint, 연결·포트 | 새 맵 때문에 여러 공통 코드를 수정하지 않기 |
| 개별 맵 원본 | 크기, 지형, 길 등급, 충돌, 스폰, 시장·출구 배치 | 건물이나 길만 수정하고 경제·저장 ID 보존 |
| 지역 표현 설정 | 팔레트, 식생 묶음, 건축·생산 소품, 주변음, 계절 표현 | 같은 기능을 지역별 모습으로 재사용 |
| 경제 정의 | townId, 품목·공급/소비, 가격용 좌표·거리, 운반 수치 | 지도를 보기 좋게 옮긴 것이 시세를 바꾸지 않기 |
| 고증 기록 | 주장, 자료 시기, URL, 위치 신뢰도, 각색 이유, 적용 대상 | 근거가 바뀌어도 관련 에셋·설명만 찾아 수정 |
| 저장/온라인 상태 | 콘텐츠 버전, 안정 ID, 위치, 화물, 시장 상태 | 제작 원본과 플레이 중 변화를 섞지 않기 |

맵 등록부는 **목록과 식별자의 단일 원본**으로 삼고, 거점 경제는 TownData의 단일 원본을 유지한다. 같은 값을 JSON과 Inspector에서 각각 편집하지 않는다. 공통 빌더가 직접 `if (region == 고려)` 분기를 늘리지 않게 한다. 지역 설정을 분리해도 새로운 지형 생성 함수까지 자동으로 작성되는 것은 아니다.

길은 세 가지를 구분한다. ① 맵 안에서 실제 걷는 노면·충돌, ② 맵 사이 이동 가능한 연결 그래프, ③ 지도 UI에 그리는 배치다. 가격·의뢰의 이동 비용은 별도 경제 규칙이다. 현행 WorldIndex의 최단 다음 맵은 연결 수 기준 BFS이며, 지형·짐·날씨를 고려한 최적 교역로 계산기는 아니다. 그 기능을 이번 공통화의 완료 조건으로 넣지 않는다.

맵 등록부는 아래처럼 명시적 시작점과 지역 참조를 가지는 형식을 제안한다.

```json
{
  "schemaVersion": 1,
  "entryPoint": { "mapId": "Naru", "spawnId": "S0" },
  "maps": [{
    "mapId": "Naru",
    "regionId": "goryeo",
    "scenePath": "Assets/PocketCaravan/Scenes/Goryeo/Naru.unity",
    "authoringSource": "Tools/MapGen/maps.py:naru",
    "environmentProfileId": "goryeo_riverbank"
  }]
}
```

위 예시는 한 항목만 발췌한 **미적용 형식 제안**이다. `S0`은 현 나루 스폰 ID를 썼으며 게임 시작 장소에 대한 팀 최종 결정이 아니다. `environmentProfileId`는 새 제안이다. 연결·스폰의 상세 좌표는 개별 맵 원본에서 내보내 등록부와 대조하고, 중복 수동 편집하지 않는다. Python 함수 참조는 허용 목록으로 해석하며 임의 코드 문자열을 실행하지 않는다.

| 수정 요청 | 제안 구조에서 수정할 원본 | 반드시 다시 확인할 영향 |
|---|---|---|
| 선착장 그림·지붕 색 교체 | 지역 미술/프리팹 | 정렬·가림·미술 라이선스. 충돌과 경제는 그대로인지 |
| 나무·시장 위치 이동 | 개별 맵 배치 | 통행·상호작용·지도 표식·저장 위치 |
| 숲길을 넓히거나 새 다리 배치 | 지형·길·충돌 | 등짐/수레 비교·감속·출구 접근·서버용 충돌 데이터 |
| 맵 사이 연결 변경 | 출구 원본·등록부 대조 | 목표/복귀 스폰·WorldIndex·지도·의뢰/저장 참조 |
| 다른 지역에 같은 장터 사용 | 공통 장터+새 지역/마을 데이터 | region 조회·상품/경제·빌드 포함·공통 코드의 지역 분기 유무 |

## 4. 팀이 수정하는 방법

### 당장 적용할 작업 규칙

현재는 지형·길·충돌·배치 원본을 `maps.py`/`gaegyeong.py`에서 수정하고 JSON과 씬을 다시 생성한다. Unity에서만 옮긴 오브젝트는 재생성 시 유실될 수 있다. 기존 씬 수정은 먼저 비교·원본 반영하고, 생성 전 수정 중인 씬이 있으면 중단한다. 전체 재생성보다 변경 맵과 의존 산출물만 갱신한다.

맵 담당자는 원본 파일을 나누고, 공통 `tiles.py`·아틀라스·빌더는 변경 요청을 모아 처리한다. 순서 의존 난수 대신 맵별 고정 seed를 유지한다. `.meta`와 기존 ID는 보존하고 생성물 직접 수정은 하지 않는다. PR에는 동일 위치·배율의 전후 화면, 통행 검사, 기존 저장 영향 여부를 함께 남긴다.

### 다음 구현에서 만들 경계

생성한 Tilemap·충돌·게임 객체는 `Generated` 프리팹으로, 팀원의 수작업 장식은 별도 `AuthoredOverlay` 프리팹으로 보관하는 안을 권장한다. 씬 조립기는 두 참조를 유지하고 생성 프리팹만 갱신한다. **현재 이 보존 기능은 없다.** 단순히 씬 루트 이름만 나누면 현재의 씬 재생성에서 보호되지 않는다.

Overlay에는 충돌 없는 미술·소리 연출만 허용한다. 장터·출구·상호작용·충돌·길 등급을 바꾸는 오브젝트는 원본 데이터와 검증기에 등록해야 한다. 장식도 통행을 가리거나 잘못된 길을 암시하면 검사 대상이다. 공통 랜드마크 anchor에 상대 배치하고, anchor 삭제 시 조용히 원점으로 옮기지 말고 오류를 낸다.

Unity Tile Palette로 지형 자체를 그리려면 **해당 맵의 원본 소유권을 Unity로 이관**하고 공통 게임플레이 JSON 내보내기를 구현해야 한다. Python과 Unity 양쪽에서 같은 타일 층을 편집하는 방식은 왕복 변환을 검증하기 전에는 채택하지 않는다.

## 5. 고증과 환경을 맵으로 번역하는 기준

국사편찬위원회 개경 GIS는 시장·창고·다리·성곽·하천 등 참고에 유용하다. 다만 대상 자료는 고려~조선 초기와 일부 조선 후기까지 걸치며, 시설 정보는 주로 점 위치이고 근대 지도·현대 지형도를 참고한다. 궁궐의 일부 좌표는 임의 묶음 위치다. **중세 건물 외곽·식생·수로를 그대로 복원한 데이터로 취급하지 않는다.** 위치 신뢰도와 자료 시대를 함께 기록한다. [국사편찬위원회 개경지리정보 자료소개](https://hgis.history.go.kr/kor_g1/main.do)

개성의 산지·분지·남서쪽으로 낮아지는 지형은 공간 구성의 참고가 된다. 현대의 기온·강수량·수종 비율·재배 작물 목록을 중세 수치나 식생 비율로 옮기지는 않는다. [한국민족문화대백과 「개성특별시」](https://encykorea.aks.ac.kr/Article/E0001660)

예성강 수운과 벽란도가 고려 수도의 관문이었던 점은 운송 풍경의 근거가 된다. 같은 항목 안의 조선시대 조운 사례와 현대 하천 수치는 고려 시설의 직접 증거로 사용하지 않는다. [한국민족문화대백과 「예성강」](https://encykorea.aks.ac.kr/Article/E0037956)

| 현재 맵 | 이번에 강화할 공간 경험 | 역사·환경 근거와 각색 경계 | 완료 판정 |
|---|---|---|---|
| 나루 Naru | 물가→하역장→장터→내륙 출구. 강변 여백과 짐 이동 동선 | 예성강 교역권 모티브. 나루를 벽란도 실측 재현으로 명명하지 않음 | 선착장 끝·육지 접합이 읽히고 적치물이 수레 동선을 막지 않음 |
| 예성 길 Route01 | 숲이 조이는 샛길과 열린 큰길, 다리 앞 시야·물소리 | 계곡·물길 모티브를 압축한 가상 길. 실제 특정 고갯길이라는 주장 금지 | 분기 전에 양쪽 지형을 파악하고 수단/화물에 따라 선택할 이유가 있음 |
| 개경 Gaegyeong | 뒤쪽 산지·높은 궁역 실루엣, 성문→시장→물류 접근로의 위계 | 개경의 지형·도시시설 참고. 모든 시대 성곽·시설을 동시 실측 복원했다고 하지 않음 | 수도의 도착 인상이 나루와 다르고 장터·출구를 찾을 수 있음 |
| 닥목 Dakmok | 작업 물가·재료 적치·건조 공간·운반 길의 연결 | 고려 종이문화 참고, 마을·공정 배치는 각색. 특정 실존 산지·고려 공법 복원은 추가 근거 필요 | 소품을 읽으면 생산 마을임을 알고 일꾼·화물 동선이 충돌하지 않음 |

식생은 균등한 꽃·나무 산포보다 수변의 갈대, 숲 가장자리, 집 주변 작업 마당처럼 기능별 군집을 만든다. 강은 맵 경계마다 갑자기 끊기거나 서로 다른 높이에서 솟지 않게 연결 지점을 점검한다. 평지·완만한 단차·암반·물가를 시각적으로 구분하되 높낮이 새 이동 시스템을 추가하지 않는다. 현재 팔레트와 고정 계절을 먼저 정리하는 안을 권장하며, 특정 계절은 아직 확정하지 않았다. 계절을 정하면 꽃·작물·색감·의복을 함께 점검한다.

근거 기록은 다음 다섯 상태로 구분한다: `사료/유물 직접 근거`, `연구 기반 복원`, `현대 지형 참고`, `게임 각색`, `확인 필요`. 확신이 낮은 부분은 단정적 백과 문구와 실존 고유명 사용을 줄인다. 이미 작성한 [고려 고증 검토표](GoryeoDesignReview.md)와 연결하고 별도 상충하는 역사 설정을 만들지 않는다. 참고 이미지는 조사와 에셋 사용 권한을 구분한다.

## 6. 도구 선택과 가능성

| 방식 | 가능성·이점 | 프로젝트에서 필요한 일 | 판단 |
|---|---|---|---|
| 기존 Python+JSON+Unity | 현 지형·길·나무 묶음 검사 유지, 결정적 생성 | 등록부, 지역 설정, 선택 생성, 수작업 보존 | **이번 우선안**. 맵 배치는 아직 코드 편집 필요 |
| Unity Tile Palette+프리팹 | 에디터에서 직접 타일과 반복 건물/소품 배치 | 타일 원본 이관, 게임플레이 데이터 내보내기, 생성기 덮어쓰기 방지 | 팀원이 시각 편집을 필요로 하면 한 맵에서 먼저 비교 |
| Tiled | JSON의 타일 층·객체 층·사용자 속성 활용 | 현재 전용 JSON으로 변환, 좌표/충돌/스폰/그룹 나무 검증 | 도구 교체 비용과 편집 이득을 작은 구간에서 비교 후 결정 |
| LDtk | 레벨 제작과 Unity 가져오기 선택지 존재 | 커뮤니티 importer의 Unity 6.3 호환·필드/레이어 변환·라이선스 확인 | 후보. 설치·실제 호환 시험은 하지 않음 |

Unity 6.3의 [프리팹](https://docs.unity3d.com/6000.3/Documentation/Manual/Prefabs.html)과 [Tile Palette](https://docs.unity3d.com/6000.3/Documentation/Manual/Tilemap-Palette.html)는 재사용·시각 편집 기반이다. 자동으로 현재 생성기의 보존 문제를 해결하는 것은 아니다. Tiled의 [공식 JSON 형식](https://doc.mapeditor.org/en/stable/reference/json-map-format/)은 현재 MapFile과 다른 형식이므로 직접 대입할 수 없다. LDtk [공식 연동 목록](https://ldtk.io/api/)의 Unity importer는 Cammin의 연동이며 Unity 공식 내장 기능으로 표현하지 않는다. 새 도구 설치와 전체 맵 이전은 이번 문서 작업에서 수행하지 않았다.

Unity MCP는 씬/콘솔 확인과 반복 검증에 계속 활용할 수 있지만, 저장소의 원본 데이터·버전 관리를 대신하지 않는다. 현재 설계 정리를 위해 추가 유료 도구나 모델 변경은 필수가 아니다.

## 7. 저장과 멀티를 막지 않는 규칙

- mapId·townId·itemId·npcId는 표시 이름과 분리해 유지한다. 배치 객체에는 안정적인 entityId를 도입하고 좌표나 배열 순서로 신원을 정하지 않는다.
- 원본 스키마 버전과 콘텐츠 버전을 구분한다. 시각 변경 hash와 통행/연결/경제 변경 hash를 분리하는 안을 권장한다. 꽃 색 변경과 충돌 변경을 같은 호환 문제로 취급하지 않는다.
- 맵 크기·출구·길을 바꾸면 이전 저장 좌표가 물·장애물·경계 밖에 놓일 수 있다. mapId별 이주표와 안전한 스폰 anchor를 준비하고 미지의 버전은 원본 저장을 보존한 채 오류를 안내한다. 기존 SaveSystem의 원자 저장/손상 복구도 [미해결 항목](RequirementsAudit.md)이다.
- 플레이 중 서버에서 지형을 즉시 고치는 기능은 요구하지 않는다. 향후 클라이언트/서버는 동일한 게임플레이 맵 버전을 확인하고 위치·출구·충돌 판정은 서버 기준으로 맞춘다. 충돌 없는 미술 변경의 호환 범위도 별도 정의한다.
- 지역 미술 표현과 실제 위험을 구분한다. 젖은 땅 그림을 바꿨다고 자동으로 새 감속이나 물품 손실을 추가하지 않는다. 주행 낙하는 제외한다. 감속은 예고·반복 피로·서버 판정을 함께 설계한다.
- 현재 실제 온라인은 미구현이다. 이 분리는 확장 비용을 줄이는 준비이며 동시 접속 성능 검증 결과가 아니다.

## 8. 구현 순서와 완료 기준

| 순서 | 작은 작업 단위 | 검증과 중단 기준 |
|---|---|---|
| A | 현 네 맵·ID·씬·저장·이미지 기준 보존, 누가 어떤 원본을 편집하는지 명시 | 실험 3D/시험장·본편 저장을 변경하지 않고 기준 재현 |
| B | 공통 맵 등록부와 regionId 조회, 기존 exporter/validator/빌더/빌드 목록 순차 연결 | 네 맵이 기존 ID·지형·충돌·시장·시작점을 보존. 목록 누락/중복 오류를 생성 전에 차단 |
| C | 한 맵 선택 생성, 의존 산출물 차이 미리보기, Generated/Overlay 보존 | 나루 표지판/장식 한 개 수정 후 다른 씬 불변. 재생성 두 번 같은 결과, 수작업 장식 유지 |
| D | 나루 미술·환경 설정과 고증 기록을 하나의 예제로 완성 | 화면·소리·길/수레 통행 확인. 시각만 바꾸면 경제·충돌 불변 |
| E | 다른 담당자가 같은 방식으로 기존 맵 한 구간을 수정 | 공통 빌더에 지역명 분기 추가 없이 적용. 설명 없이 구매→운반→판매와 저장 복구 |

4주 일정의 다른 작업을 모두 미뤄 B~E를 한 번에 만들지 않는다. 우선 B와 작은 C로 맵 수정 안전성을 확보하고, D로 실제 고려의 품질을 올린다. Tiled/LDtk 전면 이전은 이 단계의 전제 조건이 아니다. 착수일·담당자·소요 기간은 팀 일정과 한 맵 실험 결과로 결정한다.

필수 자동 검증: 맵/거점/객체 ID 중복, 존재하지 않는 region/market/target, 출구별 목표 스폰·의도한 역방향 연결, 스폰/시장/작업 경로 접근성, 타일 배열·팔레트 유효성, 나무 묶음, 지도 중첩/연결 모순, 좌표 변환, 기존 저장 이주. 같은 논리 고리의 지도 배치가 가능한 경우와 불가능한 경우도 각각 시험한다. 일방통행은 명시한 경우만 허용한다.

수동 검증: 실제 수레와 화물로 다리 양끝·성문·장터 통과, 나뭇잎에 가려진 길과 출입구, 표지판/대사 가독성, 이동 중 풍경 변화, 강·산지 방향의 일관성. 자동 검사는 재미를 승인하지 않는다.

## 9. 이번 조사에서 한 일과 남은 일

실제 생성기·빌더·지도 배치·지역 데이터 경계를 읽고 위 결합을 확인했다. 공식 기술 문서와 국사편찬위원회·한국학중앙연구원 자료를 조사했다. 현재 맵의 읽기 전용 구조 조사와 기존 통행 회귀 검사의 결과는 아래 기록에 연결한다. 조사용 실행은 에셋·씬 재생성이나 기존 저장 변경을 하지 않는다.

2026-10-15 검사: `validate.validate()`의 기존 맵 회귀 검사 **66개 통과**. 별도로 내보낸 JSON 여섯 층의 배열 길이·타일 팔레트 인덱스·스폰 ID 중복을 확인했고 오류가 없었다. 여섯 방향 연결 모두 상대 맵으로 돌아오는 연결이 있으며 현재 지도 사각형끼리 면적 중첩이 없었다. 이 추가 조사는 역방향 포트의 폭/정확한 대응, 저장 이주, 미래 고리 연결, Unity 플레이까지 검증한 것은 아니다.

| 맵 ID | 크기(타일) | 지도 원점(생성기 좌표) | 도착 스폰 ID |
|---|---|---|---|
| Naru | 40×28 | (0, 0) | E, S0 |
| Route01 | 54×34 | (40, 4) | W, N |
| Gaegyeong | 64×46 | (49, -42) | S, E |
| Dakmok | 34×22 | (113, -30) | W |

위 지도 원점은 현재 출구 정렬로 계산한 UI용 값이며 경제용 MapCoords도, 실제 개성의 역사 좌표도 아니다. 로컬 조사 기록은 `output/region-authoring/inventory-validation.json`이다. 기존 검사는 저장소 루트에서 `python3 Tools/MapGen/validate.py`로 재실행할 수 있다(Pillow 필요).

**이번 완료는 설계 정리와 가능성 조사다.** 등록부 이관, Overlay 보존, 저장 이주, 도구 이전, 멀티 연결은 다음 구현 작업이다. 현재 지역을 마음대로 옮겨도 안전하다고 선언하지 않는다.

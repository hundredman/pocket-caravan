# WoW 참고 평판 적용 기준

2026-10-24. 사용자 지시: WoW 시스템을 최대한 참고하되 조금 간소화해 적용한다. 이 문서는 그 지시를 현재 교역 게임의 설계와 R1~R4 구현 계약으로 구체화한다. **게임 코드에 반영된 상태는 아니며, 점수·보너스 비율은 D10에서 조정한다.**

## 공식 자료에서 확인한 구조

WoW에는 전통적인 단체별 평판과 확장팩의 영예 등 여러 체계가 공존한다. 최신 체계 전부를 하나로 혼합하지 않고, 단체에 대한 기여를 쌓아 등급과 보상을 여는 전통 평판을 이번 기본으로 삼는다.

- 단체별 평판을 각각 관리하고 등급과 현재/다음 단계 점수를 보여 준다. 공식 전정실에서도 전통 평판은 중립 3,000, 우호 6,000, 그 위 12,000·21,000 등 서로 다른 구간 길이를 확인할 수 있다. 이 숫자를 프로젝트 값으로 복사하지는 않는다. [공식 전정실의 평판 화면](https://worldofwarcraft.blizzard.com/en-us/worldsoul/us/armory/character/area-52/bestinworld/reputation)
- 단체의 퀘스트 흐름과 관련 활동으로 관계를 쌓는다. [Blizzard: Building Reputation with Allied Races](https://worldofwarcraft.blizzard.com/en-us/news/21508135/)
- 반복되는 의뢰·활동에서도 특정 단체 평판과 보상을 얻을 수 있다. 지도에서 대상 단체와 보상을 확인하는 사례가 있다. [Blizzard: Legion World Quests and You](https://worldofwarcraft.blizzard.com/en-us/news/20252892/legion-world-quests-and-you)
- 평판을 요구하는 구매 보상과, 세계/단체가 보유한 보상 조건과 개인 자격을 함께 확인하는 사례가 있다. 아래 길드 사례는 일반 단체 평판 전체의 동일 규칙이라는 뜻은 아니다. [Blizzard: Guild Advancement and You](https://worldofwarcraft.blizzard.com/en-us/news/2113741/guild-advancement-and-you)
- 현대 영예에서는 보급·제작·주문·협력 활동으로도 관계를 올리고 다양한 보상을 연다. 교역 게임에서 기여 종류를 구성할 때 참고한다. [Blizzard: Dragonflight Major Factions Overview](https://worldofwarcraft.blizzard.com/en-gb/news/23823105/)

위 글은 각 발표 시점의 체계를 설명한다. 특정 확장팩 조건을 현재 WoW 전체의 보편 규칙이라고 하지 않는다. 아래의 회복 창구·교역 제재·흥정은 프로젝트에 맞춘 설계이며 WoW의 동일 기능이라고 소개하지 않는다.

## 프로젝트에 적용할 골격

| 요소 | 적용 |
|---|---|
| 관계 대상 | 고려·북유럽·베네치아·아라비아 각각 하나의 문명 평판. 중앙 대륙은 각 마을이 하나의 독립 평판 단체 |
| 소유자 | 플레이어 캐릭터의 상태. 마을 성장 등급이나 공동 시장 재고와 분리 |
| 저장 | 대상 종류(문명/중앙 마을)와 안정적인 ID별 점수. 이름·현재 씬·지도 담당 구역 번호를 키로 쓰지 않음 |
| 단계 | 적대·경계·중립·우호·신뢰·존경 6단계 유지. WoW의 모든 등급 이름을 일대일 번역한 것이 아닌 프로젝트 간소화 |
| 시작 | 출신 문명 우호, 다른 문명과 중앙 마을 중립. 출신 선택 화면이 없을 때는 현재 설정된 출신을 사용하며 선택 화면은 후속 작업 |
| 성장 | 높은 단계일수록 다음 단계 필요 점수를 늘리는 것을 기본으로 함. 모든 행동의 획득량을 일괄 축소하는 방식을 기본 성장 공식으로 쓰지 않음 |
| 기여 | 퀘스트·반복 의뢰·수요품 납품·마을 돕기. 일반 거래의 누적 기여는 작게 유지하고 반복 매매만으로 고급 평판을 얻는 것은 제한 |
| 보상 | 단계별 거래 조건, 품목, 고급 시설, 흥정 자격. 잠금 화면에서 필요 단계와 현재 진행을 안내 |
| 독립성 | 중앙 마을 A의 이익/실패가 B에 자동 전파되지 않음. 문명 사이 적대 진영 선택도 강제하지 않음 |
| 지속성 | 접속하지 않은 시간만으로 평판이 하락하지 않음 |

일반 플레이어가 중립 근처에 머물게 하는 목표는 '퀘스트로 꾸준히 기여해도 성장하지 않음'이 아니다. 일상 매매만으로는 변화가 작고, 관계를 의식한 의뢰·납품을 하면 높은 평판을 달성하게 한다. 같은 행동의 반복 억제와 상위 단계 필요 점수 증가는 별도로 계산한다.

## 기여·하락의 적용 방법

1. 퀘스트와 반복 의뢰에는 받을 평판 대상과 증감량을 명시한다. 의뢰 수락·완료 화면에서 돈·신용·평판을 따로 보여 준다. 성공한 거래 한 건마다 무조건 고정 점수를 주지 않는다.
2. 경제적 기여는 수요품 공급, 유효한 누적 거래, 장거리 조달로 구분한다. 같은 물건을 사고파는 반복·주문 쪼개기·반복 완료 알림으로 획득량이 늘지 않게 한다. 상한/누적 구간/반복 보상 기준의 수치는 D10에서 정한다.
3. 의뢰 발주지·납품지에 둘 다 영향을 줄 때는 대상별 양을 적는다. 같은 문명에 속한 두 마을이면 하나의 평판에 의도치 않게 두 번 주지 않는다.
4. 실패·훼손·기한 초과, 기존에 정한 헐값 대량 판매·매점매석 등의 하락 방향은 유지한다. 정상 교역을 처벌하지 않도록 귀속·판정·기준 시세를 명시하고 예상 불이익을 거래 전에 보여 준다. 이것은 프로젝트 고유의 교역 규칙이다.
5. 높은 단계에 도달해도 소지한 점수를 소비해서 물건을 사는 방식은 쓰지 않는다. 물건은 돈으로 사고 평판은 자격으로 확인한다. 평판을 화폐와 혼동하지 않는다.

## 단계별 체감과 보상 방향

| 단계 | 방향 |
|---|---|
| 적대 | 일반 상인의 협조가 가장 낮음. 고급 서비스와 거래 폭을 제한하되, 접근 가능한 회복 접점은 반드시 남김 |
| 경계 | 불리한 거래 조건·제한된 고급 서비스, 회복 활동 안내 |
| 중립 | 기본 거래·일반 의뢰·필수 시설 이용 가능 |
| 우호 | 개선된 거래 조건과 흥정. 출신 지역의 시작 혜택이지만 희귀 보상을 전부 열지는 않음 |
| 신뢰 | 일부 희귀품과 수도권 고급 시설 자격 |
| 존경 | 최상위 평판 보상·가장 좋은 허용 거래 조건 |

구체 품목·가격/흥정률·시설·구간 경계는 이 표로 임의 확정하지 않는다. 가격 할인과 판매 가산을 동시에 무제한 적용하면 동일 장터 왕복 매매로 돈이 늘 수 있으므로, 흥정·세금·시세·출신 보정까지 합친 실제 거래 공식으로 검사한다. WoW의 할인 수치를 교역 시장에 그대로 이식하지 않는다.

## 회복 방향과 간소화

반복 가능한 기여로 관계를 다시 쌓는 구조를 참고한다. 다만 돈도 물건도 없는 플레이어를 위해 마을 일·민원/구호 접점 같은 회복 행동을 항상 시작할 수 있게 설계한다. 이 접근 보장은 WoW 전면 복제가 아닌 프로젝트의 재기 원칙이다.

회복 전용 일은 중립까지 복귀하는 역할, 그 뒤 정상 의뢰·교역·수요품 납품은 상위 평판 성장 역할로 구분하는 안을 권장한다. 기부의 허용 범위와 회복 시간은 [돈·신용·평판](../Standing.md) 8절(확정)을 따른다. 수치는 D10.

이번 범위에서 제외하는 WoW식 확장은 별도 영예 레벨 트랙, 최고 단계 후 무한 보상 트랙, 개인 NPC별 친밀도, 계정 공통 평판, 전투·던전 평판, 자동 인접 단체 전파, 진영 대립 강제다. 모두 현재 게임의 핵심 교역 흐름과 개발 범위에 비해 복잡하다. 새로운 일일/주간 로그인 의무도 기본 조건으로 추가하지 않는다.

## R 단계 인수 조건

- R1: 서로 다른 문명·중앙 마을 값 독립, 점수→단계 경계, 시작 보정, 저장 왕복. 수치 설정과 저장 형식을 분리.
- R2: 단체를 명시한 획득/하락, 중복 지급 방지, 같은 문명 내 복수 귀속 중복 방지, 보상 자격·실제 가격 계산, 현재/다음 단계 표시. 희귀품은 시작 우호로 즉시 열리지 않음.
- R3: 흥정과 평판 보정 합산 검사. 과도한 흥정은 기존 결정대로 평판 하락 없이 거래 취소·잠시 거래 불가.
- R4: 돈 0·짐 0·낮은 신용·메인 미진행에서도 회복 시작, 회복 전용 활동의 상한, 저장/재로드 중복 보상 방지.

수치·품목 체감은 Codex 계산 후 Claude와 은샘 검토(D10)로 결정한다. 이 문서의 설계 반영을 런타임 구현·플레이 검증 완료로 기록하지 않는다.

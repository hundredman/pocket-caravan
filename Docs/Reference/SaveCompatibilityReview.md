# 저장 복원·재산 보호 검토

기록: 2026-10-21. [화물 장부 검토](CargoLedgerReview.md) 뒤 실제 상태 복원·진행 유실 경로를 검토했다. 지역 콘텐츠/가격/보수/성장 문턱을 추가 변경하지 않았다.

## 확인한 문제와 수정

기존 Apply는 저장된 상품 ID가 현재 데이터에 없으면 화물을 건너뛰고, 이동 수단은 시작 수단으로 대체하며, 없는 퀘스트/장터 기록은 누락할 수 있었다. 이후 자동 저장되면 원본 재산/진행 복구가 어려워진다. 존재하지 않는 저장 맵도 상태를 먼저 적용한 뒤 이동을 시도했다. 읽기 실패/일부 Apply 예외의 저장 차단은 있었지만 이러한 ‘조용한 생략’은 예외로 인식되지 않았다.

**현재 상태를 바꾸기 전에** SaveCompatibility로 참조와 주요 수치를 검사한다. 미확인 소지 화물/이동 수단, 활성·완료 퀘스트, 장터·재고, 게시판 지역, 기수락 배달 목적지 등을 찾을 수 없거나 검사 대상 수치/목록이 올바르지 않으면 복원을 거절한다. 빈 옛 scene/vehicle 등 기존 선택 필드는 허용한다. 명시된 scene은 실제 실행 빌드의 로딩 가능 여부를 확인한다.

SaveSystem의 구조 검사도 화물 중복 ID, null 진행 목록, 잔고·위치·체력·시각 수치 등으로 보강했다. 잘못된 쓰기 요청은 기존 파일/백업을 교체하지 않는다. 이번에 저장 스키마 버전/필드를 변경하거나 실제 저장 파일을 일괄 이주하지 않았다.

복원/읽기 실패 시 자동·수동 SaveNow를 차단한다. 하단에 이번 세션이 저장되지 않음을 계속 표시하고 Esc 메뉴에는 원인과 원본 보존 상태를 보여 준다. 긴 설명은 스크롤하며 메뉴 버튼과 분리한다. 비시작 씬 직접 실행은 기존 저장 미적용/자동 저장 비활성 정책을 유지하고, 실제로 적용하지 않는 파일 문제로 오류 UI를 띄우지 않는다.

## 보존하는 정책

- 유효한 구 저장의 누락된 선택 필드·기수락 보수/기한/신용 문턱·화물 상태는 새 규칙으로 바꾸지 않는다. 기존 낙하 이주/초과 적재 재산 보존 규칙도 유지한다.
- 미확인 **소지 화물**은 예전처럼 없애지 않고 복원을 중단한다. 미확인 **창고/옛 낙하 기록**은 이미 별도 보존하는 정책이 있어 기록을 유지한다. 서로 다른 처리를 혼동하지 않는다.
- 파일을 자동 삭제/초기화하거나 임의로 현재 ID에 치환하지 않는다. 새 게임은 기존 메뉴 확인 절차를 따른다. 이름/ID를 바꾼 팀 작업은 원래 ID 복원이나 별도 이주표를 검토해야 한다.
- 공용 로컬 복원 경계이므로 통합된 지역에 적용된다. 북유럽 Draft/베네치아 미통합 자산은 수정하지 않았다. 서버 저장/세션 인증을 구현한 것은 아니다.

## 확인 범위

[검증 기록](Validation/SaveCompatibility-2026-10-21.json): 새 데이터/파일 검사27, 실제 복원 경로 Play10, 기존 로컬 상태30, 고려 시설/저장 이주25, Python26·등록 출구26 통과. 미확인 화물·이동 수단·진행·재고 거절 전후의 잔고/원가/진행 보존, 누락 맵에서 이동 시작 안 함, 정상 복원과 실패 후 저장 차단을 확인했다. 기수락 배달의 높은 구 보수/현재보다 높은 신용 조건/낙하 상태/기한이 검사 중 바뀌지 않는 추가 사례도 확인했다.

실제 컴퓨터의 본편/프리뷰 저장 두 파일은 Play에서 **읽기 전용 호환 검사**를 통과했다. 정지한 Editor의 Application.CanStreamedLevelBeLoaded 결과로 호환 여부를 판정하지 않는다. 검사 파일은 별도 output 경로를 사용했으며 본편 저장을 덮어쓰는 복원 시험은 하지 않았다.

1920×1080 메뉴 안내와 1024×768 오류 안내/긴 설명 스크롤을 캡처했다. 임시 오류와 700자 문자열을 넣은 시험 화면이며 실제 사용자 파일이 손상됐다는 뜻이 아니다. 임시 GameView 크기를 제거하고 정지 Route01로 복구했다.

검토 빌드의 소스·플랫폼별 경고/해시·Mac 초기 실행/프리뷰 저장 복구 결과는 검증 기록을 따른다. 실제 Windows 플레이와 다른 Mac의 서명/공증 통과는 별도다.

## 남은 검토

이번 사전 검사는 **명시한 거절 사례가 상태 변경 전 차단됨**을 확인했다. 모든 예상 밖 Apply 예외의 메모리 상태를 원자적으로 되돌리는 구현은 아니다. 예기치 않은 예외도 원본 파일 덮어쓰기는 차단한다. 전체 저장값 손상 검사·자동 백업 복구·명시적 ID/퀘스트 단계 이주·출신 선택 저장·서버 영속화는 SAVE-01/02·ORG-01에 남는다. 합법적 이벤트의 보수/재산 한도와 모든 지급 경계의 일관성도 별도 검토가 필요하다.

고려의 반복 이동 재미·첫/세 번째 왕복·창고의 실제 가치, 다른 지역 퀘스트 통합 및 온라인 공유 시장은 이 패치로 완료됐다고 보지 않는다.

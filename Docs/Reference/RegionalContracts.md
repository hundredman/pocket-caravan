# 초기 지역 게시판 공용 규칙

2026-10-18. 북유럽 Draft PR #2 검토에서 확인한 의뢰 목적지 혼합 문제의 첫 수정이다. 북유럽 브랜치/DB/이벤트 코드를 변경하지 않는다.

## 적용한 규칙

- 새 게시판 의뢰는 출발·도착 TownData.region.id가 같은 경우에만 생성한다. 플레이어 출신(origin)은 이 권한을 결정하지 않는다.
- WorldIndex의 market 위치가 있고 두 맵이 연결되어야 한다. 같은 지역이라도 단절되거나 색인/지역 지정이 없는 마을에는 새 의뢰를 만들지 않는다.
- 기존 게시판의 잘못된 **미수락 제안**만 정리/교체한다. 정상 제안은 재추첨하지 않는다. 빈 슬롯의 일반 시간별 보충은 기존 규칙을 따른다.
- 표시와 수락 시에도 검사하여 경로가 바뀐 뒤 남은 제안을 수락하지 못하게 한다.
- 이미 맡은 의뢰/운반 중 짐은 보존한다. 기존 도착지에서 납품하는 경로는 차단하지 않는다. 저장 JSON 구조는 유지한다.
- 해당 지역에 적합한 목적지가 하나도 없으면 게시판이 비어 있는 것이 정상이다. DB에서 다른 지역 마을/상품을 삭제할 필요가 없다.

## 팀 작업

북유럽은 전체 DB에 자기 데이터를 추가하고, 자기 맵만 재생성하는 흐름으로 테스트해야 한다. 북유럽만 남기는 DB와 전체 맵 레지스트리를 함께 사용하면 공용 맵 검증이 실패한다. 북유럽 담당자는 전용 테스트 절차, 이벤트 발생 시각/투매 적용 상태 저장, Q6 설명/판정을 수정한다.

이번 수정은 **게시판 의뢰만** 대상으로 한다. 퀘스트의 지역·장 메타데이터/일반·자동 수락 자격, 관문 해금 후 지역간 의뢰 확장, 공용 이벤트 저장은 후속 작업이다. 현재 규칙은 관문 전 기본 제한으로, 완료된 관문/장 시스템이라고 보지 않는다. 일반 이동이나 지역간 상품 거래를 막는 코드도 아니다.

WorldIndex는 실제 등록 맵/출구로 생성해야 한다. 출구 레지스트리의 거친 연결성만 검사하며 길 위의 일시적 장애물, 미시 지형 도달성, 서버 접속 가능성을 계산하는 것은 아니다. 의뢰 보수의 좌표 거리 공식은 이번 수정에서 바꾸지 않았다.

## 검증

Unity Edit 검사18개: 같은 지역/타 지역/연결·단절/지역 누락/외국 출신/목적지 부재/정상 제안 보존/오래된 제안 차단/기수락 의뢰 보존·납품/기존 게시판 JSON 호환.

기존 Unity Play 의뢰·회수·저장 검사30개와 Python 통합 검사21개 통과. 실제 북유럽 Q1~Q7 완주나 북유럽 이벤트 저장 검증을 뜻하지 않는다. 기존 Windows/Mac ZIP은 이 코드 변경을 포함하지 않는다.

## 10/20 고려 보수 후속

지역/연결 목적지 규칙은 유지한다. 고려의 신규/미수락 제안만 등록 최단 연결 구간과 화물 무게 기준으로 조정했다. 타 지역의 기존 보수 공식과 이미 수락한 계약의 약속은 유지한다. 설정/revision·기한/팁·구 저장은 [경제 패치](GoryeoTradeBalancePatch.md)를 따른다.

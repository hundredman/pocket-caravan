# 고려의 성장·의뢰·교역·이동 품질 검토와 반영

10/20 후속 구현: 배달 보수·땔감 중복·귀환 장사는 [경제 패치](GoryeoTradeBalancePatch.md)를 우선한다. 아래 수치는10/18 검토 당시 값이다.

2026-10-18. 기준: PR #12 이후 고려9맵(수도1+마을4+길4), 로컬 NPC 의뢰/게시판/장터. 실행 소스 기준 커밋은 `fd15b20`이다. 이번 변경은 여정 수첩·의뢰 선택·시설 설명 보완이다. 온라인/사람 플레이 검증과 구분한다.

## 판정과 이번 범위 결정

**첫 지역의 구조와 기능 종류는 충분하다. 충분한 재미와 분량이 확보됐다는 판정은 아직 어렵다.** 마을을 늘리기 전에 ‘내가 고른 장사가 달라지는가’, ‘수레와 시설이 다음 선택을 바꾸는가’, ‘돌아갈 때도 계산하는가’를 확인해야 한다. 동일 심부름을 많이 세거나 달리는 시간을 늘려 30~45분을 채우지 않는다.

사용자 확인: ‘사람이 의뢰’는 **사람 NPC가 주는 의뢰**다. 플레이어 간 직접 거래는 **일단 제외**한다. 시세에 따른 개인 간 거래 가격 상·하한도 보류한다. 이는 최종 영구 금지가 아니다. 초기 멀티는 NPC/장터 거래의 공유 시장·서버 판정과 서로 보이는 이동부터 검증한다. 공동 시장 구현 완료라는 뜻은 아니다.

## 실제 보완한 것

- NPC의 여러 의뢰를 한 건씩 넘겨 보고 보상·수락 비용을 확인한다. 첫 제안의 돈/적재 조건이 안 돼도 다른 제안을 읽고 받을 수 있다. 기존 선행 조건·ID·활성 목표 순서는 유지한다. Esc는 닫기다.
- 같은 NPC에게 납품할 짐이 모자란 의뢰와 완료 가능한 의뢰가 있으면 완료 가능한 쪽을 먼저 처리한다. 짐 부족 안내에서도 다른 의뢰로 갈 수 있다. 서로 다른 납품 의뢰는 각각 물건을 소비하며 한 짐으로 보상을 중복 수령하는 규칙은 추가하지 않는다.
- Q를 **여정 수첩**으로 보완한다. ‘의뢰 / 성장·시설 / 주변 거래처’를 나누어 열람하고 진행 중 의뢰의 길 안내 대상을 선택한다. HUD에는 선택한 의뢰를 표시해 다중 수락 시 중첩을 줄인다.
- 성장 화면은 현재 신용·적재량, 실제 시설 데이터의 다음 신용 조건, 시설 효과와 현재 이용 가능 여부를 표시한다. 신용3의 귀한 게시판 의뢰는 제안이 존재할 때만 가능하다고 명시한다. 새 승급 단계/전 지역 잠금을 만들지 않는다.
- 주변 거래처는 **현재 지역과 실제 연결을 확인한 거점만** 표시한다. 마을마다 거래 역할·귀환품 힌트를 데이터로 둔다. 장터를 열어 기록한 곳과 시세 미확인을 구분한다. 지도 방문과 장터 시세 확인을 같은 뜻으로 쓰지 않는다.
- 시설 이용 결과/긴 길 안내를 스크롤 본문에서 읽게 바꿨다. 이전처럼 고정된 세 줄 메시지 칸에서 뒤가 잘리지 않는다. 정보소는 고정 경로 정보이며, 원격 실시간 시세나 고려 출신 능력의 완성을 뜻하지 않는다.

`TownData.journeyNote`가 거래처 설명 원본이다. 타 지역은 비워 두어도 작동하며 자신의 데이터에 작성할 수 있다. 고려 갱신은 `Pocket Caravan > 고려 > 교역 역할·선택 의뢰 갱신`. 공용 시작 세트 초기화는 필요 없다.

## 다섯 거점은 서로 다른 선택을 담당한다

| 거점 | 첫 방문 이유 | 다시 갈 이유 / 확인할 선택 |
|---|---|---|
| 예성 나루 | 출발·소금·첫 운반 | 개경 왕복과 게시판 화물을 겸할지. 초기 정체성을 선착장/하역으로 보여 주기 |
| 개경 | 첫 도착·여러 상품·고객 | 생산 마을의 판매처, 신용3 보관. 모든 거래를 수도에서만 하는 게 우월해지지 않는지 |
| 닥목 | 종이 공급·종이 구매 과제 | 장단 땔감 수요와 종이 귀환품. 송악으로 큰길/산록을 비교 |
| 송악 산록 | 가벼운 약재 선택 장사 | 적은 적재량과 높은 매입 자금의 교환, 산록 순환과 큰길의 선택 |
| 장단 들마을 | 곡식·땔감 공급 | 등짐 곡식과 수레 대량 운송, 닥목에서 싣는 귀환품, 중간권 출발 준비 |

거점 구조는 이 정도가 적절하다. 여섯 번째 마을의 조건은 기존 다섯 곳이 담당하지 못하는 **상품/시설/지리의 선택**이 확인되는 것이다. 매번 쉬기만 하는 휴게 마을은 현재 걷기 체력 회복과 겹쳐 방문 이유가 약하다. 경치 목적은 길가 쉼터·하역장·작업터처럼 기존 맵 안의 작은 공간으로 먼저 해결한다.

마을 수를 유지한 대신 기존 미술 마감은 남는다. 나루의 하역·수도 시장·닥목 생산·산록 집산·장단 들판을 같은 건물 배열의 이름 변경으로 끝내지 않는다. 임시 동물 NPC 그림과 최종 사람 NPC 방향도 별도 미술 작업이다. 실지명/산록/강변 모티브를 사용한 각색이며 실제 역사적 생산지 복원으로 설명하지 않는다.

## 성장의 질: 수치가 아니라 가능한 행동

| 변화 | 플레이어가 새로 해 볼 행동 | 부족한 점 / 평가 |
|---|---|---|
| 신용0 → 1 | 길 안내소에서 새로운 거래처·수단별 길을 이해 | 고정 정보가 수첩과 얼마나 다른 가치가 있는지 약함. 고려 출신 정보 능력과 공통 안내소를 혼동하지 않음 |
| 등짐10 → 손수레30 | 무게16 땔감, 배달+자유 상품, 왕복 적재량 구성 | 단순 세 배 이익이 아님. 구입비·매입자본·혼합 화물과 길 차이를 평가 |
| 신용3 | 객주 분산 보관·귀한 배달 제안 | 창고는 현지 회수. 원격 배송/자동 판매 아님. 맨손 소량 거래만 하면 필요성이 약함 |
| 시세·지형 학습 | 귀환 상품, 돌아가는 길, 보수와 시세 차익 비교 | 익숙해진 뒤 같은 선택만 반복되면 새 해금 없이 피로가 빠르게 옴 |

초반 두 퀘스트 이후 송악/장단/수레를 고를 수 있다는 장점은 유지한다. 다만 정상 재고 기준 시작100 + 첫 보상30 + 종이 의뢰45 − 종이2개26 = **149냥**, 손수레150냥이다. 초반 과제 뒤 작은 추가 수입 하나면 구입 가능하다. 기존 ‘첫 수레12~25분’은 경제적으로 강제되는 시간이 아니다. 조작·학습 시간 포함 실제 측정 전에는 목표 달성으로 쓰지 않는다. 신용도 첫 두 과제로2가 되므로 선택 의뢰/성공 배달 하나면3이다. 새 숫자 문턱을 올려 분량을 부풀리는 대신, 이후 수레·보관을 쓴 다른 왕복 장사가 성립하는지를 본다.

## 배달·퀘스트·매매를 함께 했을 때 발견한 경제 문제

현재 일반 배달은 `(14 + 16×경제 좌표 거리 + 3×무게) × 0.85~1.15`, 빠른 납품은 보수의15% 추가다. 개경→닥목은 가격용 거리1이다. 무게2~6의 일반 제안은 반올림 전 **30.6~55.2냥** 범위이고 팁이 더해질 수 있다. 반면 정상 재고에서 송악 인삼2의 차익12, 장단 곡식3 차익16, 닥목 종이2 귀환 차익9다. 좌표 거리는 실제 이동 초와 다르다.

따라서 짧은 배달만 골라 성장할 가능성이 있다. 아직 랜덤 게시판 재생성·수락 가능한 물량·자유 교역 재고·NPC 거래까지 포함한 평균 수익을 측정한 값은 아니다. 이 비교만으로 모든 배달이 항상 우월하다고 단정하지 않는다. **이번에는 공용 배달 보수·타 지역의 동시 개발 경제를 임의로 변경하지 않았다.** 다음 공통 경제 패치의 우선 항목으로 기록한다.

조정 기준안(미적용): 같은 경로·화물·실제 왕복 시간에서 일반 배달은 ‘매입자본 없이 안정적으로 돈을 버는 선택’, 자유 교역은 ‘매입 위험을 지고 더 좋은 기대 수익을 찾는 선택’이 돼야 한다. 적재 공간을 모두 배달로 채우는 행동이 모든 자금 수준에서 최선이면 실패다. 보수는 기본 생활비와 화물·경로 작업량으로 분리하고, 재기 의뢰1건의 실용성은 유지한다. 단순히 모든 보수를 일괄 삭감하는 안은 채택하지 않는다.

같은 땔감4단 납품을 가르치는 구 S1과 새 장단 공급 의뢰도 반복성이 있다. 기존 저장 진행은 유지하되, 추후 공통 Q1~Q7 정리에서 입문 안내는 하나로 묶고 다른 하나는 공급처/왕복 적재의 응용으로 차이를 만들어야 한다. 퀘스트 개수를 플레이 분량으로 합산하지 않는다.

## 이동 거리와 흥미를 맞추는 기준

실측 플레이 시간 아님: 직교 최단 경로·짐5·가감속/달리기/NPC/조작/로딩 제외 계산에서 개경↔닥목 편도13.3초, 개경↔송악19.0초, 닥목↔장단19.4초(등짐). 나루→장단59.2초, 장단→중간권 버들나루64.5초다. 전체 결과는 `Tools/Integration/analyze_journey.py`와 기존 검증 기록을 따른다.

- **짧은 익숙한 길:** 매번 사건/대사로 막지 않는다. 남는 적재량, 같은 방향 배달, 돌아올 상품이 주요 판단이다. 진입 전에 목적지와 분기를 읽게 한다.
- **새 길:** 산록·두 다리·들판 작업·강변 같은 구간 차이를 멀리서 알아보게 한다. ‘출발 준비 → 길 분기 → 지형 변화/짧은 발견 → 거점 도착 → 다음 짐 선택’의 리듬을 만든다.
- **긴 길:** 1분 동안 방향 입력만 유지하는지 직접 관찰한다. 그런 구간이 있다면 경로를 단축하거나 기존 구간에 우회/적재별 선택과 도착 예고를 배치한다. 대사/장애물을 일정 간격으로 강제하는 방식은 피한다.
- **재방문:** 매회 랜덤 통행 차단 대신 시세/재고와 운반 구성을 먼저 바꾼다. 수레 구입 후 실제로 다른 길을 선택하는지 본다. 현재 산록 순환은 등짐/손수레의 최단 선택이 다르게 계산되지만 사람의 선택 검증은 남았다.
- **탐험:** 필수 교역로에서 잠깐 벗어난 관찰 공간은 귀환 동선과 연결한다. 일회 현금 줍기 반복이 본업 교역보다 유리해지는 수집 루프는 추가하지 않는다.

몇 초마다 보상을 주면 재미있다는 보편 법칙은 없다. 거리마다 의무 사건을 배치하거나 길을 길게 만들어 문명 간 거리를 대신하지 않는다. 다른 문명까지 여러 중간 구역을 지나가는 장기 구상도 유지한다.

## 설계 참고와 적용의 경계

- [Hunicke·LeBlanc·Zubek, MDA 원문](https://www.cs.northwestern.edu/~hunicke/MDA.pdf): 규칙, 실제 상호작용, 플레이어 경험을 구분하고 기능 간 영향을 반복 검증한다. 여기서는 ‘창고가 있다’와 ‘돌아올 짐을 위해 보관하는 재미가 있다’를 따로 평가하는 데 적용했다. 공식이 재미나 적정 분량을 보장하지 않는다.
- [inkle의 80 Days 공식 소개](https://www.inklestudios.com/80days/): 경로 계획, 다양한 이동수단, 도시와 선택이 여정을 구성한다. 고려에는 목적지까지의 기대와 수단에 따른 경로 선택을 참고한다. 시간 경쟁·150도시 분량을 복제하지 않는다.
- [Offworld Trading Company 배급사 소개](https://www.stardock.com/games/article/454369/introducing-offworld-trading-company-from-mohawk-games): 변하는 플레이어 주도 시장에 전략을 조정하는 경제 게임이다. 우리 게임에는 공유 시세가 재방문 결정을 바꾸는지 평가하는 참고로 사용한다. 해당 게임의 실시간 경쟁 강도를 그대로 적용하지 않는다.

## 다음 검증: 첫 왕복과 세 번째 왕복을 나눠 보기

아래는 구현 완료 표시가 아니라 팀 플레이 관찰 절차다. 치트/개발자 설명 없이 같은 빌드와 새 저장으로 진행한다. 인원은 우선3명 이상, 플레이 성향이 다른 사람이 좋다. 이 소규모 관찰로 통계적 시장 균형/대규모 접속을 입증하지 않는다.

1. 첫 두 과제 후 NPC가 시키지 않은 다음 장사/거래처를 본인이 선택하는가? ‘다음에 뭘 할지 모르겠다’는 지점과 수첩 사용을 기록한다.
2. 같은 출발지에서 가벼운 약재/생활재/게시판 중 선택 이유를 묻는다. 순수 매매 손익과 퀘스트 보수·배달 팁은 따로 기록한다.
3. 첫 수레 직전과 직후 같은 경로의 품목·물량·자금 잔액·적재량·시간을 기록한다. 모든 현금을 수레에 써서 매입이 막히는지 본다.

# 아라비아 지역 제작 계획표

작성: 2026-10-20 | 담당: 은인 | 상태: 검토용 제안

## 1. 제작 목표

기존 Pocket Caravan의 이동·매매·의뢰·저장 구조에 아라비아 지역을 추가한다. 핵심 경험은 **어떤 상품을 얼마나 싣고, 어느 길로 운반하고, 어디에 나눠 팔 것인가**다. 아라비아의 적재 강점이 이 선택에 도움을 주도록 만든다.

이번 산출물은 계획이다. 게임 코드·에셋·원본 PDF는 변경하지 않았다. 다음 작업은 원본과 같은 구성의 「초반 공통 시나리오 — 아라비아 버전」 작성이다.

## 2. 확인한 근거와 미확인 사항

| 구분 | 확인 내용 | 계획에 미치는 영향 |
|---|---|---|

| GitHub 현재 상태 | 공개 웹 조회 실패, 비인증 API는 404 응답 | 권한 있는 연결에서 main·지역 브랜치·PR 확인이 0단계 선행 작업 |

로컬 자료의 ‘사용자=고려 담당’ 같은 이전 작성 문맥을 현재 사용자에게 적용하지 않는다. 이번 요청의 담당 지역은 아라비아다. 최신 회의가 별도로 더 있었다면 그 내용과 이 계획을 대조해야 한다.

## 3. 유지할 방향과 바꿀 내용

- 유지: 따뜻하고 귀여운 교역 게임, 선대의 운반 도구와 장부, Q1·Q2 필수 후 자유 의뢰, Q7 운반 수단 구매.
- 유지: 발전된 지역에서 시작, 수도 1개와 수도 외 마을 최소 4개, 최소 한 구간에 의미 있는 두 경로.
- 유지: 지역별 동물 종과 색상 변형. 구체적인 종은 아직 제안 단계.
- 변경: 낙하·줍기·흔들림 게이지를 요구하는 Q3는 정직·신용 중심으로 재작성.
- 변경: Q4는 고려의 조기 정보 대신 아라비아의 적재·대량 운송을 체험.
- 변경: Q7은 촌락이 수도로 발전하거나 모든 이동 관문을 여는 사건이 아니라 운반 능력의 성장으로 마무리.
- 미확정: 동물 플레이어+사람 NPC는 기존 회의의 1안. 최종 채택으로 간주하지 않고 대표 화면으로 비교.
- 별도 합의: 출신 배율, 가격·보수, 정확한 마감일, 지명·역사 모티브, 외부 접속부·좌표.
- 후순위: 낙타 탑승, 환율, 집 꾸미기, 염색 UI, 길드, 음성 채팅, 새로운 날씨 생존 시스템.

## 5. 아라비아 장면의 제안 방향

**‘텅 빈 사막’보다 ‘오아시스와 시장을 잇는 생활 교역로’**를 중심으로 잡는다. 아래 명칭은 공간 역할을 정하기 위한 작업명이다. 최종 표시명은 회의의 실제 지명 방향에 맞춰 역사·지리 근거를 확인한 뒤 정한다. 현실의 수도 관계나 실제 거리라고 주장하지 않는다.

| 거점 | 플레이 역할 | 화면의 핵심 요소 | 상품 역할 후보 |
|---|---|---|---|
| 시작 오아시스 마을 | 안내·첫 배달·초급 시장 | 우물, 그늘 천막, 낮은 담, 야자수, 게시판 | 대추야자 등 저가 소모품 |
| 농원 마을 | 첫 구매처·안전한 왕복 | 농원, 물길, 수확 바구니, 작업 마당 | 저가 대량 상품의 산지 |
| 공방 마을 | 신용 의뢰·가공품 | 직물 천막, 작업대, 항아리·천 꾸러미 | 직물·생활 공예품 |
| 교역 중계 마을 | 먼 배달·수레 구입·길 분기 | 숙박 안뜰, 짐 검사대, 창고, 수레 수리 공간 | 운송 의뢰·중간 판매처 |
| 수도 시장 | 큰 수요·고급 시설·판매처 선택 | 밀도 높은 시장, 아치 통로, 창고, 상인 시설 | 여러 산지 상품의 소비처 |

연결 초안: 시작 마을↔농원 마을로 Q1·Q2를 배우고, 공방·중계 마을·수도로 넓힌다. 중계 마을→수도 구간은 **멀지만 넓고 안정적인 길 / 짧지만 감속과 도적 위험이 있는 길**로 분기한다. 짐이 가벼울 때와 무거울 때 선택이 달라지는지 비교한다. 정확한 길 씬 수와 좌표는 2단계에 결정한다.

첫 화면은 입구에서 우물과 시장이 보이고, 그늘 아래 안내 NPC와 게시판이 있으며, 화면 한쪽으로 첫 배달 길이 읽히게 한다. 큰 장식이 길·NPC·상호작용 표시를 가리지 않게 한다. 건물은 실루엣과 천막 색으로 역할을 구분한다. 사막의 모래색, 진흙색 건물, 청록·남색 천막을 후보 팔레트로 삼되 기존 지역과 같은 명도·외곽선·픽셀 밀도를 유지한다.

사막 감속은 우선 기존 노면 규칙으로 표현한다. 갈증·모래폭풍·낙타 조종은 첫 버전 필수 기능으로 늘리지 않는다. 낙타는 필요하면 배경 소품 후보로 두고, Q7은 기존 공통 손수레와 연결한다.

## 6. 캐릭터와 에셋 제작 순서

주인공 후보는 **모래고양이 계열의 작은 동물 상인**을 1안으로 제안한다. 종의 최종 확정이나 역사 주장으로 보지 않는다. 천 가방·조끼·묶은 짐으로 상인 역할을 읽히게 하고, 적재 강점은 상단의 포장·운송 노하우로 설명한다.

1. 기존 캐릭터·타일의 실제 임포트 설정을 기준표로 고정한다. 로컬 문서 기준은 타일16px/PPU16, 캐릭터16×24이며 임의로48×48로 교체하지 않는다.
2. 주인공1명+안내 NPC1명+상인1명을 기존 배경 위에 비교한다. 사람 NPC 1안의 비율도 이 화면에서 판단한다.
3. 기준 정면1장 승인 후 현재 컨트롤러에 맞는 방향·걷기 프레임을 제작한다. 다양한 의상부터 양산하지 않는다.
4. 투명 배경, 기준 발 위치, 프레임 크기, 픽셀 경계, 팔레트, 짐의 가림과 충돌체를 검수한다.
5. 시작 마을 건물·천막·우물·야자수·상자·가마니·수레·상품 아이콘을 작은 세트로 제작한다.
6. 실제 씬에서 검수한 세트를 재사용하고, 수도·농원·공방에 필요한 차이만 추가한다.
7. 각 파일에 용도·원본·출처/사용 조건·임포트 규격을 기록한다. AI 콘셉트 이미지는 그대로 타일맵이나 애니메이션으로 쓸 수 있다고 가정하지 않는다.

AI 이미지 작업은 구도·색감·복장 후보에, 실제 게임 적용은 픽셀 정리·프레임 일관성·Unity 검수에 나눠 사용한다. 이미 있는 공용 에셋은 재사용 가능 여부부터 확인한다.

8개 공통 역할은 길잡이, 마을 어른, 첫 의뢰인, 정직 시험관, 먼 마을 의뢰인, 길 위 위협, 라이벌 상인, 운반 수단 판매자다. 역할 수와 실제 NPC 개체 수는 다를 수 있다.

옛이야기는 다음 단계에서 출처와 지역적 맥락을 조사해 핵심 모티브를 선택한다. 유명 캐릭터 이름만 교체하거나 특정 현대 작품의 디자인을 복제하지 않는다. 이름·대사·실지명은 아직 이번 계획에서 확정하지 않는다.

Q1·Q2 약5분, 자유 구간10~20분은 원본의 설계 목표로만 사용하고 실제 시간을 측정한다. 퀘스트7개를 모두 강제 완료하게 만들지 않는다. 반복 의뢰·자유 교역으로도 수레 자금을 모을 수 있게 한다.

## 8. AI에 작업을 맡기는 단위

매번 한 개의 확인 가능한 결과물을 요청한다. 공통 입력은 기준 문서·소스 커밋·수정 허용 범위·완료 기준이다. 응답에는 변경 파일·실행법·검사 결과·미완료 사항을 요구한다.

### 바로 다음에 사용할 요청문

> 아라비아 제작 계획표와 첨부 고려 PDF를 바탕으로 「초반 공통 시나리오 — 아라비아 버전」을 작성해 줘. 원본 목차와 Q1~Q7 학습 흐름을 유지하되, 최신 회의의 수도1+마을4·자유 이동/신용 시설 해금·낙하 제외·적재 특화를 반영해 줘. 등장인물8개 역할, 상품·장소·대사, 퀘스트 완료 조건과 시스템 대응표를 포함해 줘. 실제 지명과 옛이야기는 근거를 확인하고 창작 부분을 구분해 줘. 확정되지 않은 가격·능력 배율은 제안으로 표시하고, 공통 코드 추가가 필요한 부분을 따로 적어 줘. 이번에는 시나리오 문서까지만 만들고 게임 코드는 수정하지 마.

### 이후 반복할 작업 카드

- 목표: 예) Q1 배달 한 번을 완주할 수 있게 만들기.
- 읽을 자료: 승인된 시나리오·ID표·현재 공통 API.
- 변경 범위: 아라비아 파일과 명시적으로 합의한 공용 참조.

- 납품: 변경 파일, 테스트 절차, 대표 화면, 발견한 공용 문제.

## 9. 팀 통합에서 먼저 확인할 것

- 올바른 pocket-caravan 저장소에서 기준 커밋을 고정하고 아라비아 작업 브랜치를 사용한다. 기존 팀원 브랜치를 폴더 복사로 덮어쓰지 않는다.
- 새 ID는 arabia_ 접두어 제안에 맞춘다. 기존 origin ID arabia, 공통 walk/handcart를 무조건 새 이름으로 바꾸지 않는다.
- 지역 등록은 World/Regions/arabia.json, 지역 데이터·씬은 기존 지역별 구조를 따른다. 빈 등록 파일만 먼저 넣지 않는다.
- GameDatabase에는 지역 콘텐츠를 추가하되 다른 지역 목록을 삭제하지 않는다. 공용 파일 담당과 조율한다.
- 문서의 아라비아 x=20~29는 제안이다. 좌표는 가격 계산에도 영향을 주므로 확정 배치처럼 적용하지 않는다.
- 출구·목적 씬·도착 스폰·역방향 연결·수레 통과 폭을 표로 맞춘다. 아직 없는 외부 씬을 출구로 연결하지 않는다.
- Python/JSON/수작업 씬 중 기준 원본을 정한다. 전체 재생성이 팀원 씬을 덮어쓰지 않도록 자기 맵 선택 생성 절차를 쓴다.
- ‘시작 세트 만들기’는 일반 실행 절차가 아니다. 공용 데이터가 초기화될 수 있다.
- 비시작 씬 직접 Play는 현재 저장이 꺼지는 방식이다. 아라비아 독립 시험과 실제 시작/출신 선택/저장 검사를 구분한다.
- 게시판은 같은 지역의 연결된 마을만 목적지로 허용한다. 공통 퀘스트의 지역·장 자격은 별도 확인한다.
- 출신 선택·적재 한도·UI·구매 허용·저장 복원은 같은 계산을 써야 한다. 지역 스크립트에 별도의 보너스 공식을 만들지 않는다.
- 북유럽에서 기록된 DB 누락·이벤트 저장·Q6 판정 문제를 아라비아에서도 검수한다. 최신 수정 상태는 PR 확인 후 기록한다.
- 온라인은 로컬 문서상 미구현이다. 아라비아 담당에게 서버 전체 구현을 자동 배정하지 않는다. 공통 담당과 최소 지역 데이터/이벤트 저장 계약을 먼저 맞춘다.

## 10. 완료 판정

1. 수도1+마을4가 연결되고 각각 교역·시설 역할이 있다.
2. Q1·Q2→자유 의뢰/거래→Q7을 실제 플레이로 끝낼 수 있다.
3. 두 경로가 적재량·시간·위험에 따라 다른 선택을 만든다.
4. 아라비아 적재 특화는 기존 장거리 판매 보너스와 의도치 않게 중첩되지 않는다.
5. 수레 구매 전후의 실운반량·왕복 시간·순이익을 비교한다. 판매 총액을 이익으로 잘못 세지 않는다.
6. 돈 부족·의뢰 실패 후 반복 의뢰로 재기할 수 있다.
7. 저장 후 재시작해 돈·짐·출신·퀘스트·이벤트가 유지되고 중복 보상이 없다.
8. Python 통합 검사, Unity 지역 등록 검사, 실제 출구 왕복·거래·저장 검사를 수행한다. 이 문서 작성 중 게임 실행 검사는 하지 않았다.
9. 기존 고려 및 통합된 팀원 지역의 시작·거래·저장이 깨지지 않는다.
10. 소스·.meta·버전·시작 방법·대표 화면·검사 결과·알려진 문제를 함께 전달한다.

# 회의 기준 — 은인의 아라비아 담당 범위와 작업 방향

정리일: 2026-10-22. 클로드에게 전달할 작업 기준.

## 이 문서의 근거와 우선순위

확인한 자료는 `Docs/Meetings/2026-10-16.md`와 `Docs/DesignUpdate_2026-10-17.md`다. 이후 회의가 있었다면 그 내용은 아직 이 문서에 포함되지 않았다. 이 문서를10월22일에 새로 열린 회의의 회의록으로 취급하지 않는다.

사용자가 지금 설명하는 요구 → 날짜가 확인되는 후속 결정 → 회의 메모 → 이전 시나리오/AI 제안 순으로 대조한다. 기록의 확정도와 시점이 불명확하면 한쪽을 임의 확정하지 말고 충돌을 명시한다. 회의의 방향 결정은 해당 기능의 구현 완료를 뜻하지 않는다.

## 1. 누가 무엇을 맡는가 — 회의 기록

| 구역 | 담당 | 지역 |
|---|---|---|
| A | 은샘 | 고려 |
| B | 윤채 | 베네치아 |
| C | 은인(현재 사용자) | 아라비아 |
| D | 기우 | 바이킹/북유럽 |

은인의 명시된 책임은 아라비아 지역이다. 지역코드C를 다른 문서의 ‘C=NPC·마을 공통기능 담당’과 혼동하지 않는다. 네트워크·경제·UI 전체 담당이 은인으로 정해진 것은 아니다. E/F는 대륙의 마을·길 요소를 가리키며 추가 담당자가 아니다.

## 2. 아라비아에 반드시 반영할 팀 방향

| 회의·후속 결정 | 아라비아 제작에 적용할 기준 | 아직 정하지 않은 것 |
|---|---|---|
| 발전된 지역에서 시작 | 기존 생활과 상업이 보이는 마을/수도를 구성한다 | 건물 수·세부 시설 배치 |
| 수도1개+수도 외 최소 마을4개 | 지역 완성 목표는 다섯 거점이다 | 각 지명·등급·시설의 구체 배정 |
| 마을은 자유롭게 이동 | 신용 때문에 마을로 가는 길 자체를 일괄 잠그지 않는다 | 외부 문명 접속 규칙 |
| 신용에 따라 시설·고급 거래 이용 | 기본 교역과 개인 성장에 따른 시설 이용을 나눈다 | 신용 임계값·고급 거래 품목 |
| 주어진 길을 통과하는 운반 | 길 개척은 넣지 않고 기존 길의 선택과 위험을 만든다 | 수리·호위·통행료 각각의 제작 범위 |
| 두 개 이상 루트와 탐험 | 적어도 대표 구간에서 다른 경로를 비교할 수 있게 한다 | 경로 길이·구체 사건·보수 |
| 지역에 따라 풍경 변화 | 아라비아와 연결 구간의 기후·생활 풍경을 드러낸다 | 중간 구역 담당·분담량 |
| 스타팅 지역별 동물 종, 색상 다양화 | 아라비아 주인공의 종과 색상 방향을 정한다 | 종 이름·선택 UI·변형 수 |
| 실제 지명 사용 | 지명 근거를 확인하고 거리·위계 각색을 구분한다 | 아라비아의 최종 지명 |
| 돈·신용·명성 | 거래/의뢰가 성장으로 이어지게 한다 | 명성 획득·소비 세부 규칙 |

지형 사건으로 끊어진 다리·쓰러진 나무·점령된 길 등이 회의에서 언급되었다. 이것을 모든 종류의 장애물, 실시간 수리, 공유 세계 영구 변경을 전부 구현하라는 결정으로 확대하지 않는다. 핵심은 위험·비용·이익을 비교해 배달하는 경험이다.

## 3. 10월17일 후속 결정 — 옛 시나리오보다 우선

출신 역할은 **고려=정보 / 아라비아=적재 / 베네치아=판매·중개 / 북유럽=범용 이동**이다.

아라비아는 ‘짐을 더 실어 대량 수송을 선택할 수 있는’ 역할로 설계한다. 구코드의 장거리 판매+5%를 최종 능력으로 사용하지 않는다. 적재 배율·적용 수단·조건은 아직 미확정이다. 새 능력을 붙일 때 적재 판정·구매·의뢰 수락·UI·저장과 공통 계산을 맞추고 구 보너스의 의도치 않은 중첩을 확인한다.

운반은 **노면·짐 무게·운반 수단에 따른 감속 중심**이다. 주행 낙하, 반복 줍기, 누적 흔들림 게이지, 정차 안정화 강요를 다시 넣지 않는다. 감속을 보여 주는 시각적 흔들림은 허용된다. 이 결정이 도적 강탈·의뢰 실패 등 모든 손실을 없앤다는 뜻은 아니다.

적재량이 늘어도 시장에 한꺼번에 팔면 가격이 떨어질 수 있다. 따라서 상품·수요처·분산 판매·운송 의뢰를 함께 설계하고, 판매 총액보다 실제 순이익과 왕복 시간으로 효과를 검증한다.

## 4. 은인이 제작할 산출물 — 회의 방향을 작업으로 풀어 쓴 목록

아래는 지역 담당을 수행하기 위한 작업 분해다. 별도의 팀 공통 담당 확정을 의미하지 않는다.

1. **아라비아 공간:** 수도1+마을4, 거점별 역할·시설, 지역 내 교역로, 경로 선택 구간.
2. **지역 교역 데이터:** 상품·공급/소비처·시장·의뢰·신용 시설. 가격/적재 공식은 공통 시스템과 연결.
3. **초반 공통 시나리오의 아라비아판:** 공통 학습 흐름을 유지하며 인물·물건·장소·대사를 지역에 맞게 각색.
4. **캐릭터와 환경:** 지역 동물 종 후보, 아라비아의 건축·식생·생활 소품과 교역 풍경. 최종 스타일은 대표 화면에서 검토.
5. **지역 콘텐츠 검증:** 출구 왕복, NPC 접근, 배달/매매/성장, 실패 후 재기, 저장과 재접속 범위 확인.
6. **팀 전달:** 원본 맵·JSON·씬·.meta·ID/연결표, 공용 파일 변경 목록, 실행 방법과 실제 검사 결과.

공통 서버·전체 UI·다른 세 지역·모든 중간 구역을 혼자 완성하는 책임으로 확대하지 않는다. 공통 기능이 필요하면 접점과 변경 이유를 분리해서 기록한다.

## 5. 공통 시나리오 — 기본 틀과 수정할 부분

Q1·Q2로 배달과 구매 후 납품을 배우고, Q3~Q6·반복 의뢰·교역을 선택하여 자금을 모은 뒤 Q7 손수레 구입으로 성장한다. 이는 공통 시나리오 초안의 틀이며 플레이 시간·금액은 실험으로 조정한다.

- Q3: 정직/신용 경험은 살릴 수 있으나 원문의 낙하·회수 장면은 최신 결정과 충돌하므로 재작성한다.
- Q4: 고려의 빠른 소식 대신 아라비아 적재·물량 선택을 체험하게 구성한다.
- Q5: 길의 거리·노면·위험을 비교한다.
- Q6: 재고/경쟁/판매처 선택을 다룬다. 단순 판매 총액을 순이익으로 판정하지 않는다.
- Q7: 운반 능력 성장으로 마무리한다. 수도가 작은 촌락이었다가 생겨나거나 모든 마을 길을 일괄 개방하는 옛 연출은 자유 이동·발전된 지역 설정에 맞춰 바꾼다.

## 6. 팀 확정으로 오해하면 안 되는 AI 제안

다음은 이전 AI가 제시한 제작안이며 회의의 확정 사항이 아니다.

- 모래고양이 주인공.
- 알 아흐사/자비드/타이즈/제다/사나를 현재 순서·역할로 배치한 지도.
- 힌드바드·마리암 등 구체 NPC 구성과 창작 대사.
- Q1보수20, Q2보수30, 상품 무게·재고·가격, 좌표x20~22.
- 전체10씬, 길5개라는 구체 수량.
- 사람NPC는 과거 사용자 지정 ‘1안’이며 최종 채택으로 확인되지 않았다.

현재 구현에서 이런 제안을 사용했더라도, 사용자가 원하는 모습과 다르면 교체할 수 있다. 다만 표시 이름 변경과 저장 참조용 ID 변경은 분리하고 기존 진행 데이터를 보호한다.

## 7. 현재 작업에 어떻게 적용할 것인가

2026-10-21 Claude 작성 STATUS.md와04 구현 결과에는 아라비아3개 씬과Q1·Q2 생성, 자동검사 통과가 보고되어 있다. 이번 문서 작성에서는 그 보고서를 읽었으며 검사를 재실행하지 않았다. 더 이상 ‘아라비아 씬0개’였던 과거 인수인계 상태로 되돌리지 않는다. 실제 현재 파일과 보고서를 대조하여 이어 간다.

첫3씬은 개발을 나눈 첫 단계다. 최종 담당 범위가 마을2개로 줄어든 것이 아니며, 현재 임시 너구리/공용 건물/대체 나무가 최종 아라비아 캐릭터·환경으로 승인된 것도 아니다.

다음 순서로 보완한다.

1. 현재 씬을 보존한 채 이 문서와 비교하여 ‘반영됨 / 임시 대체 / 미구현 / 요구와 충돌’ 표를 작성한다.
2. 사용자가 불만을 말한 외형·동선·플레이 경험을 우선 확인한다. 자동검사 통과가 시각적 만족이나 재미를 보장하지 않는다.
3. 대표 시작 화면에서 아라비아 배경·캐릭터·상점·배달 동선이 읽히도록 보완한다. 참고 이미지가 없으면 확정된 스타일이라고 주장하지 않는다.
4. 첫 구간을 유지하면서 수도와 나머지 마을, 두 경로, 선택 의뢰와 적재 특화의 남은 작업을 순서대로 연결한다.
5. 별도 아라비아 씬, ID/GUID 보존, 공용 데이터 추가 병합, 전용 저장을 유지한다. 다른 지역을 덮어쓰지 않는다.

환율·집 꾸미기·염색·길드·음성·PvP는 회의의 아이디어/후순위다. 현재 모든 기능을 필수로 동시에 추가하지 않는다. 텍스트 채팅 우선이라는 팀 방향도 은인에게 공통 채팅 시스템 전체를 자동 배정한 것은 아니다.

## 클로드에 바로 보낼 메시지

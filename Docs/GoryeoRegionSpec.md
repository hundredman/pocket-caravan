# 고려 스타팅 지역 제작 명세

> 현재 구현/검사는 [진행표](DevelopmentStatus.md), 문서 우선순위는 [문서 안내](README.md)를 따른다.

기준일: 2026-10-17. **수도 1개 + 수도 외 최소 마을 4개, 이미 발전한 지역, 자유 이동·등급/신용별 시설 이용**은 사용자 재확인 범위다. 기존 네 맵 마감만으로 대체하지 않는다. [전체 재대조](FullRequirementsReview_2026-10-17.md)와 [최신 변경](DesignUpdate_2026-10-17.md)을 함께 적용한다. 아래 지명 후보·개별 등급 배정·시설 효과/가격은 제안이며 확정값이 아니다.

## 1. 목표와 현재 재고

| 구분 | 현재 정적 확인 | 목표 |
|---|---|---|
| 수도 | `Town_Gaegyeong` / Gaegyeong | 개경 1곳. 처음부터 수도로 읽히는 규모/시장/시설 |
| 마을 | `Town_Naru`, `Town_Dakmok`, `Town_GoryeoSongak`, `Town_GoryeoJangdan` 4곳 | 수도 외 최소4곳. 기존2곳 적합성 보완 + 최소2곳 추가 |
| 길 | Route01·구릉길·산기슭 길·들길 4맵 | 거점 사이 분기/합류와 경유 구간. 마을 수에 포함 안 함 |
| 합계 | 9맵 = 수도1+마을4+길4 | 최소5개의 독립 거점. 한 거점의 여러 씬을 별도 마을로 중복 집계 안 함 |
| 이용 제한 | 로컬 쉼터/정보/창고의 기본 등급·개인 신용 판정 구현 | 시설 존재/마을 등급 + 개인 신용 + 기능별 조건을 함께 판정 |

거점이란 독립 townId와 지역 참조, 통행 가능한 진입, 교역/생활 역할, 시설 구성이 있는 정착지다. 도로 한복판 노점·새 씬 이름·성문을 추가한 것만으로 마을 하나를 채웠다고 하지 않는다. 반대로 다섯 거점이 반드시 다섯 씬이어야 하는 것은 아니며 현재 씬 단위 제작과 수정 안전성을 고려한다.

## 2. 거점별 구성표 — 역할 배치 제안

| 자리 | 기존 참조/이름 상태 | 구분할 역할과 환경 | 공급·소비/귀환 이유 | 시설 배정에서 확인 |
|---|---|---|---|---|
| 수도 | 개경 / 기존 ID 유지 | 시전·집산·고급 거래·성문/궁성 경계 | 다품목 소비·재분배. 인삼/나전의 집산과 역사 생산지 구분 | 상위 시설/거래를 보여 주되 저신용도 기본 매매 가능 |
| 마을1 | 예성 나루 / `naru` 호환 | 강변 하역·생활재·여행 준비 | 소금/생활재 유통과 생산지 화물 집산 | 입문 게시판·기본 교역·운반 준비. 실제 벽란도로 개명할지는 고증/연결 검토 |
| 마을2 | 닥목 / `dakmok` 호환 | 종이 재료/가공/건조·하천변 | 종이 공급, 생활재/재료 수요 | 생산지 의뢰와 중간 시설. 창작명은 실제 지명 채택 방향과 재검토 |
| 마을3 | 송악 산록 마을 / 실지명 모티브 각색 | 산록의 약재·인삼 유통 거점 후보 | 가벼운 고가 화물 공급·생활재 소비 후보 | 가벼운 등짐으로 갈 가치와 신용별 거래 후보 |
| 마을4 | 장단 들마을 / 실지명 모티브 각색 | 고개/농업 장터·수레 경유 거점 후보 | 곡식·땔감 등 공급과 종이/소금 소비 후보 | 장거리 준비·수레 운송·중간 거래, 상위 거점과 다른 기능 |

마을3/4의 지명·정확한 생산품은 아직 근거가 없어 실존 생산지라고 확정하지 않는다. 한 곳만 특별상품 나머지는 무의미한 통과점이 되지 않게 기본 매매와 귀환 화물을 설계한다. 지도 위치/마을 tier가 같아도 역할은 구분할 수 있다. 모든 상품을 새로 만들 필요는 없고 공통 생필품과 기존6품목을 재사용해 먼저 시험한다.

## 3. 마을 등급과 개인 신용

확정된 것은 **등급별 시설 차이 + 개인 신용에 따른 이용 제한**이다. 네 마을을 꼭1/2/3/4로 하나씩 배정한다거나 수도 등급을4로 확정한 것은 아니다. 개별 등급 배정·신용 문턱·시설별 범위는 이 문서 표를 채워 관리한다. 도로 등급0~3·상인 운반 단계·정착지 등급을 섞지 않는다.

권장 정책:

`이용 가능 = 이 거점이 해당 시설을 제공함 AND 요구 마을 등급 충족 AND 개인 신용 충족 AND 기능별 자금/수량/진행 조건 충족`

- 마을 방문·지도 탐험·기본 상품 매매·재기용 일반 의뢰는 시설 해금과 구분한다. 저신용이라고 수도 출입구나 전체 시장을 막지 않는다.
- 마을의 기본 등급/시설 보유는 지역 콘텐츠다. 개인 신용은 플레이어 상태다. 한 사람의 해금이 모든 이용자를 해금하지 않는다.
- 현재 `MarketState.Level`은 누적 거래액으로 오르는 **기존 시장 성장값**이다. 이를 그대로 신용으로 바꾸거나 모든 마을을1등급으로 낮추지 않는다. 기본 tier와 성장의 관계를 먼저 명시하고 기존 저장 level을 이주한다.
- ‘이미 발전한 지역’은 거래량에 따른 모든 시각 변화를 폐기했다는 뜻은 아니다. 다만 촌락 개경의 승급과 Q7 관문 개방을 핵심 진행으로 유지할 수는 없다.

### 시설/고급 거래 배정표 — 원안에서 재검토할 후보

| 단계적 제공 | 기능 후보 | 처음 이용/잠김의 구분 | 이번 제작에서 필요한 결정 |
|---|---|---|---|
| 모든 거점의 기본선 | 소량 매매·일반 게시판·가격/적재 안내 | 낮은 신용/돈0에서도 합법적 재기 통로 | 기본선은 신용으로 전부 막지 않음 |
| 입문 거점 | 수레 판매·경로 정보 | 자금/수단/재고 조건, 필요 신용은 별도 수치 | 현재 수레 판매처와 Q7을 대응. 임의 고신용 문턱 추가 금지 |
| 중간 등급 | 전문 상점·추가 운송 의뢰·정보/휴식 서비스 후보 | 기본 거래와 고급 서비스를 나란히 표시 | 실제 쓸 수 있는 기능·잠금 이유·해금 전후 효과를 정함 |
| 상위 마을·수도 | 대량/고가 거래·창고·운송 지원 후보 | 마을 제공 조건과 개인 신용의 결합 | 고급 거래의 실제 혜택·비용·저장. 창고의 이번 포함/후속을 명시 |
| 원안의 후속 시설 | 수리·보험·마차·상단 거점 | 수단 손상/보험 사건/상단이 있을 때 의미 | 낙하 제거만으로 필요를 가정하지 않음. 이번 필수 시설로 자동 확정하지 않음 |

이 표는 기능이 없는 건물로 완성 처리하라는 뜻이 아니다. FAC-01에서 **실제로 이용 가능한 등급별 시설/고급 거래의 세로 연결**을 최소 하나 이상 검증하고, 지역 완성 시 각 거점에 채택한 시설을 모두 기능/거절/해금 상태로 납품한다. 정확한 시설 목록이 아직 비어 있다는 사실과 ‘시설 체계 자체는 필수’라는 사실을 구분한다.

시설 데이터에 필요한 항목: `facilityId / townId / 시설 종류 / 요구 마을등급 / 요구 신용 / 제공 기능 / 비용·효과 / 상태 저장 여부 / 잠금 설명 / 이번·후속 / 담당`. 새 기능에는 안정 ID를 사용하고 기존 수레·상품·town ID는 보존한다.

## 4. 맵·교역·시나리오 연결

- 다섯 거점과 도로 구역의 **논리 연결표**를 먼저 작성한다. 한 갈림길에서 두 노면만 비교하는 현재 시험을 지역 전체의 대안 경로로 확대한다.
- 큰길/샛길·거점 경유는 거리, 적재 감속, 정보/거래 기회로 비교한다. 바이킹만 유리하도록 강제 오솔길을 늘리지 않는다.
- 각 거점은 생산/소비·초기 재고·낮은/높은 신용의 이용 시설·주요 NPC·출구/스폰·귀환 화물을 갖는다. 지도에 실제 지형과 시설/잠금 정보를 읽을 수 있게 한다.
- Q1~Q7는 기존 T/S 퀘스트와 별도 매핑한다. Q3 낙하 전제와 흔들림 장비, Q7 마을 승급/관문, Q5 미구현 날씨/연타를 그대로 가져오지 않는다.
- Q4의 조기 소식은 고려 정보 특화 후보이며 구체 선행 시간은 미확정이다. 일반 플레이어에게 기본 시세 판단 수단을 주고 파티 정보 공유도 고려한다.
- 나루의 가상 배치와 실존 벽란도, 창작 생산 마을과 역사적 생산지를 구분한다. 실제 지명 사용 방향을 취소하지 않되 불확실한 지명을 임의로 확정하지 않는다.
- 마을 밖 문명 연결은 여러 중간 구역을 지난다. 고려의 다섯 거점을 다섯 문명으로 세지 않는다.

| 3 | 마을·연결 초안 + 낙하 제거/저장 이주 | 다섯 거점 자유 왕복·기본 거래·교역 상품·지도/출구/수레 접근. 기존 저장 보존 |

서버가 붙으면 동일 시설 요청의 행위자/위치/신용/자금을 서버가 검증한다. 메뉴를 닫았다 열거나 재접속/지역 전환해도 잠금이 풀리거나 비용/보상이 중복되지 않는다. 저신용A와 고신용B가 같은 마을에서 서로 다른 이용 권한을 갖는지 검사한다. 시설 이용을 위한 모달이 다른 사람 세계 시간을 멈추면 안 된다.

후속 구현으로 신규 두 마을·기본 시설3종·보관 저장·낙하 이주를 추가했다. 현재 실제 표와 검증은 DevelopmentStatus.md를 따른다. 시나리오 Q1~Q7·고려 정보 특화·최종 시설 목록/수치·멀티는 여전히 미완료다.

## 지형 배치 기준 (2026-10-18)

한반도 윤곽의 복제 대신 산록·수도·하천·들판 생활권을 참고한다. 현재 실제 연결은 송악 산록↔개경 북쪽, 나루↔예성 길↔개경 남문, 개경 동문↔닥목↔남쪽 장단이다. 실측 복원이 아니며 경제용 worldCoord는 유지한다. 상세 배치·고증과 각색·검사 근거는 [지형 배치 기록](GoryeoLandscapeLayout.md)을 따른다.

## 플레이 경험·동선·분량 검토 (2026-10-18)

최신 검토는 [고려 플레이 경험 계획](GoryeoPlayerExperiencePlan.md)을 따른다. 수도1+마을4 필수 범위는 유지한다. 마을 추가보다 실제 공급/소비 이득, 두 신규 마을의 방문·귀환 이유, 수레 이후 목표, 지역 순환로를 먼저 검증한다. 후속으로 추가 이동 구역3개를 로컬에 반영했다. 구현 범위는 아래 패치 기록을 따른다. 첫 손수레12~25분·고려 입문30~45분은 플레이 테스트 목표 가설이며 현재 분량의 실측값이 아니다. 방문/기본 거래는 자유로 두고 개인 신용은 시설/고급 거래의 이용 조건과 구분한다.

후속 구현: [교역·성장·순환 반영](GoryeoProgressionPatch.md). 수도/마을 수는 유지하고 길3맵·지역 가격·선택 의뢰를 반영했다. 아래/이전 검토의 제안 중 실제 반영 범위는 해당 기록을 우선한다. 목표 플레이타임의 사람 검증은 남아 있다.

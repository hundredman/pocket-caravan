# Pocket Caravan 개발 기준안

> 현재 구현/검사는 [진행표](DevelopmentStatus.md), 문서 우선순위는 [문서 안내](README.md)를 따른다.

2026-10-16 일정 업데이트: 사용자 확인 마감은 **11월 초**, 정확한 날짜·팀 가용시간은 미정이다. 현재 남은 작업은 [작업 목록](ImplementationBacklog.md), 날짜/파트별 배정은 [일정](DeliveryPlan.md)에 정리한다. 기존 4주 구상을 지금부터 새 4주로 계산하지 않는다.

기준일: 2026-10-15. 목적: 4명·4주 MVP에서 무엇을 만들고 어떻게 품질을 판단할지 정의한다.

이 문서는 현재 의도를 정리한 개발 기준안이다. 2D 우선 의향을 반영했으며, 팀의 최종 승인·일정 시작일은 아직 확정되지 않았다. 초기 4주 MVP는 기본 시스템 선행 후 2~4명 실제 멀티플레이를 검증하고, 최종 제품 목표는 MMORPG 규모의 다중 접속 교역 세계다. 장기 정원은 미정이며 2~4명으로 제한하지 않는다. 코드 구현 완료와 기획 제안을 구분한다.

3. [개발·검증 계획](DeliveryPlan.md): 단계, 담당 영역, 완료 기준과 결정 목록.
4. [개발 검토 기록](DevelopmentReview.md): 이전 기획과 구현 차이 및 대화 기록. 최신 지시는 위 세 문서를 먼저 본다.
5. [전체 요구·구현·누락 대조](RequirementsAudit.md): 원본/후속 요구와 실제 상태를 추적한다. 현재 기획에서 길 개척은 제외하고 정해진 길의 선택을 구현한다. D-13과 10월16일 회의 기록을 따른다.

표기: **사용자 요구** / **현행 구현** / **제안** / **결정 대기** / **검증 미완료**. 제안을 승인된 규칙이나 구현으로 바꾸어 기록하지 않는다.

지역 제작과 향후 수정 절차는 [지역 제작·수정·확장 설계안](RegionAuthoringPlan.md)을 따른다. 맵 연결·지도 표시 배치·가격용 거리를 구분하고, 원본 소유권과 생성/수작업 보존을 먼저 정리한다. 해당 구조 개선은 아직 구현하지 않았다.

사용자는 최신 계획을 반영해 고려 본편 개발을 재개하도록 요청했다. 확정된 수도1+마을 최소4·시설 해금·운반 변경은 실행 범위다. [전체 재대조](FullRequirementsReview_2026-10-17.md)와 [고려 제작 명세](GoryeoRegionSpec.md)를 따른다. 과거 종합 검토 요청을 개발 중단 지시로 재사용하지 않으며, 미합의 제안/수치는 확정된 작업과 구분한다.

후속 요청으로 팀에게 보여 주고 수정할 **고려 지역 프로토타입 개선**은 재개했다. [최신 지역 적용 기록](GoryeoPrototypeReview.md)을 참고한다. 이를 전체 제작 구조·경제 수치·온라인의 일괄 개편 승인이나 최종 미술 확정으로 확대하지 않는다.

## 2. 게임의 약속 — GD-01

### 기존 세계·시대 설정 (원본 기획서 1·12·13쪽)

대항해시대 이전, 대략 8~15세기의 상인 문화를 한 대륙에 모은 **가상 교역 세계**다. 918~1066년은 네 출신의 역사적 활동 기간이 겹친다는 설명이며, 게임의 단일 기준 연도가 아니다. 고려를 임의로 12세기 복원 게임으로 변경하지 않는다. 동물 캐릭터·압축 지리·공통 화폐와 능력은 각색이며, 실제 역사와는 상업 백과에서 구분한다. 원본의 고증 주장은 검토 대상이지 그 자체로 사실의 증명이 아니다. 상세 검토와 지역 설계는 [고려 전체 디자인·고증 검토](GoryeoDesignReview.md)를 따른다.

동물 행상이 물건을 싣고 여러 마을과 교역로를 지나, 지역별 특산품과 시세 차이를 이용해 재산을 축적한다. 이동 중의 길 선택과 운반도 핵심 경험이다. 전투 중심 RPG로 범위를 넓히지 않는다.

반복 흐름:

> 장터의 물건·가격과 다음 경로 확인 → 적재·이동 수단 선택 → 운반과 필요 시 중간 거래·보급 → 도착·판매 → 새 화물과 정보로 다른 판단

- 사용자 요구: 지역 특산품 교역, 먼 문명까지의 여정, 분기 교역로, 장기 MMORPG 멀티플레이 고려.
- 개발 기준안: 2D 고정 탑다운·동물 캐릭터를 우선 개선한다. 이전 카툰 3D 실험은 보존하되 이번 실행 계획에 전면 전환 작업을 넣지 않는다.
- 분위기 제안: 따뜻하고 친근한 상인 여행. 긴 이동의 강제 대기나 상시 카운트다운으로 긴장을 만들지 않는다.
- 네 출신은 공통 거래를 하고 강점만 달리한다. 기존 고유 능력 전체를 4주 필수로 간주하지 않는다.

2026-10-17 사용자 확인: 고려 **정보**, 아라비아 **적재**, 베네치아 **판매/중개**, 바이킹·북유럽 **이동**을 역할 방향으로 삼는다. 바이킹을 험로에만 제한하지 않는다. 주행 중 물품 낙하는 제외하고 감속 중심으로 설계한다. 구체 배율은 미확정이다. 주행 낙하는 제거하고 시각적 흔들림을 유지했다. 기존 출신 수치는 ORG-01 미완료로 남아 있다. 역사 모티브와 게임적 각색, 기존 제안의 대체 범위는 [출신별 역할](OriginDesign.md)을 따른다.

## 3. 범위 — GD-02

| 구분 | 이번 기준안 | 상태 |
|---|---|---|
| 출발 지역 | 네 문명 각각 수도1 + 수도 외 최소 마을4, 지역별 특산품 | 사용자 재확인. 현재 고려는6맵·수도1+마을4+길1 |
| 고려 | 수도 개경 + 최소 네 마을·등급/신용별 시설·교역/연결 완성 | 사용자 담당. 다섯 거점 구조·로컬 기본 시설 구현. 교역 가치/시나리오/아트 보완, 시작 스폰 별도 결정 |
| 연결 | 여러 중간 구역을 지난 후 다른 문명 도착. 십자 연결 구역은 MVP용 모듈 | 사용자 요구. 한 번의 출구로 고려와 서역 직접 연결 금지 |
| 경로 선택 | 두 개 이상 루트·거점 경유로 거리/노면/적재/거래 기회 비교 | 회의 방향. 기존 길 분기 하나가 전체 지역 완성을 뜻하지 않음 |
| 멀티 | 기본 시스템 이후 공유 이동·시장·소유권·지속 저장을 단계적으로 검증 | 초기 MVP 검증 2~4명, 최종 MMORPG 규모. 장기 인원 미정·온라인 구현 없음 |
| 확장 | 거미줄 교역망, 보급·날씨, 대륙·바다, 상단 운영 | 장기. 모두 동시에 MVP 필수로 넣지 않음 |
| 스토리 | 기본 지역 맥락과 짧은 대화. 기능 시험은 독립 씬으로 제공 | 사용자 요구. 긴 튜토리얼을 시험 조건으로 삼지 않음 |

각 지역의 수도1+마을 최소4는 제작 기준이며 아트 밀도 조절과 거점 수 축소를 혼동하지 않는다. 공통 장터·시설·출구·특산품 계약을 재사용하고 고려를 품질 기준으로 삼는다. 다른 지역은 동시 개발 중이므로 기존 산출물을 확인해 통합하며 공통 기능 담당을 임의 배정하지 않는다.

## 4. 이동·운반 — MV-01

### 최신 결정: 낙하 제외·감속 중심

2026-10-17 사용자 결정: 주행 중 물품 낙하·반복 회수를 제외한다. 흔들림 게이지와 멈춰서 짐을 안정시키는 요구도 새 목표에서 제외한다. 노면·적재량·운송 수단에 따른 예측 가능한 감속으로 경로를 선택하게 한다. 물품을 잃는 대신 이동 시간이 달라지는 구조다.

| 경로 | 선택할 이유 | 검증 |
|---|---|---|
| 큰길 | 대량 운반과 수레 운행 | 거리·물량·중간 거래를 포함한 왕복 효율 |
| 오솔길 | 짧은 경로와 등짐 운반 | 일반 플레이어에게도 실제 선택할 이유가 있는가 |
| 풀밭 | 짧은 횡단·탐험·우회 | 감속 원인이 보이고 지나치게 느려지지 않는가 |
| 중간 거점 경유 | 거래·정보·풍경과 여정 | 강제 정차/긴 대사 없이 방문할 가치가 있는가 |

바이킹 능력을 위해 지역을 오솔길로 채우지 않는다. 출신의 이동 보너스와 경로 자체의 효용은 별도로 검증한다. 시각 HUD·카운트다운을 다시 넣지 않는다. 물·벽의 충돌은 감속과 별개로 유지한다.

### 구현 차이와 이주

현재 소스는 신규 주행 낙하와 누적 게이지를 제거했다. 기존 낙하 기록은 수량/원가/의뢰로 이주하고 미지 ID는 보존한다. 사용자 후속 확인으로 CarryVisual의 시각적 흔들림은 감속의 표현으로 유지한다. 정차 안정화/낙하 조건과 연결하지 않는다. 실제 감속은 노면/적재 계산이 담당한다. 자세한 구현/검증 한계는 DevelopmentStatus.md를 따른다.

- 기존 낙하물의 물품·원가·활성 의뢰를 보존해 이주하고 단순 삭제로 재산을 없애지 않는다. 중복 복구·초과 적재·알 수 없는 ID를 검사한다.
- 감속률·출신 적재/이동 배율은 미확정이다. 기존 에셋 값이나 이전 검토의 12%/15%/87% 등을 확정 수치로 사용하지 않는다.
- 도적 강탈·의뢰 기한/배상·경제 손실 전체를 제거한 결정은 아니다. 적용 범위는 별도 합의한다.
- 손수레 관성·선회 반경·새 충돌 물리는 미구현이며 이번 변경의 선행 조건으로 추가하지 않는다.
- 여러 사람이 다리·장터에서 만나도 통행·상호작용·가독성이 유지되는지 검증한다.

## 5. 교역·성장 — EC-01

### 현행 기준과 빈 부분

기준가에는 산지와 마을의 맨해튼 거리가 반영되고, 현재가는 재고 비율로 조정된다. 재고 배율은 0.5~2, 매입은 산출 가격의 85%를 바탕으로 한다. 실제 판매가는 추가 재고·장날·출신 효과가 반영되므로, 이 비율만으로 최종 차익을 단정하지 않는다.

- 현재 `WorldIndex` 연결 그래프와 가격용 좌표는 별개다. 분기·우회로를 늘릴 때 공식적인 수송 거리/비용을 따로 정의한다. 플레이어의 빙빙 도는 실이동 거리를 판매 프리미엄으로 쓰지 않는다.
- 왕복 교역의 수익은 판매대금 − 매입원가 − 실제로 도입한 운송비용으로 기록한다. 아직 없는 수리·식량비를 이미 계산하는 것처럼 표시하지 않는다.
- NPC 거래도 공유 재고를 바꿀 예정이며 서버에서 한 번만 실행해야 한다. 현재 로컬 `NpcTraders`가 멀티 경제를 구현한 것은 아니다.
- 구매·판매가 모두 마을 거래액을 올리는 현행 성장 규칙은 반복 매매로 성장량을 늘리는 경우를 시험한다. 순 기여·기간별 제한 등 대책은 검증 후 선택한다.
- 신용·초기 자본·가방 한도 때문에 첫 거래가 불가능해졌을 때 복구 경로를 둔다. 배달로 재기하는 방식은 후보이며 장시간 의무 튜토리얼을 요구하지 않는다.

### 여러 플레이어가 있을 때의 경험 제안

다른 상인의 구매가 내 가격·재고에 반영되는 것이 최소한의 상호 영향이다. 보행 캐릭터가 서로 보이는 것과 별도로 검증한다.

신규 상인이 기본 운반 수단과 소량 상품을 구하지 못하는 재고 독점, 대량 판매로 단일 품목이 무가치해지는 상황, NPC와 유저의 과도한 경쟁을 시험한다. 재고 회복·거래 단위·NPC 활동량을 함께 조절하며 초기 경제는 필요 시 운영자가 초기화할 수 있는 테스트 세계로 둔다. 정식 운영 경제와 테스트 리셋을 구분한다.

직접 유저 거래·공동 상단·호위는 확장 후보다. 직접 거래를 MVP에 넣지 않는 동안 다른 유저와의 거래 UI가 있는 것처럼 소개하지 않는다.

### 성장과 사회적 경험의 범위 제안

공통 성장의 장기 구조는 행상 → 수레상 → 마차급 운송 → 상단 운영이다. 현재 차량 데이터는 등짐과 손수레이므로, 이번 MVP는 이 둘로 적재량·경로 선택이 바뀌는 단계까지 우선 검증하는 안을 권장한다. 마차/지역별 운송 동물·배·자동 상단이 이미 구현되어 있다는 뜻은 아니다.

2~4명 시연에서는 서로를 이름·이동 수단으로 식별하고, 한 사람의 구매가 다른 사람의 실제 장터 재고·가격에 반영되는 경험을 확인한다. 동일한 길에서 다른 상인을 만나고 서로 다른 짐/경로로 결과가 달라져야 한다. 이를 단순 접속 성공과 구분해 플레이 기록에 남긴다.

짧은 정보 교환·동행·직접 거래를 어느 수준까지 게임 안에 넣을지는 범위 결정이 필요하다. 첫 온라인 시험은 팀의 구두 협의로 경로와 상품을 나누어 테스트할 수 있으나, 이것을 게임 내 채팅/유저 거래 구현 완료로 기록하지 않는다. 혼자와 함께할 때의 차이가 공유 시장만으로 충분한지도 평가한다.

## 6. 2D 품질·몰입 — AR-01

현재 자산 기준은 타일 16px, 동물 캐릭터 16×24, Point 필터, 무압축, 384×216 기준 Pixel Perfect Camera다. 해상도만 올리는 것을 품질 개선 목표로 삼지 않는다.

| 공간 | 전달할 인상 | 우선 제작할 장면 | 판정 |
|---|---|---|---|
| 나루 | 떠나기 전 준비하는 작은 강변 장터 | 배·선착장·짐 하역·광장의 연결 | 지명 없이도 강변 교역 거점으로 구분되는가 |
| 예성 길 | 마을을 벗어난 여행, 다음 장소를 향한 이동 | 민가 감소·숲/여울/다리·갈림길 | 지난 구간과 경로 선택 이유를 기억하는가 |
| 개경 | 도착한 수도의 규모와 상업 밀도 | 외곽 → 남문 → 밀집 시전, 큰 랜드마크 | 나루보다 큰 중심지임을 크기·밀도로 느끼는가 |
| 닥나무 마을 | 상품 생산 과정이 보이는 생활 공간 | 재료 적치·작업·종이 건조 공간 | 종이 생산지임을 장식과 활동으로 이해하는가 |

공통 제작 규칙:

- 지역별 대표 색·지붕/수목 실루엣·바닥 재질·대표 소품을 먼저 정한다. 같은 크기의 집을 규칙적으로 늘어놓는 것으로 수도 분량을 채우지 않는다.
- 경계 숲은 자연스러운 굴곡과 온전한 나무 묶음으로 만든다. 무작위 장식보다 출입구·길·랜드마크의 가독성을 우선한다.
- 집/장터/성문/주민의 크기 관계를 공통 표본으로 확인한다. 나무·기와·흙·물의 색과 명암을 통일한 뒤 지역 차이를 낸다.
- 이동 중 전경과 수관 가림은 인물·길을 숨기지 않아야 한다. 발밑 그림자·물결·수레 움직임은 행동 피드백에 사용한다.
- 지역 소리의 중심을 나루의 물·작업, 길의 바람·발걸음, 수도의 장터, 생산 마을의 작업으로 나누는 안을 시험한다. 음원 확보 전에는 완료로 세지 않는다.
- 다른 문명에 가기 전 중간 지역의 식생·재료·건축 흔적을 단계적으로 바꾼다. 맵을 바꿀 때마다 변화가 사라지거나 갑자기 다른 문명을 붙이지 않는다.

완료 기준: 나무·집 조각 누락 0, 보이는 다리·길과 통행 판정 불일치 0, 출구/스폰 단절 0. 지명을 가리고 지역 역할을 묻는 내부 플레이 테스트 결과와 수정할 항목을 기록한다. 동의하지 않은 팀원을 포함한 ‘모두 만족’으로 결과를 포장하지 않는다.

## 7. 화면·대화·시간 — UX-01

- 일수·현재 시각을 상시 HUD에 다시 넣지 않는다. 시험장에도 제한시간·카운트다운을 넣지 않는다.
- 현행 대화창은 실제 글꼴·너비·본문 높이를 재서 자동 분할한다. 기본 약 3줄, 짧은 문장 1~2개 권장. 제목·줄바꿈도 공간을 차지한다. 선택지는 마지막 페이지에서만 표시한다.
- 장터에서는 현재 가격·재고·적재 여유와 판매 손익을 읽을 수 있어야 한다. 현재 공통 장부(L)는 방문한 장터의 마지막 확인값을 기록하며, 미방문지는 미확인으로 표시한다. 외지 가격은 첫 1개 기준 참고값이고 도착 시 달라질 수 있음을 알린다. 개별 관측 시각/신선도와 최신 정보 특화는 구현 대기다. 이전 장부 노후화 배율을 확정 능력으로 사용하지 않는다. 시각을 HUD에 다시 표시하는 방식은 사용하지 않는다.
- 이름표·퀘스트 안내·상태 창은 경치와 플레이어를 가리지 않게 한다. 멀티 이름표는 거리·선택 대상에 따라 줄이고 채팅은 별도 영역을 사용한다.
- 지도는 물·숲·길·거점·현재 위치를 구분하고, 지형 지도 배치로 가격 좌표를 바꾸지 않는다. MMO에서 다른 사람의 실시간 위치를 전부 공개하는 기능은 기본 요구가 아니다.
- 현행 의뢰에는 기한이 남아 있다. 편안한 여행을 원하면 일반 매매/무기한 의뢰와 선택형 기한 의뢰를 나누는 안을 검토한다. 시간 표시 삭제를 기한 삭제로 기록하지 않는다.
- 멀티에서는 대화·지도·메뉴가 자기 입력만 막고 공유 세계를 멈추지 않아야 한다. 안전한 장터에서 거래·대화하게 하는 기본안을 적용할지 결정한다.

## 8. 재미와 성능을 따로 검증 — QA-01

현재 맵 회귀 검사 51개, 대사 분할 102개, 시험장 런타임 검사 19개 통과 기록은 기술 검증이다. 미관·여행 몰입·반복 재미·동시 접속 성능이 통과했다는 뜻이 아니다.

- 시험장 기본 조합: 등짐/손수레 × 세 경로, 우선 같은 화물 무게로 비교. 노면·적재·수단·출신을 하나씩 바꿔 원인을 구분한다. 현재 시험장의 흔들림 토글은 제거 대상이다.
- 플레이 기록: 선택한 길과 이유, 이탈 길이, 적재율, 감속·우회·정지 이유, 다시 해보고 싶은 행동, 불쾌했던 지점.
- 대표 교역 구간: 나루 → 접근로 → 개경 장터의 편도 및 귀환을 시험한다. 길을 기억하는지, 다른 짐으로 동선이 달라지는지, 판매 보상이 이동 부담에 맞는지 확인한다.
- 온라인 검증은 [멀티플레이 설계안](MultiplayerPlan.md)의 별도 시나리오를 따른다.

## 9. 아직 승인·검증이 필요한 항목

2D 우선 기준안의 팀 승인, 추가 동시 접속 목표, 각 지역의 거점·연결 구역 수, 실제 시작 위치, 도로 밖 이동의 허용 폭, 화물 소유권 정책, 기한 의뢰 정책, 네트워크/저장 기술 선택은 [개발·검증 계획](DeliveryPlan.md)의 결정 목록에서 관리한다. 빈 값을 구현자가 임의로 확정하지 않는다.

## 9. 스타팅 지역과 시설 성장 — REG/FAC

지역당 수도1+수도 외 최소 마을4. 지역은 이미 발전해 있고 정착지 등급이 다르다. 자유롭게 방문·기본 매매하되 시설/고급 거래는 마을 제공 조건과 개인 신용으로 차등한다. 등급·신용·상인 운반 단계는 서로 다른 축이다. 구체 거점/시설표와 원안 시설의 이번/후속 구분은 [고려 제작 명세](GoryeoRegionSpec.md)를 따른다. 현재 거래액 승급과 고급 배달 제한만으로 완료 처리하지 않는다.

돈·신용·명성을 별도로 추적하며 명성의 획득/소비는 세부 대기다. 지역별 동물 종 지정·색상 변형과 실제 지명 사용은 회의 방향이고, 구체 종/지명은 조사·선정 작업이다. 사람 NPC는 팀 비교1안이다. 텍스트 채팅을 우선하고 음성은 후속으로 두며 채널/범위와 이번 통합 수준을 구체화한다.

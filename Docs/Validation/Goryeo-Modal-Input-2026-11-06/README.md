# UI 입력 잠금·이동 정지 점검

## 발견과 수정

이동 중 소지품 창을 열고 W를 계속 누르는 재현에서, 시간은 멈췄으나 캐릭터가 **0.1093006칸** 더 이동했다(before-fix.json). PlayerController가 잠금 중 입력만0으로 바꾼 뒤 PlayerMotor.Tick을 계속 호출해 잔여 속도로 감속 이동하던 문제다. UIState의 기존 계약은 창이 열리면 이동과 시간을 멈추는 것이다.

공용 Scripts/Player/PlayerController.cs의 모터 정지 조건에 locked를 추가했다. 잠금 중 현재 위치에서 속도/노면 drift를 정지한다. 이동 공식/속도/카메라·저장·아트/맵은 고치지 않았다. 다른 문명 전용 스크립트와 동결된 Core/Economy/Quests/UI도 고치지 않았다.

## 재검사

- 자동Play **100확인**, 실제480×270 화면4장. I/M/Q/L 열기·다른 창 겹침 방지·Space의 월드 상호작용 차단·같은 키/ESC 닫기·PauseMenu 중복 열림 방지·Tab HUD 처리·돈/신용/화물 보존.
- 실제 W로 속도를 만든 뒤 창을 열고0.3초 확인했다. 고려 I/M/Q/L/Esc 다섯 창과 베네치아/아라비아/북유럽 맵의 I창 **8경우 모두 이동0/시계변화0**, 닫은 뒤 W 이동 재개.
- 다른 지역은 같은 출신의 시험 캐릭터로 공용 모터/소지품 창을 비교했다. 네 출신 능력 조합 전체 검사는 아니다.
- 위치/기본 상태는 QA가 준비하고, 키는 가상 Keyboard→일반 InputReader/Update 경로로 보냈다. 사람이 직접 키보드/마우스로 플레이한 검사나 OS 입력 검사는 아니다.
- 화면4장은 기존 UI 상태를 기록한 것으로 새 아트/화면 디자인 제안이 아니다. UI 그림/레이아웃은 미변경이다.

## 공통 검사와 한계

실제 저장 I/O/재시작·온라인·사람 직접 입력·장시간/시연PC FPS·빌드는 이번 범위에서 미검사다. 모든 입력/상태 조합을 전수 확인한 것은 아니다. R3/R4는 현재 본편 부재와 병합 검토가 그대로 남아 있고 이번 검사로 완료 처리하지 않는다.

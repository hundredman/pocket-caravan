# E1·B2 구현 전 판단 요청

B1은 정정 승인된 원본/면적 검사까지 완료했다. 새 Decisions 문서는 B1/A3b/D10을 해소했지만 다음 항목의 답은 아직 없다. 사용자 지시대로 임의로 정하지 않고 본편 연결 전에 멈춘다.

1. **E1 거리 단위.** Plan E1 완료 조건은 타일 길이/예상 이동시간/맵 전환 수 중 기준을 먼저 정하고 `ItemData.MapsFrom`·`ContractManager.Distance`의 경제 맨해튼 거리와 `DeliveryReward.RouteSteps`의 맵 BFS를 통일하라는 것이다. 원본의12개 도식 길은 직선 연결이며 실제 강/다리 우회 거리와 같지 않다. 채택 단위, 단위당 가격 비율/의뢰 보수·기한의 호환 방향을 답해 달라. 지리 좌표를 경제 좌표에 바로 대입하면 상품 가격과 배달 수치가 크게 바뀐다.
2. **중앙 4마을의 런타임 ID 대응.** 새 원안은 동문/북동포구/남동포구/중앙길목4곳이지만 본편 등록 시장은 `transit_woodtown`(솔재 길목)/`transit_ferry`(버들나루)2곳이다. 어느 기존ID를 어느 계획 마을에 보존하고 신규2곳을 어떤ID로 만들지 명시해 달라. 기존 퀘스트·의뢰·시설/저장 참조를 이름만 보고 옮기지 않았다. B1 지리key는 이 결정을 대신하지 않는다.
3. **B2 선행 D5.** Plan D5는 여전히 대기다. 기존 단일 씬+페이드/맵 경계 전체 이동을 유지할지, 이어 불러오기/스트리밍을 할지 답이 필요하다. 기존 구현을 관찰한 것과 새 경계 구조의 방식을 승인한 것을 구분한다.
4. **D4/D7 외부 연결 계약.** 팀원 합의 좌표/연결 구역ID는 아직 없다. 내부 고려/중앙동쪽만 먼저 연결하고 외부는 비활성 계약 자리로 남겨도 되는지 명시해 달라. 원안 연결 방향3곳은 저장했으나 다른 팀 구역으로 런타임 출구를 만들지 않았다.

답변은 고칠 파일/완료 기준/검사 순서를 갖춘 결정 문서로 main에 남기면 된다. Codex는 그 답에 따라 E1·B2를 구현하고 상품가격/의뢰 보수·기한·옛 저장을 회귀 검사한다. D10 임시안은 수신했으며 다음 R2에서 적용/재계산한다. 아직 수치나 되팔기 안전 규칙을 본편에 반영하지 않았다.

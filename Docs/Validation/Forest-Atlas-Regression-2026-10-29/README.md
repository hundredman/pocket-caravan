# 타일 묶기 화면·기능 회귀 검사 — 2026-10-29

**검사 완료, 본편 적용 보류.** 일반 배율·확대 화면과 통행/이동 결과는 같다. 비정수 전체 보기에서 처음5맵의 픽셀 차이를 검출했고, 여백 보강으로 검은 경계선은 제거했으나 **최종3맵에서 소수 픽셀 차이가 남았다**. 앞선 두 숲 창의 통과 결과를 13맵·모든 배율로 일반화하면 안 된다.

## 방법과 범위

- Unity 6000.3.26f1, M3 Pro/Metal, Edit 모드. 본편 13씬을 한 번에 하나씩 열어 원래 조명·재질·NPC/건물 SpriteRenderer를 유지했다. 이전 preview 동시 조명 중복을 피했다.
- 원래 씬과 메모리에 만든 atlas를 비교했다. Texture2D.PackTextures(padding 4, 최대2048), Point, mipmap 없음, 회전 없음. 16px 타일 크기/RGBA/PPU/피벗 유지, 복제 Tile의 sprite 참조만 임시 변경. 이 시험은 Unity SpriteAtlas 에셋의 영구 등록/플랫폼 패킹 검사는 아니다.
- 각 맵 전체 보기 1개, 전 영역을 덮는 일반 배율 창, 중심의 확대·축소+소수 좌표 창 2개를 각각 480×270으로 촬영했다. PixelPerfectCamera를 잠시 꺼 수동 카메라 배율을 검사했다.
- 일반 배율은 1타일=16화면px(orthographicSize=8.4375), 확대는32px, 축소는8px. 전체 보기는 맵 크기에 맞춘 비정수 축소다.
- 렌더 워밍업 뒤 전후 디코딩 RGBA를 비교했다. 13개의 전후 전체 보기 PNG와 접촉판을 저장했다. 일반/확대/축소 창은 메모리에서 전체 RGBA 비교했고 카메라 좌표/차이 수는 각 JSON에 남겼다.
- MapRoot의 Awake만 반사 호출해 grid/Current를 초기화하고, 전체 칸의 IsWalkable/RoadGrid.GradeAt/타일 flags·color·transform을 전후 대조했다.
- 실제 PlayerMotor.Tick 함수를 Edit 모드에서 직접 호출했다. 각 맵 일반 지면 8곳+막힌 칸 인접 8곳, 8방향×90틱으로 전후 궤적을 비교했다. 게임 루프/동적 장애/실제 조작 플레이 검사는 아니다.
- MonoBehaviour 직렬화 설정(맵 ID·NPC·출입구·스폰·장애/노면 배치 등) 및 Renderer의 가림 순서/레이어/재질/enabled를 전후 비교했다. Tile의 colliderType/flags/color/transform/gameObject 보존도 별도로 확인했다.

### 전체 보기에서 발견한 차이

각 화면은129,600픽셀이다. 일반 배율 영역 스캔과32px/8px 배율 창에서는 아래 맵도 모두 차이0이었다.

| 맵 | 전체 보기 차이 픽셀 |
|---|---:|
| transit_central_approach | 70 |
| transit_wetroad | 195 |
| transit_woodtown | 3,826 |
| transit_ferry | 475 |
| transit_south_inland | 331 |

전체 보기에서 샘플링하는 픽셀이 바뀌는 현상과 맞지만, UV/메시/셰이더 중 정확한 원인은 이번 검사로 확정하지 않았다. 원본끼리 같은 카메라 순서로 재촬영한 A/A 대조(중앙 진입·woodtown)는 차이0이었고, 임시 atlas에서는70/3,826차이가 재현됐다. 단순 시간 경과/촬영 노이즈로 통과시키지 않았다.

기존 Sprite의 geometry 복사도 별도로 시도했지만 Unity가 OverrideGeometry를 거부해 유효한 원인 검사가 되지 않았다. 이 오류 실험은 본편에 적용되지 않았고 정규 회귀 합계에서 제외했다. 중복 stack은 제거하고 `mesh-control/result.json`에 오류 종류/개수/무효 상태만 보존했다.

## 여백 보강 후 13맵 재검사

PackTextures의 4px 간격 중 각 타일 바깥2px에 가장자리 RGBA를 복제했다. 타일 내부16×16 그림·색·형태는 바꾸지 않는다. Point 샘플링이 경계 바깥을 참조해도 빈 검정색을 읽지 않도록 하는 렌더링용 여백이다.

- **13맵244쌍 재검사**: 일반/확대/0.5배231쌍은 여전히 RGBA차이0. 전체 보기10/13쌍도 차이0.
- 목재 마을 전체 보기의 검은 격자선은3,826→0픽셀, 남부 내륙331→0으로 해소됐다. 나루 길475→104로 감소했다.
- 남은 차이: 중앙 진입70, 습지 길195, 나루 길104픽셀. 모두 비정수 전체 보기에서만 발생했고 각 화면129,600픽셀 중 일부다. 픽셀 수가 작다는 이유로 완전 동일 판정하지 않았다.
- 원본 A/A 대조는13맵 모두 차이0. 판정80,641칸/이동149,760틱/설정·가림 순서는 모드별 재검사에서도 모두 동일, 정규 재검사 중 경고·오류0.
- 보강 후 저장21파일 목록·SHA와 원래 씬/dirty/비Play/Current 상태도 다시 확인했다.
- 최종 원시 수치·전체 보기 PNG·접촉판은 `padded/`, 원본은 `Tools/Performance/atlas_regression_padded.cs.txt`다. [경계선 수정 비교](padded/edge-padding-comparison.png) / [최종13맵 전후](padded/13maps-before-after.png).

남은 현상은 비정수 축소 시 UV/Point 샘플링 정밀도 차이 가능성을 남겨 둔다. 원인은 확정하지 않았다. 여백 보강만으로 모든 배율이 같아졌다고 기록하지 않는다.

## 판단과 다음 작업

숲 밀도를 낮추거나 승인 그림을 바꿀 근거는 없다. 기능 설정과 타일 충돌은 이번 시험 범위에서 보존된다. **현재의 메모리 재패킹 시험을 그대로 본편에 넣지는 않는다.** 영구 Sprite Atlas 구현을 진행할 때 기존 Sprite/Tile ID를 유지하는 엔진 atlas 방식으로 비정수 축소 차이를 다시 검사하고, 전체 보기까지 통과시킨 뒤 연결한다.

실제 Play의 NPC/사건 갱신·거래·저장 불러오기·경계 이동·런타임 가림 전환, PixelPerfectCamera의 게임 루프, 플랫폼별 atlas packing, 성능 FPS/GC/빌드는 이번에 검사하지 않았다. 출구 설정이 같다는 것을 실제 맵 전환 플레이 통과로 대신 적지 않았다.

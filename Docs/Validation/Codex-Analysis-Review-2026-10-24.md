# Codex 분담·에셋 분석 재검토

날짜: 2026-10-24. 대상: 이 대화의 Codex 분석과 로컬 문서·코드. Claude 크로스체크용이다. 미술 승인이나 구현 완료 보고가 아니다.

## 정정한 설명

| 항목 | 재검토 결과와 근거 |
|---|---|
| 비교 화면 절차를 새로 추가해야 한다 | 일부 잘못된 설명. `ArtGuide.md` 4절에 승인된 에셋 옆에 놓는 비교 검사가 이미 있다. `Plan.md` A1은 사용자 승인을 요구한다. 실제 플레이 크기 비교 자료를 구체화하는 것은 보완안이다. |
| 기준에 맞으면 기존 에셋을 유지할 수 있다 | 일반적인 감사 판정과 현재 프로젝트의 최종 제거 목표를 혼동했다. A3b는 유지/교체/삭제를 판정하지만 C6는 Ninja 팩 의존·AI 축소 시트·즉석 변환 제거와 본편의 옛 출처 에셋 0개를 요구한다. 임시 유지와 최종 유지를 구분하고, C6 예외는 별도 결정이 필요하다. |
| AI 그림은 모두 부드럽게 축소되어 있다 | 일반화하면 틀리다. `goryeo_art.py:sprite`는 woodland 계열에 `ImageOps.contain(...NEAREST)`와 18색 양자화를 쓴다. 건축·소품 등 다른 분기는 LANCZOS와 12/28색을 쓴다. 최근접 사용만으로 공통 팔레트·스타일 승인을 입증하지는 않는다. |
| A2로 에셋이 기준을 충족했는지 판정 가능 | 기술 규격과 명시적 배치 규칙만 검사 가능하다. 귀여움·실루엣의 가독성·시점·빛·스타일 조화는 화면 검토가 필요하다. 고정 팔레트도 D3 확정 전에는 후보 기준 검사다. |
| 좌표로 잘라 쓰는 코드는 모두 같은 위반 | 구분이 필요하다. `Direction.md` 2절은 온전한 개체의 엔진 타일 분할 렌더링을 허용한다. 일부만 재사용하거나 목적을 바꾸는 것과 다르다. `ArtGuide.md` 3절의 좌표 절단 금지 문구는 이 상위 원칙에 맞춰 해석하며, 새 목록은 개체/조립 조각 ID를 중심으로 만든다. |
| R1의 시작값이 확정됐다 | 정확히는 시작 **단계**만 확정됐다. 우호/중립의 수치, 단계별 경계는 별도다. R1 구조·저장은 시작 가능하지만 숫자를 임의 확정할 수 없다. |
| R6 전체가 설계안 전까지 불가능하다 | 너무 넓게 막은 설명이었다. 계약/단순 선행 원칙은 확정되어 있어 사용처 조사와 구조 작업은 가능하다. 불명확한 퀘스트 분류·평판량·옛 진행 보상 처리만 검토가 필요하다. |
| 구현이 가능하다 | 정적 구조 검토상 가능한 범위라는 뜻이다. 새 기능 구현·Unity 컴파일·실제 플레이로 완료 가능성을 입증한 것은 아니다. 자동 격자 추정은 임의 이미지에 항상 성공한다고 보장할 수 없다. |

## 코드에서 확인한 구현 조건

- `Tools/MapGen/tiles.py`: `Map.stamp`는 `self.stamps`에 배치를 기록하지만 `to_json`은 이 목록을 내보내지 않는다. A2가 최종 배치의 완전성을 검사하려면 배치 근거와 실제 타일 결과를 연결해야 한다. 구체적인 저장 형식은 아직 구현하지 않았다.
- `Scripts/Core/PlayerState.cs`, `SaveSystem.cs`: 지역별 평판 저장이 없다. `OriginData.homeRegion`과 `TownData.region`은 있으므로 지역 식별의 출발점으로 쓸 수 있다.
- `SaveData`에는 캐릭터 출신을 저장하는 필드가 없고 `GameManager`가 `Db.startOrigin`으로 시작한다. 새 평판 저장뿐 아니라 옛 저장의 출신 판별·초기화 정책도 필요하다. 기존 신용으로 과거 평판을 임의 추정하지 않는다.
- `Scripts/Quests/QuestManager.cs`: 수락한 퀘스트의 `acceptedRewardCredit`을 저장·복원한다. 데이터의 새 보상만 바꿔도 옛 진행에는 그대로 남는다. 이미 쌓인 신용 보존과 앞으로 받을 옛 보상 처리는 다른 문제다.
- `Plan.md` B2는 A4를 선행 조건에 적지 않았으나 A4 분담표는 에셋을 B2로 넘긴다. 생성 로직 개발은 진행할 수 있지만 승인 에셋의 이음매·게임 화면 검증은 에셋 인도 후에 가능하다.

## 이번 문서 수정

`Plan.md`에 A3 상위 작업을 유지하며 A3a·A3b 상세 행과 A5 상세 행을 추가했다. D10의 R1 차단 표기를 바로잡고, R1·R6·A2의 구현 한계와 확인 조건을 명시했다. 기존 담당과 우선순위를 변경하지 않았다. 앞서 제안한 A5 우선 진행 순서는 확정된 순서가 아니므로 적용하지 않았다.

`Direction.md`, `ArtGuide.md`, `Standing.md`와 코드·맵·에셋은 수정하지 않았다. Figma와 실제 게임 화면은 이번에 직접 확인하지 않았으므로 개별 에셋의 미적 적합성·교체 목록을 확정하지 않았다.

## 검사 근거와 한계

이 대화의 직전 검토에서 실행한 결과이며, 이번 문서 수정 후 재실행한 결과는 아니다.

- `python3 Tools/Integration/validate_world.py`: 오류 0, 등록 출구 92개 확인. 실제 이동 검사 92회라는 뜻이 아니다.
- 시스템 Python에서 통합 검사는 Pillow 누락으로 4개 오류가 났다. `/tmp/pocket-caravan-codex-review-20261024`의 별도 가상 환경에 Pillow 12.3.0을 설치한 뒤 `python -m unittest discover -s Tools/Integration -p 'test_*.py'`를 실행해 45개 통과했다. 프로젝트 의존 파일은 변경하지 않았다.
- 이 결과는 기존 로컬 구현의 검사다. 신규 A2/R1/A5 기능, 온라인 동시 거래, 사용자 미술 기준, Unity 실행을 검증하지 않는다.

## Claude 크로스체크 항목

1. A3b의 유지 판정과 C6의 옛 출처 0개 목표를 임시/최종 유지로 구분한 해석이 맞는지.
2. A1 승인에 D2뿐 아니라 D3도 필요하다는 관계, A5 시험 샘플과 A1 승인 샘플을 구분할지.
3. R1의 수치 미확정 상태에서 데이터 구조·저장을 만드는 범위와 옛 저장의 출신 판별 정책.
4. R6의 퀘스트별 보상 분류, 기존 수락 보상의 보존/전환 정책, 평판량을 정할 시점.
5. A2의 개체 완전성·용도 검사 범위와 A5의 수동 격자 지정 보완이 타당한지.
6. B2 개발 착수와 A4를 사용한 화면 검증 완료 조건을 분리하는 방식.

이 목록은 검토 요청 사항이다. Claude의 확인을 이미 받았다는 뜻이 아니다.

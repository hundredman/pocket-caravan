# C1 4방향·걷기 검사

`codex/c1-expand`에서 C1 연속 작업. 사용자 “좋아. 이대로 가자.”는 앞 단계의 7명 정면 승인으로 기록했다. 승인 정면은 PNG/Aseprite·해시를 `ArtReview/Approved/`에 동결했다.

## 정적·PNG·Aseprite 검사

- 생성 원본: `Tools/ArtTrials/npc_animate_c1.py`, `npc_animate_c1.lua`. 기존 나머지7명 생성기에 `layout` 반환 옵션만 추가했으며 기존 기본 정면 출력은 동일한지 다시 대조했다.
- 10명×4방향×4프레임=160개. 크기16×24, 알파0/255, 실제 불투명 최하단24, 인물별 승인 정면 색의 부분집합 확인. 방향별 주기에서 최소3개 구분 프레임 확인.
- 아래0/2 프레임이 승인 정면과 픽셀 일치함을 확인. 승인된 원본 파일은 변경하지 않았다.
- Aseprite10개를 저장 후 재열어 출력한64×96 시트가 생성160프레임과 픽셀 일치. 각각16프레임, dulr 태그와 태그 범위/125ms 시간 확인.
- `python Tools/Integration/validate_assets.py ArtReview/C1-Walk/catalogue.json --preview --report ArtReview/C1-Walk/manifest-report.json`: 오류0. 실제 맵 배치 검사나 사용자 미술 승인을 대신하지 않는다.
- 비교 그림2장을 열어 방향별 얼굴/모자/소품 형태 확인. 실제 Game 캡처의 정면/뒤/옆도 열어 확인.
- `git diff --check`: 통과.

## 실제 Unity 에디터 검사

실행 중 main 프로젝트의 장단 씬 Play에서 새 PNG를 메모리 Texture/Sprite로 읽었다. 기본 `CharacterAnimator`10개에 각각16프레임을 넣었다. 씬/에셋/코드 저장은 하지 않았다.

- PPU16·pivot(8,6)·scale1 유지. 임시 비교 열은 x30.5부터1.75칸 간격, y24.5이며 플레이어는 x28.5다.
- 일시정지 상태에서 실제 `CharacterAnimator.LateUpdate`의 시간/방향을 제어해160개 선택 프레임이 지정 Sprite와 일치하는지 확인했다.
- 반복 경계4→0 및 멈춤→0을 각각10명×4방향에서 확인: 추가80건 일치. 합계240건이다. `ArtReview/C1-Walk/unity-checks.json`.
- 각 선택 시 실제 Game 화면1920×1080을 `ScreenCapture.CaptureScreenshot`으로16장 촬영했다. `unity-walk.gif`는 이16장을 크기/배치 수정 없이 GIF로 인코딩했다.
- 마지막에 실제 애니메이션 컴포넌트를 enabled=true, walking=true, 아래 방향으로 두고 일시정지했다. Play를 진행하면 제자리 걷기를 재생한다.
- autosave=false, sceneDirty=false, Console error 조회0개. main 추적 파일 변경0개(기존 미추적 3D 실험 보존).

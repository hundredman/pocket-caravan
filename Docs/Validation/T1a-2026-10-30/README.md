# T1a 화면 끝 전환 — 2026-10-30

사용자는 '현재 구역선'이 아니라 **눈에 보이는 맵·화면 끝에서 전환**을 선택했다. 이번 작업은 `codex/transition-boundary`의 로컬 검토다. 원격 병합/푸시는 하지 않았다.

## 변경

기존에는 마지막 출구 칸에 발이 조금만 들어서도, 심지어 정지 중 출구 방향을 보고 있어도 전환했다. 또 씬은 불규칙한 구역을 감싸는 직사각형으로 만들어 이웃 지형도 보여 주므로, 논리 경계가 화면 중간에 보이는 경우가 있었다.

- 담당13맵 사이 출구에서는 바깥쪽 이동 입력이 있고 발밑 상자가 출구의 바깥 면에 닿을 때만 전환한다. 충돌 후 속도0이 되는 마지막 프레임도 이동 시도량으로 검사하고, 접촉점 바로 안쪽에 맞춘다.
- 카메라는 접근 중인 출구 면에서 먼저 멈춰 플레이어가 화면 끝까지 걸어가게 한다. 도착 맵에서도 같은 경계 면을 기준으로 프레임을 잡는다. 마지막 접촉 때 정확히 해당 면을 화면 끝에 맞춘다.
- 좁은 모서리에서는 프레임이 원래 씬 표시 직사각형을 벗어나므로 승인된 동일 원본에서 **시각 전용 CameraBackdrop**을 준비했다. 원래 맵 사각형 밖에만 배치하며 충돌·길·저장 좌표·가격·구역/ID를 바꾸지 않는다. 11맵에 TilemapRenderer 각1개, 합계27,764배경칸 추가. 렌더러/메모리 증가는 실기기FPS 보장을 뜻하지 않는다.
- 다른 문명 출구/카메라 정책은 기존대로 유지한다. 지역명/페이드 길이는 바꾸지 않았다.

PixelPerfectCamera가 한 프레임 안에서 예전 view matrix를 유지하므로 QA의 여러 순간이동 뒤 화면 좌표 계산 전에 `ResetWorldToCameraMatrix`를 호출했다. 게임 화면은 실제 PixelPerfect 렌더를 사용한다. 초기 진단 실패를 숨기거나 그 결과를 통과로 기록하지 않았다.

E1 거리 검사의 PlayerMotor 소스 지문이 달라져 보고서를 재생성했다. 지문 외 계산값·가격·시간/거리 결과는 모두 동일하다. 다른 문명 씬·데이터·코드는 수정하지 않았다.

## 그림·재현

`ArtReview/TransitionBoundary-20261030/Review/walking-before-after.gif`: 왼쪽은 기존 칸 진입 판정+원래 직사각형 카메라를 같은 씬에서 재현했고, 오른쪽은 수정한 실제 경계 입력/이동/전환이다. 원본 게임 화면에서 GIF를 조립했으며 에셋을 다시 그리지 않았다. 4방향 전후 PNG/비교판도 보관한다. QA는 `BoundaryTransitionReview.Run()`으로 시작한다. 처음만 previewOnly 씬에서 시작해 원래 저장을 끄고 이후 본편 씬을 사용한다. 사람의 직접 키보드 플레이/장시간 플레이/실기기FPS/모든 화면비는 미검사다. 현재480×270/16:9 실제 캡처 기준이다.

지형 생성은 `nature_live.json`을 이용한 기존 M1 층에서 `m4_export.py --production`으로 다시 내보내고 담당13씬만 BuildSelected한다. 배경 원본은 `camera_backdrop.py`의 시각 문맥 범위(48×32칸 예산)에서 가져온다. 생성물을 손으로 수정하지 않는다.

사용자 화면 승인 및 추가 통합 지시가 있으면 팀 카톡 사전 공지 전달 확인 뒤에 원격에 반영한다. 이전 A7d 완료 공지를 이번 수정의 사전 공지로 간주하지 않는다.

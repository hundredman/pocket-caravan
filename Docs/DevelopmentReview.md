> **2026-10-17 후속 결정:** [출신 역할](OriginDesign.md)과 [최신 변경 요약](DesignUpdate_2026-10-17.md)을 우선한다. 주행 낙하는 제외하고 감속 중심으로 변경하며 정보·적재·판매·이동 역할을 사용한다. 아래 기존 낙하/회수 검사·관찰은 이전 코드의 기록이며 유지할 신규 기능의 요구가 아니다. 실제 코드 제거/저장 이주는 아직 완료되지 않았다.

최종 정리: 2026-10-15. 범위: 저장소 개발 안내·초기 기획과 대화 기록, 이동·운반·시장·시계·저장·맵·NPC의 핵심 코드. 이번 업데이트는 문서 작업이며 네트워크 기능을 새로 구현한 결과가 아니다.

## 1. 최신 문서와 승인 상태

기존 문서는 구현 목록·지난 제안·최신 요구가 함께 있어, 팀이 바로 작업 범위를 정하거나 멀티 완료를 판정하기 어려웠다. 최신 기준을 다음 문서로 나눴다.

- [개발 기준안](GameDesign.md): 2D 품질·지역 표현·여정·이동·교역·UI.
- [멀티플레이 설계안](MultiplayerPlan.md): 공유 상태·서버 권한·거래·지역 전환·저장·혼잡.
- [개발·검증 계획](DeliveryPlan.md): 선행 단계·4주 목표·수용 검사·책임 영역·결정 목록.

사용자 확인: **기본 시스템 선행 → 4주 안에 최종 2~4명 실제 멀티플레이, 가능하면 추가 인원**. 초기 PDF의 ‘고려만 시연’ 범위를 최신 목표로 사용하지 않는다.
2D 우선으로 계획을 구체화하되 팀의 아트·지역 분량 최종 승인과 기술 선택은 별도다. 현재 구현이 온라인 MMORPG로 전환됐다는 의미는 아니다.

## 3. 최신 이동 관찰

사용자 관찰: 풀밭의 짐 낙하가 매우 잦았고, 사람들을 길로 유도하는 용도로는 쓸 만해 보였다.

해석: 도로 선호를 만들 수 있다는 긍정적 단서다. 동시에 짧은 이탈까지 지나치게 억제하거나 반복 줍기를 유발하는지는 별도로 봐야 한다. 현행은 누적 흔들림 임계치와 달리기 무작위 충격의 조합이며, 고정된 ‘풀밭 낙하 확률’로 표기하면 부정확하다.

MMO 영향: 도로 선호가 강할수록 유저·수레가 다리/장터/문에 모인다. 통과 정책·가독성·서버 화물 소유권과 함께 설계해야 한다. 신규 주행 낙하물은 제외한다. 2D 그래픽을 유지하는 것만으로 이 문제를 해결했다고 보지 않는다.

## 4. 이전 계획과 구분할 사항

- 초기 PDF의 발길 개척/성장은 현행 사전 지정 도로 등급과 다르며 이번 유지보수에는 구현하지 않았다. 10월16일 회의의 길 개척 제외 방향과 D-13을 따른다. 과거 미결정 기록을 새 필수 요구로 복구하지 않는다.
- 초기 개경 시작과 현재 Naru 시작은 다르다. 고려 수도·주변 마을 담당과 게임의 실제 시작 위치는 별도 결정이다.
- 고려 내부 네 맵은 네 문명의 스타팅 지역 네 곳이 아니다.
- 다른 문명은 여러 중간 구역을 거쳐 도착한다. 이전 3D 실험의 고려-서역 근접 배치는 최신 여정 모델이 아니다.
- 카툰 3D 배경에 기존 픽셀 동물만 바꿔 넣은 실험은 전체 픽셀/2.5D 스타일 비교가 아니다. 현재 제작 계획은 2D 우선으로 정리했다.
- 싱글의 메뉴 일시정지·클라이언트 저장·씬 이동을 온라인에서 그대로 재사용할 수 있는 구조로 소개하지 않는다.

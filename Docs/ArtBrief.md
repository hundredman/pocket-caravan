# 고려 아트 개선 요청서 (Codex 제작용)

2026-10-24, Claude 작성. 원칙은 [방향 기준](Direction.md) 1~2절, 기준은 [현재 게임 아트 기준표](Images/current-art-reference.png)와 [아트 기준](ArtGuide.md).
**지금 게임을 개선한다. 완전히 바꾸지 않는다.** 플레이어 너구리와 전체 분위기는 그대로 둔다.

## 공통

- 크기: 타일 16px·PPU 16. 캐릭터 16×24, 2등신. 모든 그림 같은 도트 크기.
- 원본은 `.aseprite`, 게임용은 PNG. 원본 제작은 AI 이미지 생성 + [아트 기준](ArtGuide.md) 4절 정리(A5 도구, 최근접 축소, 팔레트 고정, 반투명 제거) + Aseprite 손질. 코드로 직접 찍어도 된다.
- 원본 보정은 원래 색을 유지한다(2026-10-24 사용자 지시). 새 색이 필요한 시안은 [현재 아트 색 후보](../Tools/ArtGen/current_palette_candidates.txt)와 기존 캐릭터 팔레트를 기준으로 하며 D3 확정을 대신하지 않는다.
- **검토는 은샘이 그림으로 한다.** 제출할 때 ① 바꾸기 전/후를 같은 배율로 나란히 ② 실제 게임 화면 크기에 놓은 모습, 두 가지를 함께 낸다. 승인 전에는 본편에 넣지 않는다.

## 1. 사람 NPC (C1)

**확인된 인물 스타일 표본(2026-10-24):** [아낙 정면](../ArtReview/Approved/woman-front-v4.png). 사용자 “좋다. 이런 느낌이야.” — 왼쪽 돌출선 제거·오른쪽 눈/머리카락 분리 후의 16×24다. 이 표본의 얼굴 비율·선·색 정리감을 다른 인물에 맞춘다. 원본/확인 범위는 [기록](../ArtReview/Approved/woman-front-v4.approval.md) 참고.

2026-10-24 확대 승인: 실제 Unity 화면을 보고 사용자 “좋다. 사이즈도 좋은 것 같아. 이어서 진행하자.” 촌장·행상 정면과 사람 시안의 크기를 확인했다. [승인 기록](../ArtReview/Approved/chief-trader-front-c1-expand-1.approval.md)의 표본을 보존하고 나머지 7명 정면 → 4방향·걷기 순서로 별도 그림 검토를 받는다.

2026-10-24 나머지 정면 승인: 사용자 “좋아. 이대로 가자.”로 농부·약재상·닥목 촌장·객주·아이·뱃사공·도적 정면을 확인했다. [7명 승인 기록](../ArtReview/Approved/seven-fronts-c1-expand-2.approval.md)에 동결한다. 이후 10명 전체의 4방향·걷기는 별도로 제출하고 검토받는다.

2026-10-24 후속 피드백: 사람 v3는 좋아졌고 선·색상 정리가 필요하다. 이번 보완은 기존 얼굴·비율을 유지하고 윤곽선과 비슷한 중간색을 정리하는 단계다.

2026-10-24 추가 피드백: 동물 캐릭터의 그림체는 유지한다. 사람으로 바꾼 얼굴이 어색하므로 인물만 다시 검토한다. 건물·나무 v2는 긍정 피드백을 받았고 이번 인물 수정에 섞어 바꾸지 않는다.

v1 시안([human-npc-v1](Images/human-npc-v1.png))은 거절됐다. 모두 같은 몸·같은 얼굴에 모자만 달라 개성이 없었다.

**참고:** Figma `아트 시안` 페이지의 고려 캐릭터 시안(지게·머리띠·두건·장부를 든 사람들), 아라비아 NPC(상인·할머니 등). 둘 다 **머리 모양·모자·수염·소품·옷 색 덩어리**로 인물이 바로 구분된다. 다만 시안은 훨씬 큰 그림이라, 16×24에서는 세부가 사라진다. 그래서 개성은 아래로 낸다.

- **실루엣:** 그림자(검은 덩어리)만 봐도 누가 누군지 구분되어야 한다. 제출 그림에 실루엣 비교 줄을 넣는다.
- **몸 차이:** 모든 NPC가 같은 몸 틀을 쓰지 않는다. 마른·통통한·작은(아이) 몸을 둔다.
- **머리·모자와 소품을 크게:** 2~4px짜리 장식은 보이지 않는다. 소품은 몸 밖으로 튀어나오게.
2026-10-24 방향·걷기 승인: 사용자 “훨씬 낫다. 이대로 하면 좋을 것 같아.”로 옆머리 보완 후 10명 전체의4방향·걷기를 확인했다. [160프레임/원본 승인 기록](../ArtReview/Approved/C1-Walk/approval.md)으로 동결했다. 본편 연결 전 기존 주민 직업과 시안 역할의 대응은 [검토 요청](Validation/C1-Production-Binding-Review-2026-10-24.md)을 확인한다.

- **측면 머리카락(2026-10-24 사용자 수정 지시):** 두피가 넓게 비어 보이지 않게 관자놀이·뒤통수를 연결한다. 작은 귀와 눈 위 피부 틈은 남기고 승인된 정면은 유지한다.
- **얼굴:** 플레이어와 같은 큰 눈·볼 표현. 수염·주름·주근깨처럼 1~2px로 보이는 특징 하나씩.

## 2. 건물·나무는 현재 아트 유지 (C2·C3)

2026-10-25 사용자 결정: 궁궐·초가집·버드나무·숲의 약한 보정은 원본과 비슷해 필요하지 않다. `ArtReview/Environment-Expand-v2/`10개 시안은 채택하지 않고 기존 본편 그림을 유지한다. 시안은 검토 이력으로만 보존한다. 일괄 색상 정리나 실사감 완화를 추가 제작 조건으로 두지 않는다.

원본 등록·온전한 개체 사용·조립 규칙 준수 여부는 A3a/A3b에서 계속 확인한다. 실제 교체가 필요하다고 판정된 대상은 기존 형태·색·명암을 유지하며 따로 그림 검토를 받는다.

사용자가 지적한 ‘캐릭터가 나무 위에 있는 것처럼 보임’은 [점검 기록](Validation/Environment-Decision-2026-10-25.md)에 남겼다. 해당 비교 화면은 검토자가 캐릭터를 나무 안의 진입 불가 칸에 직접 놓은 오류였다. 정상 플레이에서의 재현과 분리하고, C3a에서 정상 발밑 위치·앞뒤 가림을 점검해 필요시 수정한다.

## 3. 잘라 붙여 깨진 곳 (A4)

개경 연못 둘레의 네모난 풀밭 조각처럼 잘라 붙인 곳은 조립용 물·연못 세트(가운데·가장자리·바깥/안쪽 모서리)로 다시 만든다. A2b 검사기를 통과해야 한다.

2026-10-25 사용자 승인: **“작은 연못 좋은 것 같아. 승인할게.”** 오른쪽 작은 연못 경계를 본편에 적용한다. `ArtReview/Approved/A4-Pond/`의 원본47조각을 보관하고, 승인 범위는 개경22칸/11조합과 기존 돌마당/연꽃으로 동결했다. 큰 호수는 기존 표현을 유지하며 새 물결 애니메이션은 이번 승인/적용 범위가 아니다.


## 4. 고려 환경을 팀 그림체로 다시 그리기 (C7, 2026-10-26)

**목표:** [팀 스타일 기준표](Images/team-style-reference.png)와 Figma 원본([베네치아 에셋](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=77-5) · [아라비아 에셋](https://www.figma.com/design/JeXCjYTYRGtV8FCnXWWiqe/?node-id=92-2) (같은 `아트 시안` 페이지, 각 제목 아래로 이미지가 이어진다))의 베네치아·아라비아 에셋과 나란히 놓았을 때 같은 게임으로 보이게.

| 맞출 것 | 기준 |
|---|---|
| 외곽선 | 진한 단색(거의 검정에 가까운 갈색) 1px, 바깥 윤곽 전체 |
| 명암 | 면마다 2~3단계, 평평하게. 빛은 왼쪽 위 |
| 색 | 밝고 깨끗하게. 기와는 진남색 대신 밝은 청회색~남색 2~3단, 나무 잎은 2~3단 초록 |
| 결·장식 | 잔 결·노이즈·점묘 없음. 기와 줄·창살 등은 몇 줄만 굵게 |
| 크기·위치 | 지금 개체와 같은 크기·발밑(맵 배치를 바꾸지 않음). 16px 격자, 모든 그림 같은 도트 크기 |
| 반투명 | 일반 개체는 알파 0/255. 그림자·물결은 `effect` 종류 |

2026-10-27 사용자 수정 요청: 첫 시험의 나무는 유지하고 초가집·기와집·풀/흙은 **팀 에셋처럼 형태부터 다시 제작**한다. 수정안도 팀 에셋 나란히 비교·실제 Unity 화면 승인을 받는다. 후속 사용자 정정: “특징”은 베네치아·아라비아 팀 아트의 표현 방식이다. Figma 실제 이미지(베네치아77:9·78:11, 아라비아92:31·92:32·92:102·92:107)의 큰 색면·명암·외곽선·짧은 무늬를 확인해 맞춘다. 후속 선택으로 초가집·기와집은 승인, 지형은 원래 그림 유지다. 풀/흙 새 시안은 미채택이며 개경 포장용 연못을 풀밭에 배치할 때에는 별도 맥락·물가 그림 검토를 받는다.

**대상과 순서**
1. 시험 4개: 초가집 1, 기와집 1, 나무 1(소나무), 바닥 타일 1세트(풀·흙). 팀 에셋과 한 장에 나란히 + 실제 게임 화면 캡처로 은샘 승인.
2. 승인되면: 궁궐·기와집·초가집 나머지, 버드나무·벚나무·숲, 수레·우물·소품, 바닥·길·물·해안 조립 타일(A4 세트 포함).
3. 새 맵(B3~B5)에는 승인된 C7 그림을 쓴다. 맵 작업(지형·배치)은 계속 진행하고, 그림은 A2 목록 교체로 바꿔 끼운다.

**만드는 방법:** AI 이미지 생성(팀 에셋을 참고 이미지로. Figma에 접근할 수 없으면 기준표 PNG를 참고 이미지로 쓴다) → A5 정리 도구 → Aseprite 손질. 팀 에셋을 잘라 쓰거나 그대로 가져오지 않는다(고려 그림을 새로 그린다).

**승인된 에셋 다시 보기 (C7과 함께)**
- 시험 4개를 만들 때 플레이어 너구리·사람 NPC·작은 연못도 같은 화면에 놓고, 목표 그림체 옆에서 어색한 곳(외곽선 굵기·색, 명암 단계, 채도 등)이 있으면 함께 지적한다.
- 고칠 필요가 있으면 **수정안을 따로** 만든다: 지금 승인본 / 수정안 / 팀 에셋을 같은 배율로 나란히, 그리고 게임 화면 캡처. 은샘이 승인하면 그때 승인 기록(해시)을 새 그림으로 바꾸고 본편에 넣는다. 승인 전에는 기존 승인본을 건드리지 않는다.
- 어색한 곳이 없으면 "수정 불필요"라고 이유와 함께 적는다.

# C1 — 10명 4방향·걷기 검토

승인된 10명 정면에서 확장했다. `d0`와 `d2`는 정면 승인본과 픽셀까지 동일하다. 방향별4프레임, 프레임16×24, 순서 `dulr`, 8fps다.

- `directions-1.png`, `directions-2.png`: 승인 정면 / 아래 / 위 / 왼쪽 / 오른쪽 비교. 확대4배와 실제 크기다.
- `walk.gif`: 10명×4방향 네이티브 프레임의 걷기 확대 보기.
- `unity-walk.gif`: 실제 Unity 장단 Game 화면16장을 순서대로 인코딩했다. 아래→위→왼쪽→오른쪽으로 각각4프레임, 125ms. 합성이 아니다. 검토를 위해 제자리 걷기를 표시했다.
- Unity 화면 왼쪽부터 플레이어 / 나루 촌장 / 아낙 / 행상 / 농부 / 약재상 / 닥목 촌장 / 객주 / 아이 / 뱃사공 / 도적.
- `frames/<이름>_<방향><프레임>.png`: 실제16×24 완성 프레임160개. 인물별 `.aseprite`는 네이티브16프레임 애니메이션이며 `d/u/l/r` 태그가 있다. `*-sheet.png`는 보기/검사용, 본편에서 시트를 좌표로 잘라 쓰도록 등록한 것이 아니다.
- `catalogue.json`: 전체160프레임을 개별 완성 에셋으로 등록했다. 4방향/걷기 사용자 승인 대기. 팔레트는 인물별 승인 정면에 실제 존재하는 색만 사용했고, D3 전체 팀 팔레트를 확정하지 않았다.

걷기는 기존 주기에 맞춰 0/2 중립, 1/3 발 디딤과 최대1픽셀 몸 움직임으로 만들었다. 아이의 다리는 작은 폭을 유지한다. 옆은 하나의 눈과 옆얼굴을 따로 그리고 뒤는 얼굴 대신 머리 뒤를 그렸다. 왼쪽은 형태를 뒤집은 후 명암을 다시 적용한다. 모자·옷·짐/두루마리/노 등 소품을 방향별로 유지했다.

## 재현

`PYTHONDONTWRITEBYTECODE=1 python Tools/ArtTrials/npc_animate_c1.py`

Pillow와 Aseprite 명령줄이 필요하다. `npc_animate_c1.lua`가 태그/프레임 시간을 가진 원본을 만들고, Aseprite 재출력 시트를 생성 PNG 전체와 비교한다. 실제 Unity 캡처를 GIF로 묶는 명령은 `python Tools/ArtTrials/review_c1_unity_walk.py`다.

## 검사와 남은 것

160프레임 크기/알파/팔레트/발밑·10개 정면 동일·Aseprite10개 재열기16프레임/태그/픽셀 확인, A2 미리보기 오류0. Unity 실제 `CharacterAnimator`로 방향별 프레임160건·루프/정지80건 일치, Console error0. 자세한 기록은 `Docs/Validation/C1-Walk-2026-10-24.md`.

임시 인물은 실행 중인 씬 메모리에만 두었다. PNG/씬/코드/ID/저장을 바꾸지 않았다. Play는 일시정지 상태이며 다시 진행하면 아래 방향 제자리 걷기를 볼 수 있다. Play 종료 시 원래 씬으로 돌아간다.

이번 방향·걷기 미술 승인과 실제 이동/충돌/상호작용 검사는 별도다. 본편 교체 전에는 이미 기록한 주민 직업과 새 시안 역할 배정의 Claude 검토도 필요하다. 아트 단계가 끝났다고 C1 전체를 완료 처리하지 않는다.

후속 옆머리 수정: 사용자 지시로 관자놀이·뒤통수 머리카락 면을 보완했다. 이 폴더의 좌우 프레임/원본/검토 GIF는 수정 후 버전이다. 앞뒤는 동일하다. `../C1-SideHair/comparison.png`에 전후를 제출했다. 현재 Unity 일시정지는 오른쪽 방향이다.

후속 승인: 사용자 “훨씬 낫다. 이대로 하면 좋을 것 같아.”에 따라 옆머리 보완 후 현재160프레임/원본을 `ArtReview/Approved/C1-Walk/`에 동결했고 목록은 approved로 변경했다. 본문 제출 당시의 미술 승인 대기는 해소됐다. 본편 역할 배정 검토/영구 교체·이동 검사는 별도다.

# 처음 지형의 길 경계 재확인

2026-10-27 사용자 지적: 현재 땅의 무늬 문제가 아니라 처음 버전의 길 외곽 처리 등이 사라져 어색하다. GitHub의 다른 팀 작업도 참고할 수 있다.

## 바뀐 원인

첫 C7 검토 도구 `C7TrialReview.Build`는 시험장 바닥의 기존안에도 `floor_0_12_goryeo_jade`(풀 가운데)와 `floor_1_8_goryeo_jade`(흙 가운데)만 깔았다. 원래 `tiles.Map.finish`가 `autotile`로 골라 주던 변/바깥·안쪽 모서리 타일을 거치지 않아 비교 기준부터 길 경계가 빠졌다. 새 C7 조립 세트도 두 재질을 나누는 마스크만 그렸고, 기존의 풀 가장자리·접촉 명암을 충분히 재현하지 못했다. 이는 C7 검토 구현의 누락이다.

바깥 경계 표현을 없애라는 사용자 지시는 없었다. 본편 원본/지형은 그대로 남아 있으며 실제 본편을 새 C7 땅으로 교체하지 않았다. 앞선 `GroundCompare-v6`의 “이전”은 **직전 C7 중간안**이고 처음 본편 지형이 아니었다.

## 이번 확인 화면

[원래 지형 / C7 시험 지형](comparison.png). 승인된 두 건물·나무·인물·연못·길/카메라는 같다. 원래 지형은 `tiles.py`의 `GRASS`·`DIRT_ORIGIN`·`autotile` 선택을 그대로 사용하며, 기존 동결 타일14개를510칸에 배치했다. 그 결과 처음의 풀 가장자리·명암·모서리 표현을 확인할 수 있다. 실제 Unity previewOnly Play480×270로 새로 촬영했다.

건물2개와 나무의 불투명 픽셀은 양쪽 차이0이며 [픽셀 증거](checks.json)에 남겼다. `original-ground.json`은 이 시험장만의 배치 기록이다. 실제 B3 마을 배치·보행 검사나 본편 적용이 아니다. 땅의 최종 그림 선택은 미확정이다.

## GitHub 팀 브랜치 확인

최신 원격 브랜치를 fetch해 읽었으며 팀 브랜치는 수정하거나 합치지 않았다. GitHub 연결 도구의 파일 읽기는404였고, 저장소의 Git 원격 읽기는 성공했다. [출처/커밋 기록](Reference/sources.json).

| 브랜치 | 확인 커밋 | 코드에서 확인한 경계 |
|---|---|---|
| `region/venice` | `5e2c3179` | `venice_tiles.py`의 `LAND_EDGE`, `_band`, `_corner`, `_land`: 흙길/풀 가장자리 색띠와 모서리, 물가 접촉선 |
| `region/arabia` | `dc98dc6b` | `arabia_art.py`의 `compose`: 변/안쪽·바깥 모서리 거리, 포장 연석·그늘, 흙길/풀 경계 |

아라비아가 저장한 [실제 농원길 화면](Reference/arabia-farmroad.png)도 확인했다. 이는 팀원이 기존에 촬영해 브랜치에 올린 자료이며 이번에 내가 아라비아를 실행한 결과가 아니다. 베네치아는 경계 선택/색띠 코드와 저장된 타일 구성을 읽었으며 Unity 실행은 하지 않았다.

향후 땅 수정은 처음의 경계 기능을 유지하는 기준으로 검토하고, 팀의 실제 구현도 함께 참고한다. 다른 팀의 지역 코드나 그림을 그대로 고려에 이식하지 않으며 우리 저장소의 에셋 사용/등록 규칙을 따른다. 건물 승인은 그대로 유지한다.

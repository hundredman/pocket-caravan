# 건물·배 리뉴얼 — 전체 묶음 검토

**전체10종 시안 제작·검사 완료, 사용자 승인 대기. 본편 미교체.**

사용자 기준: 건물은 NinjaAdventure처럼 지붕 윗면과 앞면이 함께 보이게, 배는 내려다보는 각도를 낮춰 선체 옆면이 충분히 드러나게 한다. 개별 중간 승인 대신 전체 작업 후 한 번에 확인받는다.

## 전체 대상

큰 초가집80×64, 작은 초가집64×48, 기와집64×48, 곳간64×48, 정자80×80, 객주96×64, 시전96×64, 성문96×80, 궁궐160×112, 배80×32. 나무·지형·소품·NPC는 이번 리뉴얼 대상이 아니다.

- [전체 전후 비교](comparison.png): 각 항목 왼쪽 기존 / 오른쪽 시안, 동일2배·캔버스 발밑 정렬.
- [Unity 실제 크기 비교](Unity/comparison.png): 기존 캐릭터·기존 jade 풀/물과 함께 놓은480×270 카메라6장. 각 줄 왼쪽 기존 / 오른쪽 시안.
- [검사](validation.json), [원본/대체 후보 목록](manifest.json).

## 제작·보존

- 내장 imagegen으로 개체별 원화10개를 별도로 생성했다. AI/*.png, [프롬프트10개](prompts.json). 참고 이미지는 개체의 기존 C7 원본, NinjaAdventure 건물의 시점, 팀 베네치아/아라비아 스타일 기준표다.
- Source/prepare-native.lua에서 투명 여백만 제외해 개체 전체를 균일 비율로 실제 캔버스에 맞추고 NEAREST 샘플링, 기존 C7 계열의 시험용30색/알파0·255로 정리했다. 생성 원화를 코드 도형으로 대체하거나 벽체를 늘리지 않았다. 배의 원화에 붙은 푸른 물결은 개체에 포함하지 않았다.
- Native/*.aseprite가 편집 원본, Native/*.png가 게임용 시안이다. 원본은 보존하고 새 폴더에만 작성했다. 팔레트는 이번 시안용이며 팀 공통 팔레트 결정이 아니다.
- 배의 비교 기준은 기존 C7 배 시안이며 본편 선박 등록/작동 여부를 증명하는 비교는 아니다. 기존 이름과 역할의 대체 후보로만 기록했다.
- Unity 검토는 **Edit 모드의 별도 메모리 갤러리**다. 캐릭터 PNG도 정지 배치다. 기존 본편 씬을 수정/저장하지 않았고 촬영 뒤 갤러리를 닫고 원래 씬으로 돌아갔다. Source/unity-review.cs.txt는 재현용 MCP execute_code 메서드 본문이다.

## 실행한 검사와 한계

10종 기존 캔버스 크기 일치/불투명 그림 존재/알파0·255/30색 이하, Aseprite 재출력10개 디코딩 RGBA 일치. Unity6캡처480×270, 본편 씬 dirty 상태 변화0/본편 에셋 쓰기0·콘솔 오류0.

시점·형태·그림체는 사용자 그림 확인 대상이며 자동 승인하지 않는다. A2 본편 목록 교체, 본편13맵 재배치/가림·충돌, 실제 플레이, 애니메이션, 빌드는 하지 않았다. 승인 후 별도로 연결한다.
